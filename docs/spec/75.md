# 廃案・否決の法案からの出し直し（設計書）

Issue #75。列を足すマイグレーションがあるので Careful。決定は Issue #63 の決めたこと9「廃案・否決の法案から『出し直す』で中身を複製した新しい下書きを作り、賛同は集め直す。元の法案へのリンクを残す」。仕様は [docs/spec.md](../spec.md)「否決された法案や、定足数に届かず廃案になった法案は課題に戻り、再提出できます」。画面の案はない（`SpBillSummary`・`PcBillSummary`・`SpResult` にそろえる）。

次のことは仕様書に定めがないので、この Issue の受入基準で確かめる（STOP 1 で確認する）。

- A. **出し直せる法案**：段階（`billStage`）が否決か廃案の法案。廃案には、定足数に届かない、無効（docs/spec/73.md）、要調整の期限切れ（docs/spec/72.md）を含む。**対象の法令が IF世界で廃止された法案と、対象の法令の廃止で廃案になった法案は出し直せない**（発議できない下書きになるので）
- B. **出し直せる人**：提出者だけ
- C. **複製するもの**：元の法案の読む版（`bills.rev`。修正案を取り込んだあとの中身）の題名・困っている人・副作用・要約・附則・対象の法令・変更点・元になった解決策。賛同、質疑、修正案、票、立場は複製しない。元の法案は変えない
- D. **基にした版は元のまま**：複製した下書きの基にした版は元の法案のものにする。そのあと IF世界か現実の条文が変わっていれば、今までの仕組み（docs/spec/72.md の B2、docs/spec/95.md）で、書く画面にいまの条文が出て、確かめるまで保存も発議もできない。本人が見ないまま新しい条文を打ち消さない
- E. **Turnstile は求めない**：発議と同じく、本人の法案の1つのボタンで、下書きを作る上限（24時間に3件、1回線20件）がかかるので。登録から7日、国、締め出しは確かめる
- F. **同じ法案からの出し直しの下書きが残っていれば、新しく作らずそこへ移る**（二度押しと下書きの増えすぎを防ぐ）。その下書きを発議したあとは、また出し直せる
- G. **リンクは新しい法案から元の法案へ**：新しい法案のページに「元の法案：<題名>」を出す。元の法案から新しい法案へのリンクは出さない（決定のとおり。使われ方を見て足す）

## 目的

否決・廃案になった法案を、提出者が手直しして次の会期に出せるようにする。

## 表

`drizzle/0019_*.sql`。`bills` に `resubmitted_from`（integer、`bills.id` への外部キー、NULL は出し直しでない）を足すだけ（ADD COLUMN）。既存の行は NULL。

## 決めたこと

1. **ルール**（`canResubmit(stage, lawGone)`。`src/lib/domain/bills.ts`）：`stage` が `rejected` か `lapsed`、かつ `lawGone` でない。`lawGone` は、対象の法令のどれかが IF世界で廃止されている（`repealedLawIds`）。#72 の「法令の廃止で要調整にならず廃案」もこれに当たる

2. **段階を求める**（`billStageNow(db, bill, now, minutes)`。`src/lib/server/results.ts`）：法案のページの読み込みと同じ手順（`billProgress` → `resultOnRead` → `adjustmentOf` → `billStage`）を1つの関数にして、ページと受け付けの両方から使う。受け付けでも読むときの処理で結果を確定する

3. **複製**（`resubmitBill(db, actor, bill, now)`。`src/lib/server/bills.ts`）：`draftInputOf(bill)` をそのまま `createDraft` に渡し、`resubmitted_from` を入れる。同じ提出者で `resubmitted_from` がこの法案で `status = 'draft'` の行があれば、その番号を返す（作らず、数えず）。上限は `createDraftLimited` と同じ（`checkBillDraft`、`actions` の `bill_draft`、超えたら違反に数える）

4. **受け付け**（`?/resubmit`。`src/routes/houan/[id]/(page)/+page.server.ts`）：順は番号と存在（404）→ ログイン → 国 → 締め出し → 登録から7日（`billGuard`）→ 提出者（403）→ 状態（`canResubmit`。409）→ 上限（429）→ 作って `/houan/<新しい番号>` へ 303

5. **画面**：
   - 法案のページの概要のタブ：提出者で出し直せるときだけ「出し直す」のボタンと「中身を複製した新しい下書きを作ります。賛同は集め直します。」。同じ法案の下書きが残っていれば「出し直しの下書きを開く」のリンクに変える
   - 結果のページ：提出者で否決か廃案なら「法案のページで出し直す」のリンク（`SpResult` の行の形）。ほかの人には出さない
   - 新しい法案のページ：題名の下に「元の法案：<題名>」（`/houan/<元の番号>` へ）。発議のあとも残る

6. **文言**：`ja.bill.resubmit`
