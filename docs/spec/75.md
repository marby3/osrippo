# 廃案・否決の法案からの出し直し（設計書）

Issue #75。列を足すマイグレーションがあるので Careful。決定は Issue #63 の決めたこと9「廃案・否決の法案から『出し直す』で中身を複製した新しい下書きを作り、賛同は集め直す。元の法案へのリンクを残す」。仕様は [docs/spec.md](../spec.md)「否決された法案や、定足数に届かず廃案になった法案は課題に戻り、再提出できます」。画面の案はない（`SpBillSummary`・`PcBillSummary`・`SpResult` にそろえる）。

次のことは仕様書に定めがないので、この Issue の受入基準で確かめる（STOP 1 で確認する）。

- A. **出し直せる法案**：段階（`billStage`）が否決か廃案の法案。廃案には、定足数に届かない、無効（docs/spec/73.md）、要調整の期限切れ（docs/spec/72.md）を含む。**対象の法令が IF世界で廃止された法案と、対象の法令の廃止で廃案になった法案は出し直せない**（発議できない下書きになるので）
- B. **出し直せる人**：提出者だけ
- C. **複製するもの**：元の法案の読む版（`bills.rev`。修正案を取り込んだあとの中身）の題名・困っている人・副作用・要約・附則・対象の法令・変更点・元になった解決策。賛同、質疑、修正案、票、立場は複製しない。元の法案と課題の状態は変えない（仕様の「課題に戻り」は、課題のページから解決策と法案をたどれる今の形のままとする）
  - **共同起草者は引き継がない**：取り込まれた修正案の本文は複製されるが、新しい法案に提案者の名前は出さない。元の法案のリンクからたどれる（元の法案のページに今までどおり出る）
  - **非表示になった解決策の引用も複製する**：今の下書きであとから非表示になったときと同じ扱い。本文は隠れ、書く画面で引用から外れることを知らせる
- D. **基にした版は元のまま**：複製した下書きの基にした版は元の法案のものにする。そのあと IF世界か現実の条文が変わっていれば、今までの仕組み（docs/spec/72.md の B2、docs/spec/95.md）で、書く画面にいまの条文が出て、確かめるまで保存も発議もできない。本人が見ないまま新しい条文を打ち消さない
- E. **Turnstile は求めない**：発議と同じく、本人の法案の1つのボタンで、下書きを作る上限（24時間に3件、1回線20件）がかかるので。登録から7日、国、締め出しは確かめる
- F. **同じ法案からの出し直しの下書きが残っていれば、新しく作らずそこへ移る**（二度押しと下書きの増えすぎを防ぐ）。その下書きを発議したあとは、また出し直せる
- G. **リンクは新しい法案から元の法案へ**：新しい法案のページに「元の法案：<題名>」を出す。元の法案から新しい法案への公開のリンクは出さない（決定のとおり。使われ方を見て足す。提出者に出す「出し直しの下書きを開く」は別）

## 目的

否決・廃案になった法案を、提出者が手直しして次の会期に出せるようにする。

## 表

`drizzle/0019_*.sql`。`bills` に `resubmitted_from`（integer、`bills.id` への外部キー、NULL は出し直しでない）を足す（ADD COLUMN）。既存の行は NULL。探すための索引（`bills_resubmitted_from`）も足す。生成した SQL が ADD と索引だけであることを読んで確かめる。

## 決めたこと

1. **ルール**（`canResubmit(stage, lawGone)`。`src/lib/domain/bills.ts`）：`stage` が `rejected` か `lapsed`、かつ `lawGone` でない。`lawGone` は、対象の法令のどれかが IF世界で廃止されている（`repealedLawIds`）。#72 の「法令の廃止で要調整にならず廃案」もこれに当たる

2. **段階を求める**（`billStageNow(db, bill, now, minutes)`。`src/lib/server/results.ts`）：法案のページの読み込みと同じ手順（`billProgress` → `resultOnRead` → 版が進んだら読み直し → `adjustmentOf` → `billStage`）を1つの関数にして、法案のページ、結果のページ、受け付けから使う。戻り値は `{ bill, progress, result, adjustment, stage }`。`bill` は読み直したあとのもので、複製にはこれを使う（受け付けが最初の読み手でも、修正案を当てたあとの中身になる）

3. **複製**（`resubmitBill(db, actor, bill, now)`。`src/lib/server/bills.ts`）：
   1. `resubmitted_from` がこの法案で `status = 'draft'` の行を探す（`savedBill` で作りかけを除く）。あればその番号を返す（作らず、数えず）
   2. 上限を確かめる（`createDraftLimited` と同じ。`checkBillDraft`、超えたら断る。違反に数えるのはアカウントの上限だけで、回線の上限は数えない。今までどおり）
   3. `draftInputOf(bill)` で `rev = 0` の行と子の行を作る（`createDraft` と同じ順）
   4. **最後の1文で確定する**：`UPDATE bills SET rev = 1, resubmitted_from = <元> WHERE id = <新> AND rev = 0 AND NOT EXISTS (同じ元で status = 'draft' の行)`。D1 は書き込みを順に処理するので、同時に押しても確定するのは1つだけ。リンクは確定のときに入れるので、作りかけの行は探す条件に当たらない
   5. 確定できなければ、作りかけの行は残したまま（読むところはすべて `savedBill` で除く。今の `saveDraft` の負けた行と同じ）、勝った下書きの番号を返す。確定したときだけ `actions` に `bill_draft` を足す

4. **受け付け**（`?/resubmit`。`src/routes/houan/[id]/(page)/+page.server.ts`）：順は番号と存在（404）→ ログイン → 国 → 締め出し → 登録から7日（`billGuard`）→ 提出者（403）→ 状態（`canResubmit`。409）→ 残っている下書きがあればそこへ 303 → 上限（429）→ 作って `/houan/<新しい番号>` へ 303。上限のときは理由をボタンのそばに出す（今の発議と同じ `use:enhance`）

5. **画面**：
   - 法案のページの概要のタブ：提出者で出し直せるときだけ「出し直す」のボタンと「中身を複製した新しい下書きを作ります。賛同は集め直します。」。同じ法案の下書きが残っていれば「出し直しの下書きを開く」のリンクに変える
   - 結果のページ：提出者で `canResubmit` のときだけ「法案のページで出し直す」のリンク（`SpResult` の行の形）。読み込みが `billStageNow` で判定して真偽値を返す（`outcome` は要調整の期限切れで可決のまま残っているので使わない）。ほかの人には出さない
   - 新しい法案のページ：題名の下に「元の法案：<題名>」（`/houan/<元の番号>` へ）。発議のあとも残る

6. **文言**：`ja.bill.resubmit`
