# 編・章・節の見出しと目次（設計書）

Issue #21。マイグレーションを足すので Careful。[docs/spec/8.md](8.md)（法令と版の DB）に、見出しの持ち方を足す。

## 目的

法令ページで、条文を編・章・節ごとの見出しの下に並べ（SpLaw・PcLaw の「第二章 人／第三節 行為能力」の帯）、目次から条へ移れるようにする（PcLaw の左の目次、SpLaw の「目次から探す」）。

## 範囲

- 入れる：本則の編・章・節・款・目（e-Gov の Part・Chapter・Section・Subsection・Division）の見出しを、版ごとに DB に持つ。取り込みで作る
- 入れない：附則（docs/spec/8.md と同じく対象外）、見出しの変わった記録（見出しが変わったかどうかは「変わった記録」に出さない）、IF世界の見出し

## 持ち方

`law_revisions` に列 `headings`（TEXT、JSON、NULL 可）を足す。中身は、その版の本則の見出しの木。

```json
[
  { "kind": "chapter", "num": "1", "title": "第一章　総則", "articles": ["1"], "children": [] },
  { "kind": "chapter", "num": "2", "title": "第二章　訪問販売、通信販売及び電話勧誘販売", "articles": [],
    "children": [
      { "kind": "section", "num": "1", "title": "第一節　定義", "articles": ["2"], "children": [] }
    ] }
]
```

- `kind`：`part`／`chapter`／`section`／`subsection`／`division`
- `num`：e-Gov の `Num` 属性（例：`5_2`）
- `title`：e-Gov の `PartTitle` などの文字列そのまま（「第五章の二　訪問購入」。番号と題名の間は全角スペース）。子要素が入っても `parse.ts` の `textOf` と同じくつなげる
- `articles`：その見出しの直下にある条の `num`（e-Gov の並び順）。子の見出しの下の条は、子の `articles` に入る
- 章立てのない法令（本則が条だけ）は `[]`

## 決めたこと

1. **版ごとの JSON 1つで持つ**：見出しは版ごとに数十個で小さく、版単位でしか読まない。条・項・号のような内部IDは振らず、表や差分の行にもしない。見出しだけが変わった版でも、その版の木をそのまま持つ
2. **条と見出しの結び付き**：`articles` の条の `num` で結ぶ。同じ版の `provision_versions` の `num` と同じ値なので、法令ページは「その版で有効な条」を `num` で見出しに振り分ける。本文は今までどおり `num` の順に並べ、帯は各条の見出しが前の条と変わるところに出す。木の中のどこにも出てこない条（本来ない）は帯なしで、`num` の順の位置のまま出す
3. **取り込み**：`parse.ts` に、見出しの木を返す純粋な関数 `parseHeadings` を足す（`parseLaw` は変えない）。MainProvision の `Part`／`Chapter`／`Section`／`Subsection`／`Division` をたどり、`TOC`・`SupplProvision`・`AppdxTable` は `parseLaw` と同じく飛ばす（TOC の見出しには条番号がなく `articles` を作れない）。`seedStatements` が `law_revisions` の列に `headings` を足して入れる
4. **マイグレーション**：`schema.ts` の `lawRevisions` に `headings: text('headings', { mode: 'json' })` を足し、`drizzle-kit generate` で `drizzle/0001_*.sql` を作る（中身は `ALTER TABLE law_revisions ADD COLUMN headings text`。snapshot と journal も一緒に更新される）。NULL を許す。今はローカルを毎回作り直すので NULL の版は生まれないが、本番で既存の行に足すときに備え、NULL は章立てのない法令と同じく見出しなしで出す
5. **D1 の文の大きさ**：見出しの JSON は1版あたり数KB。`law_revisions` の INSERT も、docs/spec/8.md の「1文 100KB 未満」の約束の中で分ける（今の `inserts` が行の大きさで区切る）

## 画面（受入基準の下書き）

- 法令ページで、条を見出しの帯の下に並べる。帯には、その条が属する見出しの `title` をそのまま、上から「／」でつないで出す（「第二章　訪問販売、通信販売及び電話勧誘販売／第二節　訪問販売」）。見出しが変わるところでだけ帯を出す
- PC は左に目次（見出しの木）、スマホは「目次から探す」で目次を開く。目次の見出しを押すと、その見出しの最初の条（その見出しの下の木を深さ優先でたどって最初の条）へ移る
- 章立てのない法令は、帯も目次も出さない

## テストの方針

- `parseHeadings` は Vitest で、特定商取引法の現在の版から作った木の形（章の数、第二章の下の節、第五章の二の題名）を確かめる
- 取り込みの SQL を `node:sqlite` に流したとき、`headings` が入っていることを、Issue #8 のテストと同じ流れで確かめる
- 画面は Playwright の2幅で確かめる

## あとで決めること

- 見出しだけが変わった改正を「変わった記録」や比較ページに出すか
- IF世界で章を足すとき（新法の制定を含む）の見出しの持ち方（フェーズ3）
