# IF世界の版と法令ページ、法案の基にする版（設計書）

Issue #72。マイグレーションがあり、条文の版に関わるので Careful。仕様の正は [docs/spec.md](../spec.md) の「法令データとブランチ」。法令の版は [docs/spec/8.md](8.md)、法案は [docs/spec/45.md](45.md)、結果は [docs/spec/71.md](71.md)。画面の案は `SpLaw`・`PcLaw`。

ユーザーと決めたこと（Issue #63 の決めたこと7〜8。仕様書のドキュメントへの反映はユーザー側）。

- 法令ごとに分岐した版を記録する。IF世界の版は可決で初めて作り、それまでは分岐した版を読む。v0.4 から、法案は「IF世界の最新」を基にする
- 同じ会期に複数可決して同じ条（内部ID）に触れたら衝突とし、発議の早い順に反映する。後の法案は要調整にし、提出者が次の会期の発議締切までに直せば、その会期の質疑に戻す。直さなければ廃案

次のことは仕様書にないので、この Issue の受入基準で確かめる（STOP 1 で確認する）。

- A. **衝突の範囲**：同じ会期に限らず、法案の基にした版より後で同じ条が変わっていれば衝突にする（前の会期に書いた下書きが、知らずに新しい条文を打ち消さないように）。足す条は同じ番号どうし。廃止は、基にした版より後の変更すべてと衝突し、廃止された法令への変更も衝突にする（`relatedBills` の「廃止は法令全部」と同じ考え）。制定は同じ法令名どうし
- B. **要調整の法案を直す**：提出者が書く画面で直す。直すと新しい版を作り、発議の時刻を直した時刻にする（付託先が次の会期になり、そこで質疑と採決をやり直す）。賛同は保ち、集め直さない（廃案からの出し直しと違い、可決までした法案なので）。票は会期ごとなので取り直しになる。**題名と種類と対象の法令は変えられない**（賛同を保つので、別の法案にしない）。対象の法令が廃止されて衝突した法案と、法令名が重なった制定は、前者は直せず期限で廃案、後者は法令名だけ直せる
- B2. **基にしたあとで変わった条の確かめ**：保存済みの下書きや要調整の法案を書く画面で開いたとき、基にした版より後で変わった条に触れていれば「ぶつかった条文」としていまの条文を並べ、「いまの条文を確かめました」のチェックがなければ保存しない。チェックして保存すると基にした版が最新に進む（#55 の案を IF世界に当てはめたもの）。廃止の法案には行がないので、基にした版より後に変わった条すべてを確かめの対象にする
- B4. **発議のときの確かめ**：基にした版より後で変わった条に触れる下書き（可決しても必ず要調整になる法案）は発議を断り、直すよう案内する。直すと版が変わるので、賛同は集め直しになる（今の賛同の決まりのまま）。発議のあとで衝突が確定したことの知らせは #78
- B3. **内部IDは条の単位**：衝突は条で見る（#63 のとおり）。IF世界の項・号に内部IDは振らない。docs/spec/45.md の「可決時に項・号へ内部IDを振る」は v0.4 では行わない。項の単位の履歴が要るようになったら別の Issue にする
- C. **前の会期の質疑と修正案**：消さず、読むだけで残す（答弁と評価はできない）。「答弁待ち」はいまの会期の質疑だけを数える。可決した修正案は本文に入ったまま。結果のページは今の付託先の会期を出す（直したあとは前の会期の結果を画面に出さない）
- D. **条の削除**：条を消さず、本文を「削除」にし、見出しは空にする（番号を残す日本の法令の書き方。`checkChanges` の `isDeleted` と同じ形）
- E. **制定と廃止**：制定の新法は `/if/hourei/if-<法案の番号>` で読める。廃止された法令は、IF世界の法令ページに廃止されたことを出す。**どちらも v0.4 では以後の法案の対象にしない**（制定した新法を改正する法案は別の Issue にする）。廃止された法令は書く画面の候補から外し、**その法令の下書きと、`if_laws` と同じ法令名の制定の下書きは発議も断る**（1会期の審議を無駄にしないため）。制定の新法への入口は結果のページだけ（法令の一覧は別の Issue）。新法のページに切り替えは出さない
- F. **帯と `noindex` を付ける範囲**：`/if/hourei` と結果のページ（#71）に帯。法案のページと投票の画面は案（`SpBillSummary`・`SpBillChanges`・`SpVote`）に帯がないので付けない。ただし架空の条文を出す**変更点のタブ、修正案のタブ、投票の画面には `noindex` を付ける**。書く画面が取りに行く条文の JSON（`/houan/kaku/joubun`）には `X-Robots-Tag: noindex` を付ける
- G. **IF世界の法令ページの中身**：条文、見出しの帯、目次、IF世界で変わった条に「IF世界で変わりました」と元の法案へのリンク。案の「現実の法律／IF世界の法律」の切り替えを現実の法令ページにも足す。**改正履歴、変わった記録、2時点の比較は IF世界には出さない**（現実との比較は別の Issue）

## 目的

可決した法案で IF世界の条文を変え、`/if/hourei` で読めるようにする。以後の法案は IF世界の最新を基に書く。衝突した法案は要調整にする。

## 範囲

- 入れる：分岐の記録、IF世界の版を作る処理（`settleSession` のあと）、衝突と要調整、`/if/hourei/<番号>`、結果のページの「IF世界の条文を見る」、法案の基にする版を IF世界の最新にすること、要調整の法案を直すこと
- 入れない
  - 現実の改正の取り込みと衝突（#74。追記の同期を入れる前に `ifBranchOf` で分岐を固定すること）
  - 確認中の法案の保留（#73）
  - 出し直し（#75）、通知（#78）
  - 制定した新法を改正する法案、IF世界と現実の比較（別の Issue を立てる）
  - 附則を IF世界の法令ページに出すこと（現実の法令ページも本則だけ）

## 決めたこと

1. **分岐**（`ifBranchOf(db, lawId)`。`src/lib/server/if-world.ts`）：行があれば読む。なければ、いま施行されている版で `INSERT ... ON CONFLICT DO NOTHING` して読み直す（`sessionParticipants` と同じ形）。#74 が現実の版を進める前に呼ぶ

2. **IF世界の条を読む**（`ifArticles(db, lawId, branchRevisionId, seq)`）：分岐した版の条（`articlesOfRevision`）に、`seq` 以下の `if_revisions` が指す `bill_changes` を順に重ねる。条の見分けは内部ID。足した条は `if_added_articles` の内部ID。`seq` を省くと最新。戻り値は `articlesOfRevision` と同じ形（`BaseArticle` に当てはまる）で、`changedBy`（最後に変えた法案）を足す

3. **法案の基にした条を読む**（`baseArticlesOf(db, law)`）：`law.baseRevisionId` と `law.baseIfSeq` から `ifArticles` を呼ぶ。今 `articlesOfRevision(db, law.baseRevisionId)` を呼んでいるところ（変更点のタブ、修正案、書く画面の確かめ）をすべてこれにする。修正案の「改正前」（`beforeText`）は、法案のいまの版でなく**修正案の `base_rev` の `bill_laws`** を読み、キャッシュの鍵に `seq` を含める（直したあとも前の会期の修正案の表示がずれないように）

4. **書く画面**：`draftArticles` は IF世界の最新の条を返す。`revisionId` は `<分岐した版>@<seq>` の形の印にする（フォームはそのまま送り返すだけ）。`bill-form` は印を分けて確かめ、いまの最新と違えば今までどおり 409（`baseChanged`）。形が違えば作り変えた値。`base_if_seq` を保存する。廃止された法令と、`if_laws` と同じ法令名の制定は断る
   - **基にしたあとで変わった条**（決めたことB2）：保存済みの法案を直すとき、保存済みの `base_if_seq` より後に変わった条に触れる行があれば、書く画面にいまの条文を並べる。保存の POST は `confirmConflicts` がなければ 400 で断り、いまの条文を返して並べる。印だけが進んで、古い本文で新しい条文を打ち消すことを防ぐ
   - 廃止された法令の既存の下書きは、書く画面に廃止されたことを出し、保存と発議（`proposeBill` の呼び手）を断る

5. **反映**（`applySession(db, session, previous, now, minutes)`）：`settleSession` の最後に呼ぶ。**その会期のすべての法案に結果が入ってから**、可決した法案を発議の早い順に処理する（docs/spec/71.md 決めたこと2 の条件）
   - **未反映の判定**：その会期の可決の結果で、`bill_results.rev` の版の `if_revisions`・`if_laws` がなく、`bill_adjustments` に（`bill_id`, その会期）の行がないもの。会期と版で見るので、直して次の会期に可決した法案も反映される。結果を書いたあと反映の前に失敗しても、やり直すと続きから進む
   - 法案ごとに衝突を調べる（決めたことA。`bill_results.rev` の版の変更点と、`base_if_seq` より後の `if_revisions`。**自分の法案の行は除く**）。衝突があれば `bill_adjustments` を入れる。**この INSERT は同じ文で「この版の `if_revisions`・`if_laws` がない」ことを確かめる**（同時に走った別の実行が反映したあとで、自分自身と衝突したことにしないため）
   - 衝突がなければ、足す条の内部IDを作り（`provisions` と `if_added_articles`）、最後に `if_revisions`（`seq` は1文で `MAX + 1`）か `if_laws` を入れる。**最後の1文が入ったときが反映**で、途中で失敗してもやり直せる。内部IDは DB が採番する（#74 の同期も同じにする）
   - `due_at` は、いまより後の最初の発議締切（`referralSession(now, minutes).deliberationAt`）。ふつうは次の会期の締切で、確定が遅れていればそのあとの締切になる。そのため `settleSession` に `minutes` を足す（Cron は `null`）
   - **1本が失敗したら、その会期の反映を止めて投げ直す**（`settleSession` と違う）。後の法案を先に反映すると発議の順が逆になり、取り消せないため
   - **会期をまたいだ順は守らない**：前の会期に未反映が残っていても（Cron が1か月止まり続けたときだけ起きる）、次の会期の反映は止めない。止めると1本の不具合で IF世界全体が止まるため。古い法案があとから反映されるときは、新しい変更と衝突すれば要調整になる。**例外**：別の会期の反映がちょうど同時に走ると（古い会期を読むときの処理と Cron など）、衝突の確かめと版の INSERT が別の文なので、両方が反映されて後の版が同じ条を上書きする。Cron が1か月止まったうえで同時に読まれたときだけ起きるので、許す
   - **0016 より前の法案**：`base_revision_id` が分岐した版と違う法案は見分けない。本番のデータがまだないので起きない
   - **Cron からも読む**：`src/lib/server/if-world.ts` は `cloudflare:workers`、`import.meta.env`、`#lib` に頼らない（docs/spec/71.md 決めたこと4）
   - **衝突の理由の優先**：`repealed` → `title` → `article`。条の衝突と法令の廃止が両方あれば `repealed`
   - 複数の法令の法案（#53）は1つでも衝突すれば全部を要調整にする。今は1本だけ。#53 では、途中で失敗した残りの法令の再開を決める
   - **読むときの処理**：`resultOnRead` は結果の行があるとすぐ返さず、可決で未反映なら `settleOnRead` を呼ぶ（docs/spec/71.md 決めたこと2 の「問い合わせ1回」は2回になる）
   - **修正案**：`settleAmendments` の `taken`（すでに採った条）と未適用の修正案を `session.key` の行に絞る。絞らないと、直して次の会期に可決した修正案が前の会期の修正案に負けて `superseded` になる

6. **段階**：`billStage(progress, outcome, adjustment, now)`。可決でもいまの付託先の会期の `bill_adjustments` があり未解決なら、`due_at` の前は `adjusting`（要調整）、そのあとは `lapsed`（廃案）。`reason` が `repealed` なら直せないので、すぐ `lapsed`。時刻から求め、期限切れを書き込まない。PC の段階の並びは、最後の段「結果」を「要調整」にする。一覧は「終わった」のタブのまま（`lapsedBefore` は変えない）

7. **要調整を直す**（`/houan/<番号>/kaku`）：提出者だけ、未解決で `due_at` の前だけ。`reason` が `repealed` なら直せない（画面にそう出し、リンクを出さない）。書く画面の確かめ（登録から7日、上限、Turnstile、入力、決めたことB2）は下書きの保存と同じで、題名と種類と対象の法令の変更は断る（`reason` が `title` のときだけ法令名を変えられる）。保存すると新しい版を作り（`insertContent`）、**`advanceBill` と同じく `db.batch` で**次を1つのトランザクションにする。順と条件は次のとおり
   1. 賛同の行を新しい版に写す。**写す元は `proposed_rev` の行**（修正案が当たった法案は `rev` と違う）。条件は `bills.rev` が開いたときの版
   2. `bills` を変える：`rev`・`proposed_rev`・`proposed_at`・`updated_at` と、**版の行でなく `bills` にある本文の列（`fields(input)`。誰が困っているか、副作用、3行要約、附則）**。条件は `rev` が開いたときの版で、調整の行が未解決で `due_at` の前
   3. `bill_adjustments` の `resolved_at` を入れる。条件は**`bills.rev` が新しい版**（2で進んでいるので、開いたときの版と比べると0行になる。`advanceBill` と同じ形）

   読み直して `rev` が新しい版でなければ、断る。段階（決めたこと6）に渡す調整の行は**いまの付託先の会期の行だけ**にする。付託先は `referralSession` で次の会期になる。発議の時刻が変わるので、`relatedBills` の「発議のあとに変わらない」の説明も直す。法案のページの提出者に期限と直すリンクを出す

8. **結果のページ**：次の4通り。可決で反映済みなら「IF世界の法律になりました」と「IF世界の条文を見る」（1つ目の法令へ）。要調整なら理由ごとの文言（`article`：「可決しましたが、先に変わった条と重なるので、調整が要ります」、`repealed`：「可決しましたが、対象の法令が先に廃止されたので、IF世界の法律になりません」、`title`：「可決しましたが、同じ名前の法律が先にできたので、調整が要ります」）と期限。期限切れなら「調整の期限までに直されなかったので、廃案になりました」。反映がまだなら「IF世界の法律にする手続きをしています」

   前の会期の質疑（決めたことC）：質疑の行に会期を持たせ、答弁のフォームと評価のボタンはいまの付託先の会期の質疑にだけ出す。`waitingQuestions` と `listQuestions` の `onlyWaiting` はいまの会期に絞る

9. **IF世界の法令ページ** `/if/hourei/<番号>`（`SpLaw`・`PcLaw` の形）：ログインは要らない。`IfBand`、「架空の法令」の表示、`noindex`。現実の法令にある番号か `if_laws` の番号だけ。ほかは 404。現実の法令ページと部品を分け、条の表示は共通の部品にする（`src/lib/components/LawParagraphs.svelte`）

10. **現実の法令ページ**：「現実の法律／IF世界の法律」の切り替えだけを足す。条文、帯のなさは変えない

11. **書く画面の条文**：`/houan/kaku`、`/houan/<番号>/kaku`、`shusei/kaku` の条文のそばに「ここに出る条文は IF世界の最新です（架空の法令）」と出す。帯は付けない（案にない）

12. **文言**：`ja.ifLaw`。画面に「ブランチ」「マージ」「反映」「分岐」を出さない
