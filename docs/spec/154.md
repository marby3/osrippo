# 統計ページ（設計書）

Issue #154。統計の匿名化の基準に触れるので Careful。仕様の正は [docs/spec.md](../spec.md) の「統計の公開」「匿名化の基準」「法案の橋渡しスコア（最初の版）」。前提の決定は Issue #147 の決めること20・21、受入基準と決めたことは Issue #154（2026-11-12 ユーザーと決定）。立場別の分布の集計は [87.md](87.md)、評価と「考えが変わった」の数え方は [67.md](67.md)、5%刻みは [149.md](149.md)。

## ユーザーと決めたこと（Issue #154）

1. **立場を超えた支持（法案）**：締切の時点のその法案への立場で賛成寄り・反対寄りに分け、それぞれの数えた票のうち「賛成」の割合の低いほうを採る。どちらかが10人未満の法案は順位に入れない。5%刻み
2. **「考えが変わった」の順位**：質疑と答弁のうち10人以上から付いたものを多い順に。付いた数は出さない
3. **範囲**：会期ごとに切り替え。最初はいちばん新しい終わった会期
4. **入り口**：PC はヘッダーに「データ」のタブ。スマホは下の5つのタブを変えず、メニュー（人の形のボタンの先）に「データ」

## この設計書で決めること

- A. **ページ**は `/toukei`、会期は `?kaiki=2050-05`（開発用の短い会期は `m8-123` の形）。ログインは要らない。IF世界の条文は出さないので IF世界の帯は付けない（法案の題名と結果だけ。結果のページへのリンクの先に帯がある）。`noindex` は付けない（統計は公開して楽しむページ。仕様の「統計は積極的に公開」）
- B. **終わった会期**は、結果の行（`bill_results`）がある会期のうち、会期の終わり（`endsAt`）を過ぎたもの。並びは結果を記録した時刻（`settled_at` の最大）の新しい順（短い会期の番号を文字の順で並べないため）。最初に出すのはその先頭
- C. **統計ページは結果を作らない**。結果は今までどおり Cron（毎日0時1分）か、結果のページ・法案のページ・一覧の「終わった」のタブを読んだときに作られる（71.md の B）。統計ページはどの要求でも会期の処理を呼ばない（重い処理を公開のページに足さないため）。会期が終わってから Cron が走るまでは、その会期は選べない
- D. **`?kaiki=` の確かめ**：形が違えば 404。形が合っていても、まだ終わっていない会期（`now < endsAt`）は 404。終わっていて結果の行がない会期は 200 で、3つの欄に「この会期に採決した法案はありません」を出す（会期の一覧には出ない）。開発用の短い会期の番号は、いまの設定の分数と合うときだけ受ける
- E. **法案の結果**（基準3）：その会期の結果の行を、題名の順ではなく法案の番号の順に並べる。確認の行が `open` なら「結果を確認しています」だけ（可否と票の数をページのデータにも入れない）。`voided` なら「廃案」と出し、票の数は結果のページと同じく出す。ほかは可決・否決・廃案と、数えた票（賛成・反対・棄権）
- F. **立場を超えた支持の計算**（基準4）：#87 の `stanceStatsOf` で法案ごとの丸める前の人数を読み（なければ作る。確認中・無効は null）、ルールの関数 `billBridge(votes)` が `for` と `against` の合計がどちらも `STATS_MIN`（10）以上のときだけ `min(for.yes / for合計, against.yes / against合計)` を返す。未定の人は入れない（仕様は2グループ）。画面に渡すのは `roundRatio` で丸めた値だけ。並びは丸めた値の高い順、同じなら法案の番号の順（丸める前の値で並べると、同じ割合に見える法案の順から細かい差が分かるため）。10本まで
- G. **「考えが変わった」の数え方**（基準5）：今の `sessionPostScores(db, sessionKey)` の `changed`（評価の上限を当てた数。67.md の H・I）。1人が1つの投稿に付けられるのは1回なので、`changed` は付けた人の数。10以上の投稿を、`changed` の多い順、同じなら投稿の番号の順に10件。数は並びに使うだけで、ページのデータには入れない。投稿の状態が見えている（`POST_SHOWN`）ものだけ（`sessionPostScores` は「まとめた」投稿も数えるが、まとめた投稿は出さない）
- H. **順位に出す投稿の中身**：「質疑」か「答弁」かの別、本文のはじめの60字（それより長ければ「…」）、法案の題名、`/houan/{法案}/shitsugi#shitsugi-{質疑の番号}` へのリンク（答弁なら親の質疑の番号）。投稿者の名前は出さない
- I. **入り口のスマホ**：メニュー（`/watashi`、ログインが要る）に「データ」のリンクを足す。ログインしていない人のために、採決のタブの一覧（`/saiketsu`）の下にも「データを見る」のリンクを足す（スマホの下のタブは5つのまま）
- J. **「データ」のタブ**：`TABS` に `toukei`（`/toukei`）を足し、PC のヘッダーにだけ出す。スマホの下のタブはいままでの5つ（`TABS` から `toukei` を除いて並べる）。`tabOf('/toukei')` は `toukei`

## 範囲

- 入れる：`/toukei` のページ、会期の一覧と確かめ、法案の結果、2つの順位、PC のタブ、スマホの入り口、文言
- 入れない：投票傾向の匿名マップ、立場の動きの再生、現実の国会との違い、委員会ごとの賛否の割れ方（#147 の決めること21）、会期をまたいだ順位、統計ページから結果を作ること（C）

表は足さない（マイグレーションなし）。

## ルールの関数（`src/lib/domain/toukei.ts`）

- `sessionFromKey(key: string, minutes: number | null): Session | null`：`YYYY-MM`（月は01〜12）ならその月の会期、`m{分}-{番号}` なら `minutes` と分が同じときだけその会期。ほかは null
- `billBridge(votes: StanceStatsData['votes']): number | null`（F。丸める前）
- `rankBridges(rows: { billId; title; bridge: number | null }[]): { billId; title; ratio }[]`：null を除き、丸めた値の高い順・番号の順に10本
- `rankChanged(rows: { postId; changed }[]): number[]`：`changed >= STATS_MIN` を多い順・番号の順に10件の番号だけ
- `excerpt(body: string): string`（60字）

## サーバーの関数（`src/lib/server/toukei.ts`）

- `finishedSessions(db, now, minutes)`：B。`bill_results` を `session_key` ごとにまとめ、`max(settled_at)` の新しい順。`sessionFromKey` で会期に戻し、終わったものだけ
- `sessionResults(db, session)`：E。結果の行と確認の行と法案の題名
- `bridgeRanking(db, session, bills, minutes, now)`：F。確認中・無効でない法案ごとに `stanceStatsOf`
- `changedRanking(db, session)`：G・H。`sessionPostScores` から番号を選び、その投稿（答弁なら親の質疑）と法案の題名を読む。読む番号は10個までなので D1 の値の数の上限にかからない
- ページの読み込みが返すのは、題名・可否・票の数・丸めた割合・本文のはじめ・リンクの番号だけ。グループの人数と `changed` は返さない

- 会期の選択：`<form method="get">` の `<select name="kaiki">`（「会期」）と「表示する」ボタン（JavaScript がなくても動く）。選べるのは B の一覧
- 見出し2「{2050年5月の会期}の法案の結果」：表（題名（結果のページへのリンク）・結果・賛成・反対・棄権）。スマホは横にはみ出さないよう、表を横に送れる枠に入れる
- 見出し2「立場を超えた支持が多い法案」：番号付きの並び（`<ol>`）。各行に題名（結果のページへのリンク）と「立場を超えた支持 35%」。注記「その法案に賛成寄りだった人と反対寄りだった人の、それぞれの賛成の割合のうち、低いほうです。どちらかが10人に満たない法案は入れません。」

## テスト

- **ルールのテスト**（`src/lib/domain/toukei.test.ts`）：`sessionFromKey`（月の形、13月、分の会期の分が違う）、`billBridge`（10人ちょうどと9人、未定は入れない）、`rankBridges`（丸めた値で並べ、同じなら番号の順）、`rankChanged`（10ちょうどと9）
- **画面のテスト**（`e2e/toukei.spec.ts`、2幅。基準ごとに1本。ほかのテストと会期がぶつからない年）
  - 基準1：PC はヘッダーの「データ」（いまのタブ）、スマホは下のタブが5つで「データ」がなく、わたしの記録と採決の一覧から行ける。ログインなしで 200
  - 基準2：2つの会期で結果を作り、最初は新しいほう、選ぶと URL に `?kaiki=` が付いて切り替わる。`?kaiki=abc`・まだ終わっていない会期で 404
  - 基準3：可決・否決・廃案の法案の行（題名・結果・票の数・リンク）。確認中の法案は「結果を確認しています」で、ページのデータに票の数がない
  - 基準4：両方のグループが10人以上の法案に「立場を超えた支持 N%」。片方が9人の法案は入らない。ページのデータに人数がない
  - 基準5：10人が「考えが変わった」を付けた質疑が出て、9人の質疑は出ない。ページのデータに数がない
  - 基準6：2幅で横にはみ出さない。色は今までの `src/lib/styles/tokens.test.ts` が担う

基準3〜5の準備は重い（数えた票を入れる人を10人以上、評価を付ける人を10人以上作る）ので、同じワーカーの中で1つの会期を作って使い回す（#87 の画面のテストと同じ形）。
