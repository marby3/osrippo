# 法案を書く画面で、2本以上の法令と、別の課題の解決策を扱う（設計書）

Issue #53。IF世界への反映（会期終了時の処理）に触るので Careful にする（ラベルを `mode:careful` に変える）。仕様の正は [docs/spec.md](../spec.md) の「法案」の項（「1本の法案で複数の法令を扱える。新法の附則で関連法を改正する形と、『○○法等の一部を改正する法律』のような一括改正の形を認める。対象法令は5本まで」「1つの法案が複数の解決策をまとめてもよい」）。表と形の決まりは [docs/spec/45.md](45.md) の決めたこと5・6、反映は [docs/spec/72.md](72.md) の決めたこと5。書く画面の絞り込みは Issue #46 の決めたこと1と基準1。

マイグレーションはない（`bill_laws` と `bill_changes` は最初から法令5本の形で、`if_revisions` は法令ごとの行を持つ）。

## 入れるものと入れないもの

- 入れる：書く画面と直す画面で2本以上の法令を扱う、別の課題の解決策を探して選ぶ、変更点のタブと修正案と結果のページの法令名、複数の法令の反映を全部入るか全く入らないかにする、新法の IF世界のページの混ざりを直す
- 入れない：附則の文章から変更点を読み取ること（決めたこと1）、「条文全体のなかで見る」（#54）、解決策を探す専用のページ（決めたこと7）、委員会の対象法令を増やすこと

## 決めたこと

1. **附則で関連法を改正する形の表し方**：関連する法令の変更点を、主の法令と同じ「変える条」の欄で書く。附則の欄は今のまま自由文で（いつから始めるかなど）、文章から変更点を読み取らず、文章を自動で作ることもしない。法的な形の違いは正式名（`formalName`）と変更点のタブの法令名で示す。STOP 1 で確認する
2. **種類ごとの形**（docs/spec/45.md 決めたこと5 のまま。`lawShapeOk`）：
   - 改正：すべて改正（一括改正）
   - 制定：主が新法、ほかは改正
   - 廃止：主が廃止、ほかは廃止か改正。ほかの法令の扱いは法令ごとに選ぶ（廃止の法令に変える条の欄は出ない）
   - 主の法令（`seq` 0）は外せず、選び直せる。足した法令は外せる。正式名の主は `seq` 0
   - 選べる法令は委員会の対象法令のうち IF世界で廃止されていないもの（`committeeLawList`）。**いま対象は3本なので、実際の上限は改正が3本、制定が新法＋3本**。ほかの枠で選んだ法令は選択肢に出さない（作り変えて同じ法令を送ると 400）
3. **フォームの形**（作り変えを防ぐ入口。今のフォームの名前は変えない）
   - 主の法令：`law`、`base`（今のまま）
   - 足した法令：`law.N`、`base.N`、`action.N`（N は 1 から続く番号。`law.N` は 1〜5 を読み、番号が飛んでいれば 400、6本以上は `lawCount` で 400。枠を外すと画面が番号を振り直す）。`action.N` は `amend` か `repeal`、なければ `amend`。`lawShapeOk` が種類との組み合わせを確かめる
   - 変更の行：`op.i` などの i は法案全体の通し番号のまま（行の誤りを返す位置が1つで済み、「50条まで」もそのまま数えられる）。どの法令の行かを `seq.i` で指す（なければ 0）。`seq.i` が `0` から法令の数の範囲の整数でなければ 400
   - 制定の新法の条は `seq` 0 の行。番号は新法の行の中で 1 から順に付ける
4. **確かめ**（`checkBillForm`）：法令ごとに今の確かめを行う（版の印、廃止されていないこと、基にした版が最新か、`checkChanges`）。`checkChanges` の誤りの位置は法令の中の位置なので、通し番号へ戻して返す
   - 空の `law.N` は「選んでください」をその法令の欄に出す（400）。主の空は今のまま
   - 法令全体の誤り（変える条がない、廃止に条がある）はその法令の欄に出す。足した法令の誤りは `errors.laws[seq]` に `{ law?, changes? }` で持つ。主の法令の誤りは今のまま `errors.fields.laws` と `errors.changes` に置く（今の画面とテストの位置を変えない）。足した枠では、法令を選ぶまで変える条の欄を出さない（入力必須の欄でブラウザが送るのを止め、枠のそばの誤りが出なくなるため）
   - どれかの法令で基にした版が古ければ、全体を 409 で断り、開き直すよう案内する（今のまま）
5. **直す画面**：`/houan/<番号>/kaku` は `bill.laws` のすべてを読み、法令ごとに条（`draftArticles`）、いまの番号（`currentNumsOf`）、ぶつかった条文（`staleArticles`）を求める
   - ぶつかった条文は法令が2本以上なら法令名を付ける。確かめのチェックは全体で1つ。保存のとき `staleArticles` は `lawId` が同じ保存済みの法令と比べる（今は1つ目だけ。足したばかりの法令は基にした版が最新なので比べない）
   - 法令の1本でも IF世界で廃止されていれば、どの法令かが分かるように法令名を付けて知らせ、保存を断る（`checkBillForm` が断る）。その枠は選び直すか外せば保存できる
   - **要調整を直すとき**は法令の組を変えられない（選択と外すと足すを出さない）。`saveAdjustedBill` の `sameLaws` に `action` の一致を足す（今は位置ごとの `lawId` と `newTitle` だけで、廃止の法案の関連法の扱いを変えられてしまう。位置ごとに比べるので、順番の入れ替えは今も断る）
   - **対象の法令が先に廃止された法案の出口**：要調整の `repealed` は今のまま直せず、すぐ廃案になる（docs/spec/72.md 決めたこと6）。残りの法令の変更を活かせるように、**出し直しは「すべての法令が廃止された」ときだけ断る**（`resubmitStateOf` の `some` を `every` に。新法を含む法案は断らない。1本の法案は今と同じ）。写した下書きを直す画面で、廃止された法令の枠を外すか選び直す。そのままでは保存と発議を断る（今のまま）
6. **画面（書く）**：キャンバスに案がないので SpBillChanges の形と Tokens で組み、STOP 2 のスクリーンショットで確認してもらう（#46 決めたこと）。法令ごとの枠の中に、選択と版の読み込みと変える条を持つ。枠の下に「ほかの法令も変える」のボタン。制定と廃止では「新しい法律（または廃止の法案）の附則で改正する形になります」の説明を添える。枠ごとに条を別々に取りに行く（`/houan/kaku/joubun` をそのまま使う）。どの枠も基にした版が決まるまで送れない
7. **別の課題の解決策**：書く画面の「元になった解決策」の欄の中に「ほかの課題の解決策を探す」を置く。別のページにしない（書いた内容が消えないように、戻る操作も要らないように）
   - `GET /houan/kaku/kaiketsu?q=`：JSON。`parseQuery` と `searchSolutions`（`/kensaku` と同じ。表示中の解決策で課題も一覧に出るもの、「わかる」の多い順）で20件まで。公開の情報なのでログインは要らない（`/kensaku` と同じ）。回数の制限はアプリでは掛けず、`/kensaku` と同じく Cloudflare の WAF で掛ける（デプロイのときにやることに足す）。言葉の形の誤りは 200 で理由を返す（`/kensaku` と同じ）。内部の番号は解決策と課題の番号だけ
   - 結果は本文と課題名を出し、「選ぶ」で引用の候補に足してチェックを入れる。5つ選んでいれば選べない。すでに候補にあるものは「選んだ解決策」と出す。20件を超えたら「言葉を足して絞ってください」
   - 候補は課題ごとに分けて出す（課題が2つ以上のときだけ課題名の見出し）。`candidateSolutions` に課題名を足す
   - 探す欄の中で Enter を押してもフォームを送らない
   - **選んだ解決策が消えないこと**：探して足した候補は画面の状態に持つ。フォームは `use:enhance` で送るので、400 と 409 で画面が作り直されず消えない（JS がないと Turnstile を通らないので、JS なしの再表示はない）。保存したあとは `citedCandidates` が引用の課題ごとに候補を読むので、別の課題の解決策を引用した下書きを開いても出る。あとで非表示になった解決策は今のとおり候補に出ず、保存すると外れることを知らせる
   - `checkBillForm` の「同じ課題のものだけ」（`solutionsOneIssue`）をなくす。引用できるのは今のとおり一覧に出る課題の表示中の解決策だけ
8. **反映は全部入るか全く入らないかにする**（`applyBill`。docs/spec/72.md 決めたこと5 の「複数の法令は #53 で決める」の答え）
   - 問題：今は `if_revisions` と `if_laws` を法令ごとに別の文で入れる（廃止も `if_revisions` の行で、ほかの表は変えない）。途中で失敗すると、やり直しの判定（`applySession` の `NOT EXISTS if_revisions`）が「反映済み」とみなし、**残りの法令が永久に反映されない**
   - 決定：途中からの再開を作らず、失敗しても半端に残らない形にする。準備（`ifBranchOf`、足す条の内部ID。何度やっても同じで、版から指されなければ読まれない。内部IDの作り方は変えない：`if_added_articles` は法令と番号で引き、`provisions` は DB が採番するので、2本の法令で同じ番号の条を足しても重ならない）を全部の法令で終えてから、`if_revisions` と `if_laws` の行を **`db.batch` で1つのトランザクションにして入れる**。バッチが入ったときが反映。再開が要らないので判定の条件は変えない
   - batch の中は builder（`db.insert(ifRevisions).values({ seq: nextIfSeq(lawId), ... }).onConflictDoNothing({ target: [billId, billRev, lawSeq] })`。`importLaw` と同じ形）。値つきの `db.run(sql)` を入れない（本物の D1 でだけ落ちる）
   - `if_laws` の `onConflictDoNothing` は `id`（`if-<法案の番号>` で法案から1つに決まる）だけを対象にする。**題名の重なりは握りつぶさない**：別の法案の同じ題名の新法が衝突の確かめのあとに入ったら、バッチ全体が失敗して巻き戻り、次の処理で `title` の要調整になる（握りつぶすと関連法だけ反映された新法のない法案になる）。SQLite で確かめた：同じ `id` で同じ題名の行は何も入らず、別の `id` で同じ題名の行はエラーになる
   - **失敗の受け方**：今のまま。`applySession` は1本が失敗したら止めて投げ直し、次の Cron（翌日）か、結果のページを読むときの処理でやり直す（docs/spec/72.md 決めたこと5。順を逆にしないため）。失敗し続ける法案があると後ろも止まるのは今と同じで、ログに出る
   - 同時に走ったもう1つの実行：`if_revisions_bill` の一意と `if_laws` の主キーで何も入らない。先に読んだ一覧の法案が相手の実行で反映されていても、衝突の確かめは自分の法案の行を除くので（`touching` と `conflictOf` の `billId`）、要調整にならない。今と同じ
   - 衝突の判定は今のまま（1本でも衝突すれば全部を要調整。理由の優先も同じ）
   - 本番のデータはまだないので、半端に反映された法案を直す処理は要らない
9. **新法の IF世界のページ**（`ifLawPage`）：今は `bill_changes` を法案と版だけで読むので、関連法の条が新法の条に混ざる。新法の `law_seq`（0）に絞る。これは #53 で初めて起きる
10. **結果のページ**：`ifPlaceOf` を `ifPlacesOf` に変え、法令の順（`seq`）にすべて返す（今は `if_revisions` を先に見るので、制定＋関連法で新法でなく関連法へ行く）。リンクは1本なら今の「IF世界の条文を見る」のまま、2本以上なら法令ごとに「IF世界の条文を見る（景品表示法）」を出す。廃止した法令へのリンクは、IF世界の法令ページの今の廃止の表示を出す。`resultOnRead` は1本でもあれば反映済みとする（決めたこと8 で半端がない）
11. **法令名を出す場所**（法令が2本以上の法案だけ。1本のときは今のまま）：`法令名 第2条` の形
    - 変更点のタブと採決の画面（`billChangeViews` の `location`。どちらも同じ関数）。連番は法案全体で続ける
    - 修正案：タブの一覧は今も出ている。**足すのは**非表示の修正案の欄（`hiddenAmendmentsFor`）、運営の画面（`reportedAmendments`）、結果のページの修正案の行（`priorAmendmentResults` の呼び手）
    - 法令名は修正案の基にした版（`base_rev`）の `bill_laws` から引く
12. **変えないもの**：`validateBill` の形、`formalName`、`insertContent`、`draftInputOf`（出し直しと統合案はこのまま全部の法令を写す）、`relatedBills`、`proposeBlock`、`notifyConflicts`、`amendableArticles`（すでに法令ごと）

## 受入基準の案

1. **一括改正**：改正の法案で「ほかの法令も変える」から2本目の法令を選び、法令ごとに変える条を書いて保存できる。正式名は「主の法令名等の一部を改正する法律案」。変更点のタブは「1. 消費者契約法 第1条 ・ 書きかえ」のように法令名つきで、連番は法案全体で続く
2. **制定＋関連法**：制定の法案に関連する法令を足し、その法令の変える条を書いて保存できる。正式名は「新法の名前＋案」のまま。新法の条の番号は新法の中で順に付く
3. **廃止＋関連法**：廃止の法案で、足した法令を廃止か改正で選べる。正式名は廃止が1本なら「Aを廃止する法律案」、2本なら「A等を廃止する法律案」
4. **直す**：2本の下書きを開くと両方の中身が入っていて、法令を足す・外す・直すことができる。基にした版が古い法令があれば開き直すよう案内する。ぶつかった条文は法令名つきで出る。要調整を直すときは法令の組と扱いを変えられない。対象の法令の一部が先に廃止されて廃案になった法案は出し直せて、廃止された法令を外せば保存できる
5. **入力の誤り**：法令を選んでいない枠、変える条のない枠はその枠のそばに誤りを出し、入力は残す。50条までは法案全体で数える
6. **別の課題の解決策**：書く画面で言葉を入れて探し、別の課題の解決策を選んで保存できる。法案のページに、その解決策と元の課題へのリンクが出る。5つまで。非表示の解決策は探しても出ない。直す画面でも同じ
7. **反映**：2本以上の法令の法案が可決すると、すべての法令が IF世界に入り、結果のページに法令ごとのリンクが出る。1本でもぶつかれば全部が要調整になる。途中で失敗しても半端に残らず、次の処理で全部入る
8. **新法のページ**：制定＋関連法が可決すると、新法の IF世界のページには新法の条だけが出て、関連法の条は関連法のページに出る
9. **修正案の法令名**：2本以上の法令の法案で、修正案のタブ、非表示の修正案の欄、運営の画面、結果のページのどこでも、「第2条」に法令名が付く。関連法の条への修正案が可決すると、その法令に入る

信頼の境界のテスト（それぞれ1本）

- フォームの `law.N`、`base.N`、`action.N`、`seq.i`、`solution`：対象外の法令、同じ法令を2つ、番号の飛び、形の違う版の印、ほかの法令の版の印、種類と合わない扱い（改正の法案に廃止）、範囲外の `seq.i`、6本以上、非表示の解決策、形の違う解決策の番号はすべて 400 で保存しない
- `GET /houan/kaku/kaiketsu?q=`：短い言葉、長い言葉、制御文字は 200 で理由を返す。`q` がなければ結果なし。500 にならない

## テストの方針

- 単体（`src/lib/db/`、`openMemoryDb`）：決めたこと8 の失敗（トリガーで2本目の法令の INSERT を一度だけ失敗させ、何も入っていないことと、やり直すと全部入ること）、題名の重なりで巻き戻ること、決めたこと9、決めたこと10、決めたこと11 の法令名、`checkBillForm` の通し番号
- 画面（`e2e/houan-fukusu.spec.ts`。年は 2478 から、IP は 10.115 から）：基準1〜6、基準9 の画面。可決するテストは `IF_LAW`（景品表示法）の未使用の条を使い、制定＋`IF_LAW` で基準7・8 を確かめる。消費者契約法は可決しない
- 新しい batch の形は画面のテストで本物の D1 を通ることまで確かめる（`db.batch` に入れる形を変えるので）

## 画面の言葉

- ボタン「ほかの法令も変える」「この法令を外す」。足した法令の見出し「対象の法令 2」（制定と廃止は「関連する法令 1」）
- 法令の扱い「廃止する」「一部を改正する」
- 探す欄「ほかの課題の解決策を探す」「探す」「選ぶ」「選んだ解決策」「当てはまる解決策はありません」
- 実装用語（反映、衝突など）は出さない
