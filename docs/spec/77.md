# 委員長選挙と理事、解任動議（設計書）

Issue #77。マイグレーションがあり、運営の画面の権限と結果の確認に関わるので Careful。決定は Issue #63 の決めたこと16「立候補はその会期に質疑か答弁を1件以上書いた人。投票は1人1票で最多得票、同数はくじ。解任動議は今月の参加者の 20%、理事の代行は7日」。仕様は [docs/spec.md](../spec.md) の「委員長の選び方」。画面の案はない（`SpVote`・`PcVote` にそろえる）。

仕様のとおりにすること：次の会期の委員長は前の会期の4週目に選挙で決める。立候補制。初回の会期は委員長を置かず、運営が事務局として行う。任期は1会期で、連続は2会期まで。次点を理事とする。運営は選任に関与しない。委員長の仕事は、質疑の整理、通報の一次対応、類似課題の統合、「確認中」法案の確認。

次のことは仕様書に定めがないので、この Issue の受入基準で確かめる（STOP 1 で確認する）。

### 選挙

- A. **時期**：立候補は4週目の前半、投票は4週目の全部（`voteAt`〜`endsAt`。法案の採決と同じ期間）。最後に立候補した人にも票が入る時間を残す。立候補は前半のあいだ取り下げられる。票は締切まで変えられる（法案の票と同じ）
- B. **立候補できる人**：その会期に、その委員会の法案に質疑か答弁を1件以上書いた人（非表示は数えない。決定16）。登録から7日、国、締め出し、Turnstile を確かめる。**連続して2会期務めた委員長は立候補できない**（いまの会期と前の会期の委員長。解任された任期も数える）。仕様の「実績が一定以上」は、実績の計算がフェーズ5なので、決定16のとおりここでは見ない
- C. **投票できる人**：法案の数えた票と同じ資格（`isEligibleVoter`。「参考の票」はない。資格のない人には押させず理由を出す）。登録から7日、国、締め出し、Turnstile を確かめる。自分に入れてもよい
- D. **結果**：最多得票が委員長、次の3人までが理事。1票以上入った候補だけ。同数はくじ。候補がいないか票が0なら、次の会期は委員長なし（運営が事務局のまま）。公開するのは委員長と理事の名前だけで、得票数は出さない（少ない票数で誰が入れたか推測できるのを避ける。合計の票数は出す）。立候補を取り下げた候補への票は数えない。結果は書き込んだら変えない
- E. **確定**：会期の終わりの処理で（Cron と、委員会のページを読むとき）。締切から1分は処理しない（`SETTLE_GRACE`）。何度走っても同じ

### 委員長の権限

- F. **できること**：運営の画面（`/kanri`）の、通報を受けた課題と解決策の非表示と表示に戻す、類似課題の統合、「確認中」法案の確認。提出者や賛同者や本人の課題を扱えない決まりは今のまま。運営と運営協力者の権限は変えない（委員長がいても運営は操作できる）。記録の `actor` は `chair` か `director` で、画面には「委員長」「理事」と出す
- G. **「質疑の整理」（似た質疑をまとめる）はこの Issue に入れない**：質疑の操作の記録の仕組みが要るので、質疑の通報と非表示（#80）と一緒に作る

### 解任動議

- H. **署名が今月の参加者の 20%（最低3人）に届くと解任する**（動議のあとの投票はしない。任期が1か月なので、投票を挟むと終わってしまうため）。署名できるのは法案の数えた票と同じ資格の人で、登録から7日、国、締め出し、Turnstile を確かめる。委員長本人と理事は署名できない（代行で利益を受けるので）。解任の前なら署名を取り消せる。だれが署名したかは出さず、人数と必要な人数だけ出す。解任は元に戻せない
- I. **解任のあと**は理事が代行する。理事がいなければ運営が事務局に戻る。解任された人は、その任期の委員長の権限を失う。結果の表示に「解任」と出す

### 理事の代行

- J. **委員長が7日何もしないと、理事が代行できる**（決定16）。「何もしない」は、任期の始まりか、委員長の最後の操作（`moderation_logs`、解決策の非表示、結果の確認）から7日。理事は全員が同じ権限で、順位はない。委員長が操作すると代行は止まる（時刻から求めるので、状態を書き込まない）。代行の操作の記録の `actor` は `director`。7日たつ前の理事に権限はない

## 目的

委員会の参加者が委員長を選び、委員長が通報や確認中の法案を扱えるようにする。運営の負担を分ける。

## 範囲

- 入れる：立候補、投票、結果の確定、委員会のページ、解任動議、代行、`/kanri` の権限
- 入れない：質疑の整理（#80）、実績の計算（フェーズ5）、立候補の抱負、委員長への通知（#78）、新しい委員会を作ること（委員会は今1つ）、任期の途中の辞任（解任か任期の終わりまで。使われ方を見て足す）

## 決めたこと

1. **ルール**（`src/lib/domain/chairs.ts`。純粋な関数）：
   - `candidacyOpen(session, now)`：`voteAt <= now < voteAt + (endsAt - voteAt) / 2`。`electionOpen(session, now)`：`voteAt <= now < endsAt`
   - `electionResult(candidates, votes, random)`：得票の多い順、同数はくじ（`random` を受ける）。1票以上の候補だけ。返すのは順位つきの列
   - `DIRECTOR_MAX = 3`、`recallRequirement(participants) = max(3, ceil(participants * 0.2))`、`ACTING_AFTER = 7日`
   - `consecutiveLimit`：いまの会期と前の会期の両方で委員長（`role = 'chair'`。解任された任期も数える）なら立候補できない

2. **選挙**（`src/lib/server/chairs.ts`）：`standForChair`、`withdrawCandidacy`、`castChairVote`、`electionPage`。どれも期間と資格を条件に入れた1文（`castChairVote` は候補の行があることも文の条件に入れる。`INSERT ... SELECT ... ON CONFLICT DO UPDATE`）。受け付けの順は、ログイン → 国 → 締め出し → 登録から7日 → Turnstile → 入力 → 期間（409）→ 資格（403）

3. **確定**（`settleElection(db, committeeId, session, now, random)`）：`now < endsAt + SETTLE_GRACE` なら何もしない。`chair_elections` に行があれば何もしない。取り下げていない候補の票を集計して `electionResult` を求め、`chair_elections` の行と `chair_terms` の行（次の会期を任期にする）を `db.batch` で入れる。`chair_elections` の主キーで2回目の実行は何も変えない：`chair_terms` の文は `ON CONFLICT DO NOTHING`、同時に走って違うくじを引いても、先に入った行だけが残るよう、**`chair_terms` の文に「この会期の `chair_elections` の行の `settled_at` がこの実行の値」を条件に入れる**。呼ぶのは `runSessionEnd` の最後（取り込みの前後どちらでもよいので、取り込みの前）と委員会のページの読み込み。失敗しても法案の会期の処理を止めない（ログに出して Cron を失敗にする）

4. **権限**（`chairPowerOf(db, userId, now)`）：いまの会期の `chair_terms` を読む。
   - `role = 'chair'` で `recalled_at` が NULL なら `chair`
   - `role = 'director'` で、委員長が解任された、委員長の最後の操作（なければ任期の始まり）から7日たった、または委員長の行がない（ないのは委員長が決まらなかった会期なので理事もいない）なら `director`
   - 最後の操作は、`moderation_logs.actor_user_id`、`solutions` の `status_actor_user_id`、`vote_reviews.decided_by` のうち、その人の任期の会期の中で一番新しい時刻。`moderation_logs` は課題と解決策の両方を記録しているので `moderation_logs` と `vote_reviews` の2つを見る
   - `staffRoleOf(db, userId, now)`：`user.role` があればそれ（運営を優先）、なければ `chairPowerOf`。`/kanri`（`staffOf`）、`kadai/[id]`、`kadai/[id]/kaiketsu` はこれを使う。`roleOf` を読むところは全部で3か所（確かめた）
   - `Role` の型に `chair`・`director` を足す（`staff.role` が `actor` と `decided_role` に入る）。`ROLES`（`user.role` の値）は変えない。`ja.unei.actors` に足す

5. **結果の確認**：`pendingReviews` と `decideReview` は `staff.role` をそのまま使う。関わりの判定（`involvedInBill`）は今のまま

6. **解任**（`signRecall`、`cancelRecallSignature`）：署名の行と確定の文を `db.batch` で一緒に流す。確定の文：`UPDATE chair_terms SET recalled_at = ? WHERE committee_id = ? AND session_key = ? AND role = 'chair' AND recalled_at IS NULL AND (SELECT count(*) FROM recall_signatures ...) >= 必要な人数`。必要な人数は押したときの今月の参加者（`sessionParticipants`。会期ごとに固定）から求める。委員長がいないか解任のあとは署名できない（409）。取り消しは解任の前だけ

7. **ページ** `/iinkai`（ログインなしで読める。国の制限は書き込みだけ）：
   - いまの委員長と理事の名前（なければ「今月は委員長がいません。運営が事務局を務めています」）。解任されていれば「解任されました」、代行中なら「理事が代行しています」
   - 選挙の区画：期間の案内、候補の名前（この会期の質疑と答弁の数を添える）、立候補と取り下げのボタン、投票のフォーム（自分の票が分かる。ほかの人の票は出さない）。候補の順は名前の順ではなく、毎回同じ順にならないよう `user_id` のハッシュで並べる（上に並ぶ人が有利にならないように）
   - 前の選挙の結果（委員長、理事、合計の票数）
   - 解任動議の区画：署名の人数と必要な人数、署名と取り消しのボタン
   - `noindex` は付けない（IF世界の条文を出さないので）。入口は採決の一覧（`/saiketsu`）と結果のページの「委員会」のリンク（全体のメニューは #85）

8. **受け付け**（`/iinkai` の `?/stand`・`?/withdraw`・`?/vote`・`?/recall`・`?/cancelRecall`）：Turnstile は `stand`・`vote`・`recall`。形が違えば 400

9. **文言**：`ja.chair`。`ja.unei.actors`、`ja.kanri` の説明を「運営と委員長」に直す
