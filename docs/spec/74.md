# 現実の改正の同期と、会期の終わりの取り込みと衝突（設計書）

Issue #74（#55 もここで閉じる）。マイグレーションがあり、条文の版に関わり、外部の API を呼ぶので Careful。仕様の正は [docs/spec.md](../spec.md) の「現実の改正の取り込み」。法令の版は [docs/spec/8.md](8.md)、IF世界は [docs/spec/72.md](72.md)。画面の案はない（`SpLaw`・`PcLaw` にそろえる）。画面の言葉は「現実の改正の取り込み」「ぶつかった条文」。

ユーザーと決めたこと（Issue #63 の決めたこと10・11。仕様書のドキュメントへの反映はユーザー側）。

- 現実の改正との衝突：v0.4 は「現実の改正の取り込み」のページに、ぶつかった条文を出すところまで。議題を自動で法案にすることはしない。IF世界側の条文を残す
- 取り込む範囲：その会期の終わりまでに施行された版だけ。公布済みで未施行の版は取り込まない

次のことは仕様書にないので、この Issue の受入基準で確かめる（STOP 1 で確認する）。

- A. **同期は追記だけ**：既存の版と内部IDを変えない。変えるのは、版の状態（施行予定 → 施行済み）、前の行を閉じること（`to_revision_id`）、法令の題名だけ。**既存の施行予定の版より前に新しい版が割り込むときは、その法令の同期を止めてログに出す**（版の順を変えると内部IDの追跡が壊れるため。人が直す）。API から版が消えても消さない
- B. **同期を動かす場所**：毎日の Cron で、会期の処理より先に。法令ごとに失敗を受け止め、同期の失敗は会期の処理を止めない。`EGOV_SYNC` が `1` のときだけ呼ぶ（テストのサーバーから API を呼ばない）
- C. **取り込みは現実の版を指すだけ**：IF世界の版と同じ番号の列に「ここから基にする現実の版が変わる」行を足す。IF世界で変えた条は法案の変更点を上に重ねるので、自然に IF世界側が残る
- D. **衝突**：現実で変わった条を IF世界でも変えていれば、ぶつかった条文として記録する。現実で足した条の番号が IF世界で足した番号と同じときも衝突で、IF世界の条を残す
- E. **#55（基にしたあとで現実の版が変わった下書き）**：IF世界の可決と同じ扱いにする（docs/spec/72.md の B2・B4）。取り込みで変わった条に触れる下書きは、いまの条文を出して確かめ、確かめるまで保存と発議を断る。可決までいった法案は要調整。これで #55 を閉じる
- F. **ページ**：`/if/hourei/<番号>/torikomi` に、法令ごとの取り込みの一覧（施行日、改正した法律、変わった条、ぶつかった条文は現実の条文と IF世界の条文を並べる）。IF世界の法令ページから入る。ぶつかった条に印を付ける
- G. **附則と別表**は今までどおり取り込まない。**施行予定の版の中身が後から変わった場合**は追わない（同じ版の番号の中身は変わらないとみなす）。全文検索は現実の新しい行も足す（IF世界の条文は検索しない。今までどおり）

## 目的

現実の改正を毎日取り込み、会期の終わりに IF世界へ反映し、ぶつかった条文を見られるようにする。

## 範囲

- 入れる：`src/lib/egov/`（API の呼び出し）、追記の同期、取り込み、衝突の記録、取り込みの一覧のページ、法案の基にする版との比べ（#55）
- 入れない：議題を自動で法案にすること（決定のとおり）、衝突の解消の画面（法案で直す）、2017年より前の履歴、公開ミラー、新法の同期（IF世界だけのもの）

## 表

`drizzle/0018_*.sql`。新しい表だけで、既存の表は変えない。

| 表 | 列 | 決まり |
| --- | --- | --- |
| `if_imports` | `law_id`（`laws` への外部キー）、`seq`（`if_revisions` と同じ番号の列）、`revision_id`（`law_revisions` への外部キー）、`session_key`、`created_at` | 主キー（`law_id`, `seq`）。UNIQUE（`law_id`, `revision_id`） |
| `if_import_articles` | `law_id`、`seq`、`provision_id`、`num`、`conflict`（0・1）、`real_body`（取り込んだ版の条文の文字。消えた条は NULL）、`if_body`（そのときの IF世界の条文の文字。衝突のときだけ）、`bill_id`（IF世界で最後に変えた法案。衝突のときだけ） | 主キー（`law_id`, `seq`, `provision_id`）。`if_imports` への外部キー。**当時の条文を写す**（あとで IF世界が変わっても、当時ぶつかった内容を読めるように） |

`if_revisions` と `if_imports` の `seq` は法令ごとに1つの列で、`MAX` は両方の表を見る。別の表なので UNIQUE は効かないが、同じ法令の反映と取り込みは同じ会期の処理の中で順に走る。

## 決めたこと

1. **API**（`src/lib/egov/client.ts`）：`https://laws.e-gov.go.jp/api/2/law_revisions/<法令>` と `.../law_data/<版>`。形はテストデータと同じ（手元で1回確かめた）。`fetch` を引数で受け取り、テストはテストデータを渡す。応答の形が違えば例外。1回の Cron の問い合わせは「対象の法令の数 + 新しい版の数」

2. **追記の履歴**（`extendHistory(start, revisions, { nextId })`。`src/lib/domain/law/history.ts`）：`buildHistory` の中身を共有し、いまの最後の版の木と内部IDを起点にする。**同じ版の列を一度に作った場合と同じ行になる**ことをテストで確かめる（テストデータの全部の法令の全部の位置で分けて比べる）。戻り値に新しい行のほか、閉じる行（`provisionId`・`toRevisionId`）を含める

3. **同期**（`syncLaw(db, lawId, fetchJson)`。`src/lib/server/law-sync.ts`）
   1. 分岐を固定する（`ifBranchOf`。現実の版が進む前に）
   2. 版の一覧を読み、今の DB の版と比べる。割り込みなら止める（決めたことA）
   3. 状態の変わった版の `status` を更新する。施行済みの最新の版から題名を更新する
   4. 新しい版を古い順に1つずつ読み、`extendHistory` して、**1つの版を1つの `db.batch`** で入れる（版 → 内部ID → 行 → 検索の行 → 前の行を閉じる）。途中で失敗しても、次の日は入っていない版から続く
   - 内部IDと行の番号は DB の `MAX + 1` から。D1 の値の上限に合わせて文を分ける

4. **Cron**（`scheduled`）：`EGOV_SYNC === '1'` なら対象の法令を同期し、そのあと `runSessionEnd`。同期の失敗はログに出して続け、最後に投げ直す。`wrangler.jsonc` の `vars` に `EGOV_SYNC: "1"`。`scripts/preview-test.ts` は `0` で上書きする

5. **取り込み**（`importReal(db, session, now)`。`if-world.ts`）：`settleSession` の `applySession` のあと。その会期の結果がすべて入っていないときは走らない（今の `return` のあと）
   - 対象：委員会の対象の法令で、`status = 'enforced'`、施行日がその会期の終わりより前、`seq` がいま基にしている現実の版より大きい版。**1回の問い合わせで求める**（読むたびに走るので）
   - 版ごとに古い順に：前の版と条を比べ（`changedArticles`。純粋な関数）、変わった条について IF世界で変えているかを見て、`if_imports` と `if_import_articles` を `db.batch` で入れる。UNIQUE があるので、何度走っても同じ。廃止された法令は取り込まない

6. **IF世界の条を読む**（`ifArticles`）：`seq` 以下の最後の `if_imports` の版を基にする（なければ分岐した版）。その上に法案の変更点を重ねる。**同じ番号の条が2つになったら IF世界で変えた条を残す**（決めたことD。現実で番号がずれたときも同じ）。IF世界の版の番号（`ifHeadOf`）は両方の表の最大

7. **基にした版との比べ**（`touching`・`staleArticles`・`conflictOf`）：`base_if_seq` より後の `if_import_articles` の条も「変わった条」に足す。これで書く画面の確かめ、発議の確かめ、要調整がそのまま働く（決めたことE）。文言の「基にしたあとで変わりました」もそのまま

8. **ページ** `/if/hourei/<番号>/torikomi`：帯、「架空の法令」、`noindex`、ログインは要らない。新しい順に50件ごと。`if-` の新法は 404。IF世界の法令ページに「現実の改正の取り込み」のリンクと、ぶつかった条に「現実の改正とぶつかっています」を出す（いま基にしている版までの `conflict` の条）

9. **画面のテストのデータ**：テストのサーバーで API を呼ばず、別のプロセスから D1 を開けない（Issue #17）ので、テストのサーバーだけの `POST /test-import`（`isTestServer` でないと 404）で、対象の委員会の外の法令を作り、実際の `extendHistory` と `importReal` を通す。共有の3法に触らない。そのため `importReal` は法令を引数で絞れる

10. **文言**：`ja.torikomi`。「リベース」「同期」「ブランチ」を画面に出さない
