# 現実の改正の同期と、会期の終わりの取り込みと衝突（設計書）

Issue #74（#55 もここで閉じる）。マイグレーションがあり、条文の版に関わり、外部の API を呼ぶので Careful。仕様の正は [docs/spec.md](../spec.md) の「現実の改正の取り込み」。法令の版は [docs/spec/8.md](8.md)、IF世界は [docs/spec/72.md](72.md)。画面の案はない（`SpLaw`・`PcLaw` にそろえる）。画面の言葉は「現実の改正の取り込み」「ぶつかった条文」。

ユーザーと決めたこと（Issue #63 の決めたこと10・11。仕様書のドキュメントへの反映はユーザー側）。

- 現実の改正との衝突：v0.4 は「現実の改正の取り込み」のページに、ぶつかった条文を出すところまで。議題を自動で法案にすることはしない。IF世界側の条文を残す
- 取り込む範囲：その会期の終わりまでに施行された版だけ。公布済みで未施行の版は取り込まない

次のことは仕様書にないので、この Issue の受入基準で確かめる（STOP 1 で確認する）。

- A. **同期は、施行済みの部分は追記だけ、施行予定の部分は作り直す**：施行済みの版と内部IDは変えない。施行予定の版は法案からも修正案からも指されないので、API の一覧と違えば消して作り直す。公布と施行の順が逆の改正（あとで公布された改正が先に施行される）は普通に起こる（テストデータの52版のうち14版）。このとき e-Gov 側でも後ろの版の中身が変わるので、作り直すのが正しい。**施行済みの部分が API と食い違ったら**（施行済みの版より前に新しい版が来る、施行済みの版が消える、施行予定に戻る）その法令の同期を止めてログに出し、Cron を失敗にする。人が直す
- B. **同期を動かす場所**：毎日の Cron で、会期の処理より先に。法令ごとに失敗を受け止め、同期の失敗は会期の処理を止めない。`EGOV_SYNC` が `1` のときだけ呼ぶ（既定は `0`。本番の設定で `1` にする）
- C. **取り込みは現実の版を指すだけ**：IF世界の版と同じ番号の列に「ここから基にする現実の版が変わる」行を足す。IF世界で変えた条は法案の変更点を上に重ねるので、自然に IF世界側が残る
- D. **衝突**（どれも IF世界の条を残し、ぶつかった条文として記録する）
  - 現実で変わった条（本文の変更、番号だけの変更、削除）を IF世界でも変えている。IF世界の条は IF世界の番号のまま残し、現実の番号に追いかけない
  - 現実の条（追加、繰り下げ）の番号に、IF世界で変えたか足した別の条がある。現実の条はその番号では読めなくなる
  - IF世界で変えていない条は現実に従う。番号だけの変更も追いかける。両方で削除した条は衝突にしない
- E. **#55（基にしたあとで現実の版が変わった下書き）**：IF世界の可決と同じ扱いにする（docs/spec/72.md の B2・B4）。取り込みで変わった条に触れる下書きは、いまの条文を出して確かめ、確かめるまで保存と発議を断る。可決までいった法案は要調整。これで #55 を閉じる
- F. **ページ**：`/if/hourei/<番号>/torikomi` に、法令ごとの取り込みの一覧（施行日、改正した法律、変わった条、ぶつかった条文は現実の条文と IF世界の条文を並べる）。IF世界の法令ページから入る。ぶつかった条に印を付ける。その条をあとで IF世界の法案が変えたら印は消える（一覧には当時の記録として残る）
- G. **附則と別表**は今までどおり取り込まない。全文検索は現実の新しい行も足す（IF世界の条文は検索しない。今までどおり）。**現実の法令の廃止は扱わない**：API が廃止を返したら（`repeal_status` が `None` でない）、その法令の同期を止める。対象3法で起きれば仕様を決め直す。法令の題名は1つで、現実の最新に合わせる（IF世界の画面も同じ題名）

## 目的

現実の改正を毎日取り込み、会期の終わりに IF世界へ反映し、ぶつかった条文を見られるようにする。

## 範囲

- 入れる：`src/lib/egov/`（API の呼び出し）、同期、取り込み、衝突の記録、取り込みの一覧のページ、法案の基にする版との比べ（#55）
- 入れない：議題を自動で法案にすること（決定のとおり）、衝突の解消の画面（法案で直す）、2017年より前の履歴、公開ミラー、新法の同期（IF世界だけのもの）

## 表

`drizzle/0018_*.sql`。新しい表だけで、既存の表は変えない。

| 表 | 列 | 決まり |
| --- | --- | --- |
| `if_imports` | `law_id`（`laws` への外部キー）、`seq`（`if_revisions` と同じ番号の列）、`revision_id`（`law_revisions` への外部キー）、`session_key`（`if_revisions` と同じ形）、`created_at` | 主キー（`law_id`, `seq`）。UNIQUE（`law_id`, `revision_id`） |
| `if_import_articles` | `law_id`、`revision_id`、`provision_id`、`num`（現実の番号。なくなった条は前の番号）、`change`（`amended`・`renumbered`・`added`・`removed`）、`conflict`（0・1）、`real_body`、`if_body`、`bill_id`（`bills` への外部キー） | 主キー（`law_id`, `revision_id`, `provision_id`）。`if_imports` の UNIQUE への外部キー。`real_body`・`if_body`・`bill_id` は衝突のときだけ入れる。**当時の条文を写す**（あとで IF世界が変わっても、当時の内容を読めるように）。`real_body` が NULL は現実でなくなった条、`if_body` が NULL は IF世界で削除した条 |

**番号の採番**：`seq` は法令ごとに `if_revisions` と `if_imports` で1つの列にする。どちらの行も「両方の表の `MAX + 1` を求めて入れる」1つの文で入れる（`applyBill` の文も両方を見るように変える）。D1 は書き込みを順に処理するので、番号は重ならない。

## 決めたこと

1. **API**（`src/lib/egov/client.ts`）：`https://laws.e-gov.go.jp/api/2/law_revisions/<法令>` と `.../law_data/<版>`。形はテストデータと同じ（手元で1回確かめた）。`fetchJson` を引数で受け取り、テストはテストデータを渡す。版の番号は `encodeURIComponent` を通す。1回の呼び出しは10秒まで（`AbortSignal.timeout`）。応答の形が違う、知らない状態（今受け付けるのは `CurrentEnforced`・`PreviousEnforced`・`UnEnforced`）、施行日の形が違う、`repeal_status` が `None` でないときは例外

2. **追記の履歴**（`extendHistory(start, revisions, { nextId })`。`src/lib/domain/law/history.ts`）：`buildHistory` の中身を共有し、起点の版の木と内部IDから続ける。`start` は **DB の行の形**（`provisionsAt` の戻りと同じ）から組み立てる。**同じ版の列を一度に作った場合と同じ行になる**ことをテストで確かめる（`buildHistory` の結果のうち起点までの行から `start` を作り、テストデータの全部の法令の全部の位置で分けて比べる）。戻り値に新しい行のほか、閉じる行（`provisionId`・`toRevisionId`）を含める

3. **同期**（`syncLaw(db, lawId, fetchJson)`。`src/lib/server/law-sync.ts`）
   1. 分岐を固定する（`ifBranchOf`。現実の版が進む前に）
   2. 版の一覧を読み、古い順に並べる。DB の先頭の版より前は比べない（2017年より前）
   3. **DB の施行済みの版の列が、一覧の同じ位置に同じ順で、施行済みのまま並ぶ**ことを確かめる。違えば止める（決めたことA）
   4. それより後を「作るべき末尾」とする。DB の施行予定の版と、版の番号と状態の列が同じなら何もしない。題名だけ違えば題名を直す
   5. 違えば、末尾の版の中身を**先に全部読む**（読めなければ DB に触らない）。`extendHistory` を施行済みの最後の版から走らせる
   6. **1つの法令を1つの `db.batch`** で入れ替える：古い末尾の検索の行 → 行（`from_revision_id` が末尾）→ 閉じた印を戻す（`to_revision_id` が末尾なら NULL）→ 末尾だけの内部ID → 古い末尾の版 → 新しい版 → 内部ID → 行 → 検索の行 → 閉じる → 題名。途中で失敗すれば何も変わらず、次の日にやり直す
   - 施行予定から施行済みになった版は、このとき読み直した中身で確定する。だから施行済みの中身は、施行された時点の e-Gov と同じになる
   - 内部IDと行の番号は DB の `MAX + 1` から。D1 の値の上限に合わせて文を分ける
   - 末尾だけの内部ID（末尾の版で足された条・項・号）は消して作り直すので番号が変わる。`bill_changes`・`amendments`・`if_added_articles` が指すのは施行済みの版の条と IF世界で足した条だけで、末尾だけの条は指さない

4. **Cron**（`scheduled`）：`EGOV_SYNC === '1'` なら `laws` の全部の法令を同期し、そのあと `runSessionEnd`。同期の失敗はログに出して続け、最後に投げ直す。同期全体は60秒まで（超えたら残りの法令は次の日）。`wrangler.jsonc` の `vars` は `EGOV_SYNC: "0"`。本番の設定で `1` にする（手作業）

5. **取り込み**（`importReal(db, session, now, lawId?)`。`if-world.ts`）：**Cron の `runSessionEnd` の最後にだけ走る。読むときの処理では走らない**（同期のあとに必ず走り、同時に2つ走らず、読むたびの問い合わせも増えない）。その会期の反映まで終わったときだけ走る。`settleSession` は反映まで終えたかを返す
   - 対象：`laws` の全部の法令のうち、`status = 'enforced'`、**施行日がその会期の最終日（日本時間の `endsAt` の前の日付）以下**、`seq` がいま基にしている現実の版より大きい版。1回の問い合わせで求める。IF世界で廃止された法令は取り込まない
   - 版ごとに古い順に：**いま IF世界が基にしている現実の版**と比べ（`changedArticles`。純粋な関数）、変わった条について衝突を判定して（決めたことD）、`if_imports` と `if_import_articles` を `db.batch` で入れる。UNIQUE があるので、何度走っても同じ
   - 同期が遅れて（e-Gov の状態の更新が遅れて）次の会期の Cron まで施行済みにならなかった版は、次の会期の取り込みに入る。`session_key` は**取り込んだ会期**。順はずれない
   - その会期に確認中で反映されなかった法案は、取り込みのあとで反映されるときに、基にした版との比べ（決めたこと7）で判定される
   - 同じ時刻に読むときの反映と取り込みが重なると、衝突の記録だけ抜けることがある。IF世界の条が残る結果は変わらないので、この Issue では排他を作らない

6. **IF世界の条を読む**（`ifArticles`）：`seq` 以下の最後の `if_imports` の版を基にする（なければ分岐した版）。その上に法案の変更点を内部IDで重ねる。**同じ番号の条が2つになったら IF世界で変えた条を残す**（決めたことDの2つ目）。IF世界の版の番号（`ifHeadOf`）は両方の表の最大。目次と見出しの帯も同じ版の `headings` を読む。番号が飛ぶ（取り込みの分）ことに頼るものはない。IF世界の版の一覧のページはなく、`seq` は比べにだけ使う

7. **基にした版との比べ**（`touching`・`staleArticles`・`conflictOf`）：`base_if_seq` より後の `if_import_articles` の条も「変わった条」に足す。**内部IDか番号のどちらかが同じ**なら触れている（今の `touching` と同じ。足す条は番号で比べる。`src/lib/server/if-world.ts` の `touching`）。`staleArticles` は現実でなくなった条も、中身なしで返す（返さないと発議を断れない）。これで書く画面の確かめ、発議の確かめ、要調整がそのまま働く（決めたことE）。文言の「基にしたあとで変わりました」もそのまま

8. **ページ** `/if/hourei/<番号>/torikomi`：帯、「架空の法令」、`noindex`、ログインは要らない。取り込み（版）を新しい順に50件ごと。変わった条は番号と変わり方だけ（大きな改正でも読み込みが増えないように、本文を持つのは衝突の行だけ）。`real_body` が NULL なら「現実の法律ではなくなりました」、`if_body` が NULL なら「IF世界では削除されています」。`if-` の新法とない番号は 404。IF世界の法令ページに「現実の改正の取り込み」のリンクと、ぶつかった条に「現実の改正とぶつかっています」を出す。印を出すのは `conflict` の行のうち、その取り込みより後にその条（内部IDか番号）を変えた IF世界の版がないもの

9. **画面のテストのデータ**：テストのサーバーで API を呼ばず、別のプロセスから D1 を開けない（Issue #17）ので、テストのサーバーだけの `POST /test-import`（`isTestServer` でないと 404）で、対象の委員会の外の法令を作り、実際の `extendHistory` と `importReal` を通す。共有の3法に触らない

10. **文言**：`ja.torikomi`。「リベース」「同期」「ブランチ」を画面に出さない
