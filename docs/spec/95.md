# 現実の改正の取り込みと衝突、取り込みの一覧のページ（設計書）

Issue #95（#55 もここで閉じる）。マイグレーションがあり、IF世界の条文の読み方と会期の処理を変えるので Careful。仕様の正は [docs/spec.md](../spec.md) の「現実の改正の取り込み」。同期は [docs/spec/74.md](74.md)、IF世界は [docs/spec/72.md](72.md)。画面の案はない（`SpLaw`・`PcLaw` にそろえる）。画面の言葉は「現実の改正の取り込み」「ぶつかった条文」。

ユーザーと決めたこと（Issue #63 の決めたこと10・11）。

- 現実の改正との衝突：v0.4 は「現実の改正の取り込み」のページに、ぶつかった条文を出すところまで。議題を自動で法案にすることはしない。IF世界側の条文を残す
- 取り込む範囲：その会期の終わりまでに施行された版だけ。公布済みで未施行の版は取り込まない

仕様のとおりにすること：会期の終わりの順は「採決の締切 → 可決法案の反映 → 現実の改正の反映 → 衝突の検出」。**会期中に IF世界の条文は変わらない**（例外は2つ。会期の処理か取り込みの失敗で遅れた法令の、次の日以降の取り込みと、確認中だった法案があとで確定したときの反映）。

次のことは仕様書に定めがないので、この Issue の受入基準で確かめる（STOP 1 で確認する）。

- A. **取り込みは現実の版を指すだけ**：IF世界の版と同じ番号の列に「ここから基にする現実の版が変わる」行を足す。IF世界で変えた条は法案の変更点を上に重ねるので、自然に IF世界側が残る。**取り込みは法令ごとに1つの会期に1回**（Cron は毎日走るが、終わった記録のある法令は次の会期まで走らない。失敗した法令のやり直しで、ほかの法令が会期の途中で変わらない）
- B. **衝突**（どれも IF世界の条を残し、ぶつかった条文として記録する）
  - 現実で変わった条（本文の変更、番号だけの変更、削除）を IF世界でも変えている。IF世界の条は IF世界の番号のまま残し、現実の番号を追いかけない
  - 現実の条（追加、繰り下げ、隠れたままの本文の変更）の番号に、IF世界で変えたか足した別の条がある。現実の条はその番号では読めなくなる
  - IF世界で変えていない条は現実に従う。番号だけの変更も追いかける
  - **IF世界の条と現実の条の中身が同じなら衝突にしない**。比べるのは見出しと `articleBodyText`。現実の条が残っていて番号が違えば衝突にする（番号がずれたまま記録が残らないのを防ぐ）。IF世界の削除、現実の「削除」の本文、現実でなくなった条はどれも「削除」として同じに扱う。表記が少しでも違えば衝突になる（IF世界の条が残るので安全な側）
  - **似ていなくて内部IDが変わった条**（`unconfirmed`。「第5条 削除」もこの形）は、閉じた条と同じ番号の新しい条を1つの本文の変更として扱う。現実の法律からなくなったとはしない
- C. **#55（基にしたあとで現実の版が変わった下書き）**：IF世界の可決と同じ扱いにする（docs/spec/72.md の B2・B4）。取り込みで変わった条に触れる下書きは、いまの条文を出して確かめ、確かめるまで保存と発議を断る。可決までいった法案は要調整。**番号が変わった条の下書きは同じ内部IDの条を指したまま**で、書く画面にはいまの番号で出す。`unconfirmed` の条は新しい条の番号で出す。条がなくなっていれば、その行をエラーにして選び直してもらう。これで #55 を閉じる
- D. **ページ**：`/if/hourei/<番号>/torikomi` に、法令ごとの取り込みの一覧（施行日、改正した法律、変わった条、ぶつかった条文は現実の条文と IF世界の条文を番号つきで並べる）。IF世界の法令ページから入る。ぶつかった条に印を付ける。その条をあとで IF世界の法案が変えたら印は消える（一覧には当時の記録として残る）
- E. **固定の版を広げる**：同期（#74）の固定の版を「分岐した版と取り込んだ版のうち最後の版」にする

## 目的

会期の終わりに、施行された現実の改正を IF世界へ反映し、ぶつかった条文を見られるようにする。

## 範囲

- 入れる：取り込み、衝突の記録、IF世界の条の読み方、法案の基にする版との比べ（#55）、書く画面の番号、取り込みの一覧のページ、固定の版
- 入れない：議題を自動で法案にすること（決定のとおり）、衝突の解消の画面（法案で直す）、衝突の通知（#78）、公開ミラー

## 決めたこと

1. **取り込み**（`importReal(db, session, now, lawId?)`。`if-world.ts`）：**Cron の `runSessionEnd` の最後にだけ走る。読むときの処理では走らない**。その会期の反映まで終わったときだけ走る（`settleSession` は反映まで終えたかを返す）。`if_import_runs` にその会期の行のない法令だけを処理する（全部あれば1回の問い合わせで終わる）
   - 対象：`laws` の全部の法令（新法は `if_laws` にあり `laws` に入らない）。その法令の**基の版の次から、`status = 'enforced'` で施行日がその会期の最終日（`endsAt` の1ミリ秒前の、日本時間の日付）以下の版が続くところまで**。条件を満たさない版が途中にあれば、その後ろは施行済みでも取り込まない（途中を飛ばすと固定の版より前に施行予定の版が残る）。IF世界で廃止された法令は取り込まない
   - 版ごとに古い順に：**いま IF世界が基にしている現実の版**と比べ（`changedArticles`。純粋な関数。`src/lib/domain/law/`。`unconfirmed` もここで1つにまとめる）、変わった条について衝突を判定して（決定B）、`if_imports` と `if_import_articles` を `db.batch` で入れる（値つきの `db.run` を入れない。D1 の1文の値の上限に合わせて文を分ける）。UNIQUE があるので、途中で失敗してやり直しても同じ
   - 法令ごとに失敗を受け止める。終わった法令は `if_import_runs` を入れる。失敗した法令があれば Cron を失敗にする
   - e-Gov の状態の更新が遅れて、その法令の取り込みのときに施行済みになっていなかった版は、**次の会期の取り込みに入る**。`session_key` は取り込んだ会期。会期の途中では入らない
   - その会期に確認中で反映されなかった法案は、取り込みのあとで反映されるときに、基にした版との比べ（決めたこと3）で判定される
   - 同じ時刻に読むときの反映と取り込みが重なると、衝突の記録だけ抜けることがある。IF世界の条が残る結果は変わらないので、この Issue では排他を作らない。読んだあとに同期が本文だけ作り直した場合も排他を作らない（同期のタイマーを Cron の時刻から離す。デプロイの Issue）
   - `lawId` を渡すと、その法令だけを処理し、`if_import_runs` を見ず入れない（画面のテストのデータ用。決めたこと7）

2. **IF世界の条を読む**（`ifArticles`）：`seq` 以下の最後の `if_imports` の版を基にする（なければ分岐した版）。その上に法案の変更点を内部IDで重ねる。**法案が変えた条は、削除も改正も法案の番号（`r.num`）で、基の版になくても残す**（現実でなくなった条）。並びは今までどおり番号の順で、見出しの帯は基の版の見出しの木にない番号なら前の帯が続く（`headingPaths` の今の扱い）。**同じ番号の条が2つになったら IF世界で変えた条を残す**（決定Bの2つ目）。IF世界で変えた条を現実が別の内部IDにしたら、現実の新しい条は同じ条なので出さない（そのあと番号が変わっても）。衝突の判定も内部IDの変わる前までさかのぼる。IF世界の版の番号（`ifHeadOf`）は両方の表の最大。目次と見出しの帯も同じ版の `headings` を読む。IF世界の版の一覧のページはなく、`seq` は比べにだけ使うので、番号が飛んでも困らない

3. **基にした版との比べ**（`touching`・`staleArticles`・`conflictOf`）：`base_if_seq` より後の `if_import_articles` の条も「変わった条」に足す。取り込みの行は**内部IDで比べ**、足す条だけ番号で比べる（取り込みの行の番号は現実の番号なので、番号で比べると別の条に当たる。法案の行は今の `touching` のまま）。`unconfirmed` で閉じた条は `closed_provision_id` でも当たる（続けて変わったときは順にたどる）。`staleArticles` は、内部IDがある行は内部ID（閉じた条は新しい条）でいまの条を選び、なければ番号で選び（隠れた現実の条の番号には IF世界の条がある。なくなった条は番号で選ばない）、どちらもなければ中身なしで返す（返さないと発議を断れない）。文言の「基にしたあとで変わりました」はそのまま

4. **書く画面**（`houan/[id]/kaku`）：保存済みの行の番号は、`provisionId` からいまの IF世界の番号を求めて出す。内部IDで引けなければ取り込みの記録（`closed_provision_id`）を**いまの条に着くまでたどり**、着けばその番号で出す。それもなく条がなくなっていれば番号を空にして、その行に「この条はなくなりました。選び直してください」を出す。保存のときに番号から内部IDを引き直す今の処理は変えない。**修正案は変えない**：修正案は本案の版に結び付き、本案の基にした版（固定の版までなので残る）の条と比べるので、取り込みをまたいでも変わらない。本案は可決のときに要調整になり、直すと版が変わって修正案の更新が要る（今までどおり）

5. **ページ** `/if/hourei/<番号>/torikomi`：帯、「架空の法令」、`noindex`、ログインは要らない。取り込み（版）を新しい順に50件ごと。変わった条は番号と変わり方だけ（大きな改正でも読み込みが増えないように、本文を持つのは衝突の行だけ）。変わった条が0件の取り込み（附則だけの改正）は「条文の変更はありません」。`real_body` が NULL なら「現実の法律ではなくなりました」、`if_body` が NULL なら「IF世界では削除されています」。`if-` の新法とない番号は 404。`?page=` の形が違えば、ほかの一覧と同じ（`parsePage` が null なら 404）。番号が変わった条は「第5条→第6条」と出す。IF世界の法令ページに「現実の改正の取り込み」のリンクと、ぶつかった条に「現実の改正とぶつかっています」を出す。印を出すのは `conflict` の行のうち、その取り込みより後にその条（内部IDか `if_num`）を変えた IF世界の版がないもの。隠れた現実の条があとで別の番号に移っても、印は法案で直すまで残る

6. **固定の版**（`pinnedRevision(db, lawId)`。`if-world.ts`）：`if_imports.seq` が最大の行の版。なければ分岐した版。`syncLaw` はこれを使う。取り込みとすれ違うと、同期の batch は固定の版を消そうとして外部キーで失敗するので壊れない

7. **画面のテストのデータ**：テストのサーバーで API を呼ばず、別のプロセスから D1 を開けない（Issue #17）ので、テストのサーバーだけの `POST /test-import`（`isTestServer` でないと 404）で、対象の委員会の外の法令と、その法令を変えて可決した法案を作り、実際の `extendHistory` と `importReal` を通す。共有の3法に触らない

8. **文言**：`ja.torikomi`。「リベース」「同期」「ブランチ」を画面に出さない
