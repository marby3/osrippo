# 採決の表と、投票資格・定足数・可決・割り当てのルール（設計書）

Issue #65。マイグレーション（表の追加と `actions` の作り直し）を足すので Careful。仕様の正は [docs/spec.md](../spec.md) の「採決と投票の公正さ」と「発議要件と定足数は割合で決めます」。会期の区切りは `src/lib/domain/session.ts`（#44）、今月の参加者は [docs/spec/49.md](49.md)、法案の進みは [docs/spec/50.md](50.md)。

仕様書にない次のことは、ユーザーと決めた（Issue #63 の決めたこと。仕様書のドキュメントへの反映はユーザー側）。

- 定足数は、有効票を棄権も含めて数える。母数は付託先の会期の今月の参加者で、その 20% を切り上げ、最低10人（決めたこと1）
- 有効票で、賛成が反対より多ければ可決。棄権は母数に入れない。同数は否決（決めたこと2）
- 投票資格は、会期が始まる前日の終わりまでに登録し、それまでに今月の参加者に数える行動が1回以上ある人（決めたこと3）
- 割り当ては、委員会が1つのあいだは所属を作らず、審議中の法案からくじで3本（足りなければあるだけ）。自分が提出・賛同した法案は除く。採決の期間に、採決の一覧か投票の画面を初めて開いたときに固定する（決めたこと4）
- 票は締切まで変えられ、最後の票を数える。有効票か参考票かは締切の時点で判定する（決めたこと5）
- 今月の参加者に数える行動に、質疑・答弁・補足・評価・修正案・投票を足す

## 目的

投票の画面（#70）と会期の終わりの処理（#71）が使う、表とルールを作る。

## 範囲

- 入れる：表（票、割り当て）、`actions` の種類の追加、今月の参加者に数える行動の追加、定足数と可決の判定、投票資格、割り当てのくじと固定、票を入れる関数、票の数え方
- 入れない：画面とフォームの受け付け（ログイン・国・締め出し・Turnstile・レート制限の確かめは #70）、結果の記録と法案の状態の変更（#71）、修正案の先議の票（#68）、異常の検知（#73）、票の履歴の表示と削除（結果を記録したあとの Issue）

## 表

`drizzle/0011_*.sql`（`drizzle-kit generate`）。generate のあとに SQL を読み、次を確かめる。

- 作り直す既存の表は `actions` だけ。`actions` にはトリガーがなく、`actions` を参照する外部キーもない（`schema.ts` で確かめた）ので、作り直しで消えるものはない
- 索引（`actions_user`・`actions_ip`・`actions_target`）が作り直されている
- 既存の行が消えない（`INSERT … SELECT` で移している）

| 表 | 列 | 備考 |
| --- | --- | --- |
| `votes` | `session_key`（`Session.key`）、`bill_id`（`bills` への外部キー）、`user_id`（`user` への外部キー）、`choice`（`yes`・`no`・`abstain`。CHECK）、`created_at`、`updated_at` | 主キー（`session_key`, `bill_id`, `user_id`）。索引：`user_id`。票は最後の1つだけを持つ |
| `vote_assignments` | `session_key`、`user_id`（`user` への外部キー）、`seq`（0〜2。CHECK）、`bill_id`（`bills` への外部キー）、`created_at` | 主キー（`session_key`, `user_id`, `seq`）。同じ `session_key`・`user_id` に同じ `bill_id` は1つ（UNIQUE） |

`actions` の `kind` に次を足す。#66〜#70 で使う種類をまとめて足し、Issue ごとに表を作り直さないようにする。

- `question_post`・`answer_post`・`supplement_post`（#66）
- `stance_set`（#66）
- `evaluation_add`・`evaluation_remove`（#67）
- `amendment_post`・`amendment_accept`・`amendment_support_add`・`amendment_support_remove`（#68）
- `vote_cast`（#70）

## 決めたこと

1. **票に会期を持たせる**：同じ法案が要調整で次の会期にもう一度採決されるので（Issue #63 決めたこと8）、主キーに `session_key` を入れる。付託先の会期は今 `proposed_at` から求めている（`referralSession`）が、要調整の法案はそれと違う会期になる。持ち方は #72 で決める
2. **今月の参加者に数える行動**（`PARTICIPANT_KINDS`）：今の8種類に `question_post`・`answer_post`・`supplement_post`・`evaluation_add`・`amendment_post`・`vote_cast` を足す。立場の変更（`stance_set`）、取り消し、修正案の取り込みと先議の賛同は、決めた行動に入らないので数えない
3. **定足数**（`quorumRequirement`。純粋な関数。`src/lib/domain/votes.ts`）：`max(10, ceil(今月の参加者 × 20 / 100))`。発議要件と同じく、小数を使わず整数で書く
   - 境界：50人で10人、51人で11人、100人で20人、101人で21人
   - 今月の参加者は、付託先の会期の `sessionParticipants`（#49）を使う。会期の始めに固定した数で、会期中の行動で変わらない
4. **可決の判定**（`billOutcome({ yes, no, abstain }, required)`。純粋な関数）：受け取るのは有効票の数
   - `yes + no + abstain < required` なら `lapsed`（廃案）
   - それ以外で `yes > no` なら `passed`（可決）
   - それ以外は `rejected`（否決）
5. **投票資格**（`isEligibleVoter(db, userId, registeredAt, session)`）：`registeredAt < session.startsAt` で、`actions` に `PARTICIPANT_KINDS` の行があり `created_at < session.startsAt`。`session` は付託先の会期。条件を組み立てる部分は `tallyVotes` と共通にする
   - 「前日の終わりまで」は、会期の始まりより前と同じ
   - 登録から7日の決まりは投票には足さない。名簿の基準日が同じ役目をし、登録の浅いアカウントの票は参考票として数える（仕様「会期の途中で作られたアカウントの票は参考票」）
   - 登録の時刻は `user.created_at`（本当の時刻）、行動の時刻は `actions.created_at`（`nowOf`）。どちらも書かれた時点の値なので、あとから変わらない。`actions` を消す機能と退会を入れるときに、前提を見直す（docs/spec/49.md 決めたこと3と同じ）
6. **その会期に採決する法案**（`billsInVote(db, session, previous)`）：`savedBill`、`status = 'proposed'`、`previous.deliberationAt ≤ proposed_at < session.deliberationAt`。`referralSession` と同じ結果になる（締切の前の発議はその会期、前の会期の締切からあとの発議はこの会期）。単体テストで一致を確かめる
7. **割り当てのくじ**（`drawAssignments(billIds, count, random)`。純粋な関数）：候補を Fisher-Yates で混ぜて先頭から `count` 本。`random` は `() => number` を受け取り、テストでは決まった値を渡す。本番は `Math.random`。一度固定すると引き直せず、結果を予測しても利益が小さいので、暗号の強さは要らない
8. **割り当ての固定**（`assignedBills(db, userId, session, previous, now, random)`）：その人の行があれば読む。なければ、その会期に採決する法案から、提出者か賛同者（`bill_supports` のどの版の行でも）である法案を除いてくじを引き、1文でまとめて `INSERT … ON CONFLICT DO NOTHING` で入れ、読み直す
   - 同時に開いても、1文は全部入るか全部入らないかなので、先に入った組だけが残る。主キーを `seq` にしているので、違う組を引いた2つ目の文は全部の行がぶつかる
   - 候補が0本なら行を入れない。候補は締切のあとは増えないので、開くたびに0本になる
   - 賛同の行は、取り消すと消える。古い版の行が残っている人は、賛同したことのある人として除く（中身は読んでいるので、くじの目的に合わない）
   - 採決の期間かどうかは呼ぶ側（#70）が確かめる
   - D1 の値の数の上限（1文に100個）に対して、3行で15個なので問題ない
9. **票を入れる**（`castVote(db, userId, session, previous, billId, choice, now, random)`）：入れたかを返す。受け取る値は呼ぶ側（#70）が確かめる
   - **先に割り当てを固定する**（`assignedBills` を呼ぶ）。画面を開かずにフォームへ直接送っても、割り当てを飛ばして有効票にならない。`vote_assignments` に行がないのは「候補が0本」のときだけになる
   - 票を入れるのは次の1文。その会期に採決する法案（決めたこと6と同じ条件）にしか入らないので、廃案（`status` は `proposed` のまま）や次の会期に付託される法案には入らない

   ```sql
   INSERT INTO votes (session_key, bill_id, user_id, choice, created_at, updated_at)
   SELECT ?, id, ?, ?, ?, ? FROM bills
   WHERE id = ? AND status = 'proposed' AND rev > 0 AND proposed_at >= ? AND proposed_at < ?
   ON CONFLICT (session_key, bill_id, user_id) DO UPDATE SET choice = excluded.choice, updated_at = excluded.updated_at
   RETURNING bill_id
   ```

   SQLite の `INSERT … SELECT … ON CONFLICT` は、`WHERE` がないと文の解釈があいまいになるので、`WHERE` を必ず付ける（上の形で満たす）
10. **票の数え方**（`tallyVotes(db, session, billId)`）：`{ counted: { yes, no, abstain }, reference: { yes, no, abstain } }` を返す。投票資格があり、その会期の割り当てのすべてに票を入れた人の票を有効票、それ以外を参考票にする。1文の集計で求める（投票者ごとに問い合わせない）

    ```sql
    SELECT v.choice,
      (u.created_at < :start
        AND EXISTS (SELECT 1 FROM actions a WHERE a.user_id = v.user_id AND a.kind IN (…) AND a.created_at < :start)
        AND NOT EXISTS (SELECT 1 FROM vote_assignments va WHERE va.session_key = v.session_key AND va.user_id = v.user_id
          AND NOT EXISTS (SELECT 1 FROM votes w WHERE w.session_key = va.session_key AND w.bill_id = va.bill_id AND w.user_id = va.user_id))
      ) AS counted,
      count(*) AS n
    FROM votes v JOIN user u ON u.id = v.user_id
    WHERE v.session_key = :session AND v.bill_id = :bill
    GROUP BY v.choice, counted
    ```

    - 列は別名を付けて書く（drizzle の `${table.col}` は表名なしの列名になり、副問い合わせの中の同じ名前の列を指す。#49 の Blocker）
    - 割り当ての行がない人は、候補が0本の人だけ（決めたこと9）で、割り当ての条件を満たす
    - 割り当ての条件は法案の状態を見ない。今のコードでは発議した法案の `status` は変わらず、#71 が結果を書いても数え方が変わらないようにするため。採決中に撤回できるようにするなら、#76 でこの条件を直す（撤回された法案を除く）。併合審査（#69）は法案の状態を変えない（Issue #63 決めたこと15）
    - 締切のあとに呼ぶと、締切の時点の判定になる。締切のあとは `castVote` を呼ばない（#70 が確かめる）ので、行は変わらない
11. **置き場所**：純粋な関数は `src/lib/domain/votes.ts`、DB に触れるものは `src/lib/server/votes.ts`

## テストの方針

単体テスト（node:sqlite にマイグレーションを流す）。受入基準ごとに1本。

- 基準1 表：既存のトリガーと全文検索の表が残り、`actions` の既存の行が移っている。新しい種類が入る
- 基準2 数える行動：足した6種類を数え、`stance_set` は数えない
- 基準3 `quorumRequirement` の境界
- 基準4 `billOutcome` の境界
- 基準5 `isEligibleVoter` の境界（登録と行動の時刻のちょうどと1ミリ秒前、数えない行動）
- 基準6 割り当て：3本、足りないとき、自分と賛同した法案を除く、固定、同時に開いたとき、`billsInVote` と `referralSession` の一致
- 基準7 `tallyVotes`：有効票と参考票、割り当ての未完了、最後の票、画面を通らずに入れた票、その会期に採決しない法案には入らないこと

新しい入力の受け口を作らない（`castVote` の値は #70 が確かめる）ので、信頼の境界のテストは足さない。
