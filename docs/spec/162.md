# 読める法律の取り込み（設計書）

Issue #162。受入基準と決めたことは Issue #198 の「#162」の節と、ユーザーの決定のコメントの4（2026-11-13）。法令の表と全文検索に表を足し、取り込みのバッチを足すので Careful（ROADMAP「モード」の、条文の内部IDと版のまわり）。ただし、いまある `laws`・`law_revisions`・`provisions`・`provision_versions` と全文検索の表は変えない。

## 目的

委員会の対象（遊べる法律）だけでなく、残りの法律も最新の版だけ読めるようにする。法律Wiki（#163〜#166）の土台にする。

## 範囲

- 入れる
  - 表：`readable_laws`、`readable_articles`、全文検索の `readable_search`
  - バッチ：`pnpm sync:readable`
  - 法令のページ `/hourei/[lawId]` で読める法律を出すこと
  - 画面のテストの D1 に、テストデータの読める法律を入れること
  - `docs/readable-laws.md`
- 入れない
  - 法律の一覧と検索の画面（#163）
  - 別名と条だけのページ（#164）
  - 自動リンク（#165）とリンク元（#166）
  - 本番の D1 につなぐ引数（本番の公開 #203）

## 表

マイグレーションは足すだけで、いまある表と行は変えない。

| 表 | 列 | 備考 |
| --- | --- | --- |
| `readable_laws` | `id`（e-Gov の law_id、主キー）、`title`、`title_kana`、`law_num`、`law_type`（`Act`・`Constitution`）、`category`（事項別分類の名前）、`abbrevs`（JSON、e-Gov の略称の配列。なければ `[]`）、`promulgation_date`、`last_amended`（施行済みの最新の版の施行日。改正がなければ NULL）、`revision_id`（取り込んだ版の law_revision_id）、`updated`（e-Gov の `updated`。次の取り込みで変わったかを見る）、`headings`（JSON、見出しの木）、`synced_at` | 遊べる法律の行も入れる（一覧と検索の材料）。遊べる法律の条文は `readable_articles` に入れない |
| `readable_articles` | `id`（整数、自動採番）、`law_id`（`readable_laws` への外部キー）、`seq`（法令の中の順）、`num`（e-Gov の形の条の番号）、`label`、`caption`、`paragraphs`（JSON、`Paragraph[]`） | 一意：（`law_id`, `num`）。内部IDは持たない（版の履歴がないため）。遊べる法律に上げるときは、全部の版を取り込み直し、この表の行は消す（#172） |
| `readable_search` | FTS5、`tokenize='trigram'`、`content='readable_articles'`、`content_rowid='id'`。索引に入れる列は見出しと本文をそろえた文字列 | 本文の写しを持たない（外部の本文の表）。入れ替えは、法令ごとに `'delete'` の命令で消してから入れる。2文字の言葉は探せない（trigram は3文字から） |

`readable_search` の索引に入れる文字列は、`readable_articles` に `search_text`（見出しと本文を `searchTexts` と同じ規則でそろえたもの）の列として持たせる。外部の本文の表は、索引の列と同じ名前の列を読むため。ここが本文の写しに近くなるが、2つ目の全文検索の索引（2文字ずつの組）は作らない。

## 決めたこと

1. **対象**（基準1）
   - e-Gov 法令API v2 の `GET /laws?law_type=Act&repeal_status=None` の全件（`limit` と `offset` で全部読む）と、`law_type=Constitution` の全件
   - `current_revision_status` が `CurrentEnforced` でないもの（未施行の版しかない法律）は入れない
   - 政令と府省令は入れない
2. **取り込みの流れ**（基準1・2）
   1. 一覧を読む。行ごとに形を確かめる（`src/lib/egov/` に `readLawList` を足す。応答は信頼の境界）
   2. 法令ごとに `readable_laws` を書く（入れるか、変えるか）
   3. 遊べる法律（`laws` にある法令）でなく、`updated` が保存した値と違う（または行がない）法令だけ、`/law_data/{revision_id}` を読んで条を作り直す。`parseLaw` と `parseHeadings` は、いまの取り込みと同じものを使う
   4. 条の作り直しは、法令ごとに次の3つを1つの `batch` にする。古い索引を消す、条を消して入れ直す、索引を入れる。D1 の1回の上限（1000文、1文100KB）を超える法令は、条を分けて入れる（索引は最後にまとめる）
   5. 一覧になくなった法令（廃止）は、`readable_laws` と条と索引を消す
   6. 1つの法令で失敗しても、ほかは続け、最後に終了コード1で終わる（`sync:laws` と同じ）
3. **e-Gov への負荷**：法令の本文は1件ずつ、1秒あけて読む。2回目からは変わった法令だけを読むので、ふつうは週に数十件
4. **法令のページ**（基準3）
   - `/hourei/[lawId]` は、`laws` にあれば、いまのとおり遊べる法律のページを出す
   - なく、`readable_laws` にあって条があれば、読める法律のページを出す
   - 読める法律のページに出すもの
     - 題名、法令番号、「読める法律（最新の版だけ）」の表示と最後の改正日
     - 見出しの帯と目次
     - 条文（ふりがなと法令用語の説明は、遊べる法律と同じ部品）
   - 読める法律のページに出さないもの
     - 改正の記録、比較へのリンク、条ごとの「N年変わっていない」（版の履歴がないため）
     - IF世界へのリンク
   - `/if/hourei/[読める法律の id]` は 404 のまま
5. **全文検索**：いまの `/kensaku` には、この Issue では読める法律を足さない（#163 で、法律の一覧の検索と一緒に足す）。この Issue では、索引が引けることだけを DB のテストで確かめる
6. **画面のテストの D1**：`pnpm db:reset` は、遊べる3法に加えて、テストデータの読める法律（民法の `129AC0000000089_20200401_501AC0000000034`）を入れる。一覧の応答は `tests/fixtures/egov/laws_list_*.json` に、e-Gov の形で小さく作る
7. **バッチの入口**：`scripts/sync-readable.ts`（`pnpm sync:readable`）。`--persist-to` は `sync:laws` と同じ。本番の D1 につなぐ引数は #203 で足す
8. **大きさの記録**（基準5）：手元の D1 に全件を取り込み、次を `docs/readable-laws.md` に書く。2GB を超えたら、索引に入れるのを見出しだけにする（`search_text` を見出しだけにする）
   - DB の大きさ
   - 表ごとの行数
   - 書き込んだ行数
   - 取り込みにかかった時間

## テストの方針

テストは受入基準ごとに1本で、e-Gov は呼ばない（`tests/fixtures/egov/`）。

- 基準1（DB のテスト）：テストデータの一覧と本文で取り込むと、次のようになる
  - 法令名・読み・略称・分類・法令番号・最後の改正日が入る
  - 民法の条が入り、`readable_search` で本文の3文字の言葉を引くと、その条が返る
  - 遊べる法律の条は入らない
  - 未施行だけの法律は入らない
- 基準2（DB のテスト）：同じ一覧で2回目を流すと、本文は1件も読まない。1件の `updated` を変えると、その1件だけ読む
- 基準3（画面のテスト、2幅）：`/hourei/129AC0000000089` に、題名、「読める法律（最新の版だけ）」、第1条の本文が出る。比較へのリンクは出ない
- 基準4：法令のページ・IF世界・同期のいまある画面のテストと DB のテストを流す（新しいテストは書かない）
