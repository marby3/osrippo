# 共同提出者（設計書）

Issue #76 のうち共同提出者。マイグレーションがあり、下書きを編集できる人と票の割り当てに関わるので Careful。撤回と統合案は共同提出者を前提にするので、別の Issue に分ける（STOP 1 で確認する）。決定は Issue #41 の決めたこと4「共同提出者と撤回は、統合案や修正案と一緒に v0.4 で扱う」。仕様は [docs/spec.md](../spec.md)「答弁できるのは提出者・共同提出者・賛同者」「発議後の撤回には提出者全員の同意が必要」「提出者どうしで統合案を共同提出できる」。画面の案はない（`SpBillSummary`・`PcBillSummary` にそろえる）。

**編集できる人**：仕様の「発議前は提出者と賛同者だけが編集できる」は、#41 の決めたこと4で「提出者1人だけ」に変えた。賛同者は今までどおり編集できず、共同提出者を足す。

次のことは仕様書に定めがないので、この Issue の受入基準で確かめる（STOP 1 で確認する）。

- A. **なり方は本人の申し出と提出者の承認**：下書きのページで本人が「共同提出者になりたいと申し出る」を押し、提出者が承認する。提出者から指名する形にしない（人を探す画面がなく、作ると名前の一覧ができる。賛同者の名前を出さない決まり（docs/spec/49.md）にも反する）。招待のリンクも作らない（外へ渡す必要が出る）
- B. **時期は下書きのあいだだけ**：申し出、承認、断る、外す、抜けるは発議の前だけ。発議で固定する
- C. **人数は共同提出者5人まで**（撤回に全員の同意が要るので増やしすぎない）
- D. **共同提出者にできること**：下書きの編集（提出者と同じ。保存で賛同が集め直しになるのも同じ）、答弁（役割は「共同提出者」）。**提出者だけのまま**のこと：申し出の承認と断る、発議、要調整を直す、出し直し、修正案の取り込み。出し直した下書きに共同提出者は引き継がない
- E. **共同提出者は賛同に数えない**：提出者と同じく、自分の法案に賛同できない。賛同していた人を承認したら、その賛同を外す（発議要件に数えない）
- F. **修正案**：共同提出者は提出者と同じく、自分の法案に修正案を出せず、先議の賛同もできない（本文を直す人が修正案を出すと、取り込みで共同起草者にも載るので）
- G. **一度でも共同提出者になった人は、抜けても外されても提出者の側のまま**（本文を書いた人が、発議の直前に抜けて賛同や投票の割り当てや修正案に回る抜け道を作らないため）。規則はこの1つで、できなくなるのは編集と答弁と名前の掲載だけ。
  - 再度の申し出はできない。賛同できない。修正案を出せず、先議の賛同もできない
  - 票の割り当てから除く。結果の確認では関わった人。評価は提出者の側として数える（立場が未定の人として数えない）
  - 外すと元に戻せないので、提出者の画面で確かめてから外す。投票そのものは今の提出者と同じ
- H. **名前の出し方**：承認された共同提出者の名前は法案のページに出す。申し出ている人の名前は提出者にだけ出す

## 目的

複数の人で法案を書き、答弁を手分けできるようにする。あとの撤回と統合案の土台にする。

## 表

`drizzle/0020_*.sql`。

| 表 | 列 | 決まり |
| --- | --- | --- |
| `bill_cosponsors` | `id`（整数、自動採番。フォームで相手を指すのに使い、他人の内部IDをページに載せない）、`bill_id`（`bills` への外部キー）、`user_id`（`user` への外部キー）、`status`（`requested`・`accepted`・`left`。CHECK）、`created_at`、`accepted_at` | UNIQUE（`bill_id`, `user_id`）。`user_id` の索引。断る、取り下げるは行を消す（一度もなっていないので、また申し出られる）。外す、抜けるは `left` にする（決定G。`left` は変わらない）。発議のときに残った `requested` の行は読まない。**共同提出者は `status = 'accepted'` だけ**。申し出は本人だけで作れるので、権限の判定に `requested` を入れない |
| `actions`（作り直し） | `kind` の CHECK に `bill_cosponsor` を足す | 過去と同じく表を作り直す（`__new_actions`、索引の張り直し。`drizzle/0011_votes.sql` と同じ）。生成した SQL を読み、既存の行が残ることを確かめる |

`posts.role` は列の値に CHECK がないので、`cosponsor` を足すのにマイグレーションは要らない。

## 決めたこと

1. **ルール**：`COSPONSOR_MAX = 5`（`src/lib/domain/bills.ts`）。`answererRole`（`src/lib/domain/posts.ts`）に共同提出者を足す（提出者 → 共同提出者 → 賛同者の順）。**役割はサーバーの1つの関数**（`billRoleOf(db, bill, userId)`）で求め、今の5か所（`shitsugi/+page.server.ts`、`post-actions.ts` の4か所）をすべてこれに替える（役割は答弁だけでなく評価のスコアにも効く。直し忘れると共同提出者の評価が「未定の人の評価」として数えられる）。抜けた人の役割は `former`（`PostRole` に足す）で、答弁はできず（`role` が `author`・`cosponsor`・`supporter` のときだけ答弁できる）、評価では提出者の側として数える（`domain/evaluations.ts` は役割が null でなければ賛成寄りなので、そのまま働く）

2. **操作**（`src/lib/server/cosponsors.ts`）：どれも状態を条件に入れた1文。記録と上限は申し出だけ（`actions` の `bill_cosponsor`。行が変わったときだけ足す。今月の参加者には数えない。`PARTICIPANT_KINDS` に入れない）
   - `requestCosponsor`：下書きで、提出者でなく、行がない人（`left` は断る。409）。上限は1アカウント24時間30回（`LIMITS.billCosponsorPerDay`、`RefusalKind` の `bill-cosponsor-day`、超えたら違反に数える）。1本あたりの件数は制限しない（提出者は断るか放っておけばよい）
   - `withdrawCosponsorRequest`：本人が `requested` の行を消す
   - `decideCosponsor`（提出者）：承認は `accepted` にして同じ人の賛同（全部の版）を外す。人数の確かめは同じ文の中（`accepted` の数が5未満。6人目は 409）。D1 の batch で一緒に行い（値つきの `db.run` を入れない）、**賛同を消す文の条件に「その人の行が `accepted` で、法案が `draft`」を入れる**（batch の中では前の文の結果で後の文を止められないので、承認が通らなかったときに賛同だけ消さない）。断るは行を消す
   - `leaveCosponsor`：本人か提出者が `accepted` の行を `left` にする
   - すべて `status = 'draft'` の法案だけ。発議と同時に走っても、発議のあとの行は変わらない

3. **編集**：`saveDraft` と書く画面の「提出者か」に「`status = 'draft'` のときの共同提出者（`accepted`）」を足す。`saveDraft` の文の条件は `EXISTS`。法案のページの「編集する」（`canEdit`）も同じ。要調整の法案の書く画面と `saveAdjustedBill` は提出者のまま（共同提出者には書く画面を 403 にする）

4. **賛同**：`setBillSupport` の提出者の断りに共同提出者を足す（理由は「共同提出者は賛同できません」）。**賛同を入れる文の条件にも「`accepted` か `left` の行がない」を `NOT EXISTS` で足す**（確かめのあとに承認が走っても、どちらの順でも賛同の行が残らないように）。発議要件の数え方は変えない

5. **割り当てと確認**：除く条件は「行が `accepted` か `left`」。`assignedBills`、`involvedInBill`、`pendingReviews`（`involvedInBill` を呼ばず同じ条件を SQL で持っている）に足す。確認の2か所は1つの式にまとめる

6. **修正案**：`amendment-actions.ts`（出す、先議の賛同）、`shusei` の2つのページ、`AmendmentCard.svelte` の提出者の断りに「`accepted` か `left` の人」を足す。今の `isAuthor` は取り込みのボタンと先議の賛同の両方に効くので、`isAuthor`（取り込み）と `isSide`（出す、先議の賛同）に分ける。取り込みのボタンは共同提出者に出さない

7. **受け付け**（`src/routes/houan/[id]/(page)/+page.server.ts` の `?/cosponsor`）：`op` が `request`・`withdraw`・`accept`・`decline`・`leave`・`remove`。相手は `id`（`bill_cosponsors.id`。`parseIssueId`）で指す（`accept`・`decline`・`remove` だけ）。順は番号と存在（404）→ ログイン → 国 → 締め出し → 登録から7日（`request` だけ。賛同の取り消しと同じく、抜けるには要らない）→ 入力（`op`・`id`。400）→ 権限（403）→ 状態（409）→ 上限（429）。Turnstile は求めない（賛同と同じ）。`id` がその法案の行でなければ 409。提出者でない人の `accept`・`decline`・`remove`、共同提出者でない人の `leave` は 403。申し出ていない人の `withdraw` は 409

8. **画面**（法案のページの概要のタブ）：
   - だれにでも：`提出者 A ・ 共同提出者 B、C ・ 賛同 N人`（共同起草者の行は今までどおり、その下）
   - 下書きで、ログインしていて提出者でも共同提出者でもない人：「共同提出者になりたいと申し出る」。申し出たあとは「申し出を取り下げる」。登録から7日たっていない人には出さない（賛同と同じ案内）
   - 提出者：申し出の一覧（古い順に20件まで。名前、「承認する」「断る」）と共同提出者の「外す」（外すと元に戻せないと書く）。5人なら承認のボタンを出さず「共同提出者は5人までです」
   - 共同提出者：「編集する」と「共同提出者から抜ける」。賛同のボタンは出さない
   - 発議のあとは名前だけ

9. **発議は読んだ版を確かめる**：編集する人が複数になるので、`?/propose` に `rev` を足し、`proposeBill` の文の条件に入れて、違えば 409（「ほかの人が保存しました。読み直してください」）。`proposeBlock` の確かめもこの版で行う。発議は取り消せないので、提出者が読んでいない版を発議しない

10. **文言**：`ja.bill.cosponsor`。答弁の役割の名前に「共同提出者」を足す
