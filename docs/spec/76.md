# 共同提出者（設計書）

Issue #76 のうち共同提出者。マイグレーションがあり、下書きを編集できる人と票の割り当てに関わるので Careful。撤回と統合案は共同提出者を前提にするので、別の Issue に分ける（STOP 1 で確認する）。決定は Issue #41 の決めたこと4「共同提出者と撤回は、統合案や修正案と一緒に v0.4 で扱う」。仕様は [docs/spec.md](../spec.md)「答弁できるのは提出者・共同提出者・賛同者」「発議後の撤回には提出者全員の同意が必要」「提出者どうしで統合案を共同提出できる」。画面の案はない（`SpBillSummary`・`PcBillSummary` にそろえる）。

次のことは仕様書に定めがないので、この Issue の受入基準で確かめる（STOP 1 で確認する）。

- A. **なり方は本人の申し出と提出者の承認**：下書きのページで本人が「共同提出者になりたいと申し出る」を押し、提出者が承認する。提出者から指名する形にしない（人を探す画面がなく、作ると名前の一覧ができる。賛同者の名前を出さない決まり（docs/spec/49.md）にも反する）。招待のリンクも作らない（外へ渡す必要が出る）
- B. **時期は下書きのあいだだけ**：申し出、承認、断る、外す、抜けるは発議の前だけ。発議で固定する
- C. **人数は共同提出者5人まで**（撤回に全員の同意が要るので増やしすぎない）
- D. **共同提出者にできること**：下書きの編集（提出者と同じ。保存で賛同が集め直しになるのも同じ）、答弁（役割は「共同提出者」）。**提出者だけのまま**のこと：申し出の承認と断る、発議、要調整を直す、出し直し、修正案の取り込み
- E. **共同提出者は賛同に数えない**：提出者と同じく、自分の法案に賛同できない。賛同していた人を承認したら、その賛同を外す（発議要件に数えない）。抜けたあとは賛同できる
- F. **票の割り当てと確認**：共同提出者は提出者と同じく、割り当てから除き（`assignedBills`）、結果の確認では関わった人とする（`involvedInBill`）。投票そのものは今の提出者と同じ
- G. **名前の出し方**：承認された共同提出者の名前は法案のページに出す。申し出ている人の名前は提出者にだけ出す

## 目的

複数の人で法案を書き、答弁を手分けできるようにする。あとの撤回と統合案の土台にする。

## 表

`drizzle/0020_*.sql`。新しい表だけ。

| 表 | 列 | 決まり |
| --- | --- | --- |
| `bill_cosponsors` | `bill_id`（`bills` への外部キー）、`user_id`（`user` への外部キー）、`status`（`requested`・`accepted`。CHECK）、`created_at`、`accepted_at` | 主キー（`bill_id`, `user_id`）。断る、外す、抜ける、取り下げるは行を消す（記録は `actions`）。`user_id` の索引 |

`posts.role` は列の値に CHECK がないので、`cosponsor` を足すのにマイグレーションは要らない。

## 決めたこと

1. **ルール**（`src/lib/domain/bills.ts`）：`COSPONSOR_MAX = 5`。`answererRole` に共同提出者を足す（提出者 → 共同提出者 → 賛同者の順）

2. **操作**（`src/lib/server/cosponsors.ts`）：どれも状態を条件に入れた1文で、行が変わったときだけ `actions`（`bill_cosponsor`）に足す
   - `requestCosponsor`：下書きで、提出者でなく、まだ行がない人。回線の上限は賛同と同じ考え（`LIMITS` に `billCosponsorPerDay: 30` を足し、超えたら違反に数える）
   - `withdrawCosponsorRequest`：本人が `requested` の行を消す
   - `decideCosponsor`（提出者）：承認は `accepted` にして同じ人の賛同を外す。人数の確かめは同じ文の中（`accepted` の数が5未満）。D1 の batch で承認と賛同の削除を一緒に行う（値つきの `db.run` を入れない）。断るは行を消す
   - `leaveCosponsor`：本人か提出者が `accepted` の行を消す
   - すべて `status = 'draft'` の法案だけ。発議と同時に走っても、発議のあとの行は変わらない

3. **編集**：`saveDraft` と書く画面の「提出者か」を「提出者か共同提出者か」にする。`saveDraft` の文の条件は `EXISTS`。提出者のページの「編集する」も同じ。要調整を直す（`saveAdjustedBill`）は提出者のまま

4. **賛同**：`setBillSupport` の提出者の断りに共同提出者を足す（理由は「共同提出者は賛同できません」）。発議要件の数え方は変えない（賛同の行を外すので）

5. **割り当てと確認**：`assignedBills` の除く条件と `involvedInBill` に足す

6. **受け付け**（`src/routes/houan/[id]/(page)/+page.server.ts` の `?/cosponsor`）：`op` が `request`・`withdraw`・`accept`・`decline`・`leave`・`remove`。順は番号と存在（404）→ ログイン → 国 → 締め出し → 登録から7日（`request` だけ。賛同の取り消しと同じく、抜けるには要らない）→ 入力（`op`・`user`。400）→ 権限（403）→ 状態（409）→ 上限（429）。Turnstile は求めない（賛同と同じ）。`user` は申し出の行があるかで確かめ、なければ 409

7. **画面**（法案のページの概要のタブ）：
   - だれにでも：`提出者 A ・ 共同提出者 B、C ・ 賛同 N人`
   - 下書きで、ログインしていて提出者でも共同提出者でもない人：「共同提出者になりたいと申し出る」。申し出たあとは「申し出を取り下げる」
   - 提出者：申し出の一覧（名前、「承認する」「断る」）と共同提出者の「外す」。5人なら承認のボタンを出さず「共同提出者は5人までです」
   - 共同提出者：「編集する」と「共同提出者から抜ける」
   - 発議のあとは名前だけ

8. **文言**：`ja.bill.cosponsor`。答弁の役割の名前に「共同提出者」を足す
