# 共同提出者・撤回・統合案（設計書）

Issue #76。マイグレーションがあり、下書きを編集できる人、票の割り当て、法案の状態に関わるので Careful。ユーザーの判断で3つを1つの PR にする。決定は Issue #41 の決めたこと4「共同提出者と撤回は、統合案や修正案と一緒に v0.4 で扱う」（Issue #63 に共同提出者の決定はない）。仕様は [docs/spec.md](../spec.md)「答弁できるのは提出者・共同提出者・賛同者」「発議後の撤回には提出者全員の同意が必要」「提出者どうしで統合案を共同提出できる」。画面の案はない（`SpBillSummary`・`PcBillSummary` にそろえる）。

**編集できる人**：仕様の「発議前は提出者と賛同者だけが編集できる」は、#41 の決めたこと4で「提出者1人だけ」に変えた。賛同者は今までどおり編集できず、共同提出者を足す。

次のことは仕様書に定めがないので、この Issue の受入基準で確かめる（STOP 1 で確認する）。

### 共同提出者

- A. **なり方は本人の申し出と提出者の承認**：下書きのページで本人が「共同提出者になりたいと申し出る」を押し、提出者が承認する。提出者から指名する形にしない（人を探す画面がなく、作ると名前の一覧ができる。賛同者の名前を出さない決まり（docs/spec/49.md）にも反する）。招待のリンクも作らない（外へ渡す必要が出る）
- B. **時期は下書きのあいだだけ**：申し出、承認、断る、外す、抜けるは発議の前だけ。発議で固定する
- C. **人数は共同提出者5人まで**（撤回に全員の同意が要るので増やしすぎない）
- D. **共同提出者にできること**：下書きの編集（提出者と同じ。保存で賛同が集め直しになるのも同じ）、答弁（役割は「共同提出者」）。**提出者だけのまま**のこと：申し出の承認と断る、発議、要調整を直す、出し直し、修正案の取り込み。出し直した下書きに共同提出者は引き継がない（出し直しは別の法案で、提出者が改めて承認する。元の共同提出者は、新しい法案では提出者の側ではない）
- E. **共同提出者は賛同に数えない**：提出者と同じく、自分の法案に賛同できない。賛同していた人を承認したら、その賛同を外す（発議要件に数えない）
- F. **修正案**：共同提出者は提出者と同じく、自分の法案に修正案を出せず、先議の賛同もできない（本文を直す人が修正案を出すと、取り込みで共同起草者にも載るので）
- G. **一度でも共同提出者になった人は、抜けても外されても提出者の側のまま**（本文を書いた人が、発議の直前に抜けて賛同や投票の割り当てや修正案に回る抜け道を作らないため）。規則はこの1つで、できなくなるのは編集と答弁と名前の掲載だけ。
  - 再度の申し出はできない。賛同できない。修正案を出せず、先議の賛同もできない
  - 票の割り当てから除く。結果の確認では関わった人。評価は提出者の側として数える（立場が未定の人として数えない）
  - 外す、抜けるは元に戻せないので、ボタンの近くに影響を書き、確かめのチェックを求める。申し出のボタンの近くにも、承認されると賛同が外れること、抜けても元に戻せないことを書く
  - 投票そのものは今の提出者と同じ（投票の受け付けと数え方に提出者の判定はなく、変えない）
- H. **名前の出し方**：承認された共同提出者の名前は、承認の順に法案のページに出す。申し出ている人の名前は提出者にだけ出す。賛同者の名前は出さない決まりだが、賛同していた人を承認すると「賛同 N人」が減るので、賛同していたことが推測できることはある（本人が申し出たことなので許す。申し出のボタンの近くに書く）
- I. **断られた申し出は再度できない**（断った提出者のもとに同じ人が何度も来ないように）。自分で取り下げた申し出は、また出せる

### 撤回

仕様：「発議後の撤回には提出者全員の同意が必要で、賛同の取り消しはできない」。

- J. **撤回できる時期は発議から採決が始まる前まで**。採決が始まると票の割り当てが固定され、票が入るので撤回できない（割り当てのやり直しが要らない）。下書きは撤回しない（発議しなければよい）
- K. **同意するのは提出者と共同提出者（`accepted`）の全員**。抜けた人は入らない。各自が「撤回に同意する」を押し、最後の1人が押した時点で撤回になる。全員が同意する前なら取り消せる。提出者1人の法案は1回押せば撤回になるので、確かめのチェックを求める
- L. **撤回は元に戻せない**。法案のページと質疑は読めるまま残り、段階は「撤回」。質疑、修正案、立場、評価は書けなくなる。「終わった」のタブに出る。出し直しはできない（自分で取り下げた法案なので。#75 の決定に足す）

### 統合案

仕様：「提出者どうしで統合案を共同提出できる。統合案が発議されると、元の法案は取り下げ扱いになる」。

- M. **元の法案は2本**。3本以上は作らない（使われ方を見て足す）。どちらも「取り下げられる」状態（下書きか、発議から採決が始まる前まで）で、同じ委員会
- N. **作り方**：元の法案の提出者が、自分の法案のページで相手の法案の番号を入れて「統合案を作る」を押す。自分の法案の読む版を複製した新しい下書きができる（#75 と同じ。基にした版も元のまま）。提出者は押した人で、賛同は集め直す。もう1本の条文は、共同で書き直す
- O. **同意**：元の法案それぞれの提出者と共同提出者の全員が同意する。相手の法案の提出者は、同意すると統合案の共同提出者になる（上限の5人に数える）。同意は取り消せない。統合案を発議するまでは何も起きず、相手の提出者が統合案の共同提出者から抜ければ発議できない。統合案の提出者は「統合案をやめる」で普通の下書きに戻せる（同意とつながりを消す）
- P. **発議**：全員が同意していて、元の法案が2本とも取り下げられる状態のときだけ。発議と同時に元の法案を「撤回」の状態にする（`db.batch`）。段階の名前は「統合案に統合」で、統合案へのリンクを出す。元の法案についた賛同と質疑は統合案に移らない
- Q. **リンク**：統合案のページに「元の法案：A、B」、元の法案のページに「統合案：M」（下書きのあいだは、元の法案の提出者と共同提出者にだけ出す。発議のあとはだれにでも）

## 目的

複数の人で法案を書き、答弁を手分けできるようにする。発議した法案を全員の同意で取り下げ、似た法案を1本にまとめられるようにする。

## 決めたこと

1. **ルール**：`COSPONSOR_MAX = 5`（`src/lib/domain/bills.ts`）。`answererRole`（`src/lib/domain/posts.ts`）に共同提出者を足す（提出者 → 共同提出者 → 賛同者の順）。**役割はサーバーの1つの関数**（`billRoleOf(db, bill, userId)`）で求め、今の5か所（`shitsugi/+page.server.ts`、`post-actions.ts` の4か所）をすべてこれに替える（役割は答弁だけでなく評価のスコアにも効く。直し忘れると共同提出者の評価が「未定の人の評価」として数えられる）。抜けた人の役割は `billRoleOf` だけが返す `former`（`PostRole` に足す）で、評価では提出者の側として数える（`domain/evaluations.ts` は役割が null でなければ賛成寄りなので、そのまま働く）。答弁はできず（受け付けと `QuestionCard` には `former` を null として渡すので、今までどおり補足を書ける）、`posts.role` に保存されず、画面の役割の名前にも出ない

2. **操作**（`src/lib/server/cosponsors.ts`）：どれも状態を条件に入れた1文。記録と上限は申し出だけ（`actions` の `bill_cosponsor`。行が変わったときだけ足す。今月の参加者には数えない。`PARTICIPANT_KINDS` に入れない）
   - `requestCosponsor`：下書きで、提出者でなく、行がない人（提出者は 403、`left` と `declined` は 409）。上限は1アカウント24時間30回（`LIMITS.billCosponsorPerDay`、`RefusalKind` の `bill-cosponsor-day`、超えたら違反に数える）。1本あたりの件数は制限しない（提出者は断るか放っておけばよい）
   - `withdrawCosponsorRequest`：本人が `requested` の行を消す
   - `decideCosponsor`（提出者）：承認は `accepted` にして同じ人の賛同（全部の版）を外す。人数の確かめは同じ文の中（`accepted` の数が5未満。6人目は 409）。D1 の batch で一緒に行い（値つきの `db.run` を入れない）、**賛同を消す文の条件に「その人の行が `accepted` で、法案が `draft`」を入れる**（batch の中では前の文の結果で後の文を止められないので、承認が通らなかったときに賛同だけ消さない）。断るは `declined` にする
   - `leaveCosponsor`：本人か提出者が `accepted` の行を `left` にする（確かめのチェックがなければ 400）
   - すべて `status = 'draft'` の法案だけ。発議と同時に走っても、発議のあとの行は変わらない

3. **編集**：保存どうしの上書きは今の `saveDraft` の版の条件（`expectedRev`）で防げる（違えば 409）。`saveDraft` と書く画面の「提出者か」に「`status = 'draft'` のときの共同提出者（`accepted`）」を足す。`saveDraft` の文の条件は `EXISTS`。法案のページの「編集する」（`canEdit`）も同じ。要調整の法案の書く画面と `saveAdjustedBill` は提出者のまま（共同提出者には書く画面を 403 にする）

4. **賛同**：`setBillSupport` の提出者の断りに共同提出者を足す（理由は「共同提出者は賛同できません」「共同提出者だった法案には賛同できません」）。**賛同を入れる文の条件にも「`accepted` か `left` の行がない」を `NOT EXISTS` で足す**（確かめのあとに承認が走っても、どちらの順でも賛同の行が残らないように）。発議要件の数え方は変えない

5. **割り当てと確認**：除く条件は「行が `accepted` か `left`」。`assignedBills`、`involvedInBill`、`pendingReviews`（`involvedInBill` を呼ばず同じ条件を SQL で持っている）に足す。確認の2か所は1つの式にまとめる

6. **修正案**：`amendment-actions.ts`（出す、先議の賛同）、`shusei` の2つのページ、`AmendmentCard.svelte` の提出者の断りに「`accepted` か `left` の人」を足す。今の `isAuthor` は取り込みのボタンと先議の賛同の両方に効くので、`isAuthor`（取り込み）と `isSide`（出す、先議の賛同）に分ける。取り込みのボタンは共同提出者に出さない

7. **受け付け**（`src/routes/houan/[id]/(page)/+page.server.ts` の `?/cosponsor`）：`op` が `request`・`withdraw`・`accept`・`decline`・`leave`・`remove`。相手は `id`（`bill_cosponsors.id`。`parseIssueId`）で指す（`accept`・`decline`・`remove` だけ）。順は番号と存在（404）→ ログイン → 国 → 締め出し → 登録から7日（`op` が `request` のときだけ。形の違う `op` は `request` でないので次の入力で断る）→ 入力（`op`・`id`・確かめ。400）→ 権限（403）→ 状態（409）→ 上限（429）。Turnstile は求めない（賛同と同じ）。`id` がその法案の行でなければ 409。提出者でない人の `accept`・`decline`・`remove`、共同提出者でない人の `leave` は 403。申し出ていない人の `withdraw` は 409

8. **画面**（法案のページの概要のタブ）：
   - だれにでも：`提出者 A ・ 共同提出者 B、C ・ 賛同 N人`（共同起草者の行は今までどおり、その下）
   - 下書きで、ログインしていて、行がない人：「共同提出者になりたいと申し出る」と、決定G・Hの説明。申し出たあとは「申し出を取り下げる」。登録から7日たっていない人には出さない（賛同と同じ案内）
   - 提出者：申し出の一覧（古い順に20件まで。ほかにあれば「ほかに N 件」。名前、「承認する」「断る」）と共同提出者の「外す」（外すと元に戻せないと書く）。5人なら承認のボタンを出さず「共同提出者は5人までです」
   - 共同提出者：「編集する」と「共同提出者から抜ける」（確かめのチェックつき）。賛同のボタンは出さない
   - 抜けた人：申し出と賛同のボタンを出さず、「共同提出者から抜けた法案です」と出す。断られた人：申し出のボタンを出さず、「申し出は断られました」と出す（賛同はできる）
   - 発議のあとは名前だけ

9. **発議は読んだ版を確かめる**：編集する人が複数になるので、`?/propose` に `rev` を足し、`proposeBill` の文の条件に入れて、違えば 409（「ほかの人が保存しました。読み直してください」）。`proposeBlock` の確かめもこの版で行う。発議は取り消せないので、提出者が読んでいない版を発議しない。賛同の数は今の文の条件のまま（承認で賛同が外れれば、その場で数え直される）

10. **文言**：`ja.bill.cosponsor`。答弁の役割の名前に「共同提出者」を足す

## 決めたこと（撤回と統合案）

11. **状態**：`BILL_STATUSES` に `withdrawn`、`BillProgress` に `withdrawn` を足す。`billProgress` は `status` を先に見て `withdrawn` を返す。質疑、修正案、立場、評価、投票の開く条件は `progress` で決まっているので、そのまま閉じる。`inVote` は `status = 'proposed'` なので採決と会期の処理に入らない。変えるところは、`relatedBills`（撤回を除く）、`listBills` の「終わった」（`withdrawn` を足す）、結果のページ（「この法案は撤回されました」）、`BILL_PROGRESS_STEP`、`ja.bill.progress`、`progressOf` の型

12. **撤回**（`src/lib/server/withdraw.ts`）：`consentWithdraw`、`cancelWithdraw`。受け付けは `?/withdraw`（`op`：`consent`・`cancel`）。順は番号と存在（404）→ ログイン → 国 → 締め出し → 入力（400）→ 権限（提出者か `accepted` でなければ 403）→ 状態（409）。同意の行を入れたあと、1つの文で確定する：`UPDATE bills SET status = 'withdrawn', withdrawn_at = ? WHERE id = ? AND status = 'proposed' AND NOT EXISTS (同意していない提出者か共同提出者)`。時期は受け付けで `billProgress` を見る（`proposed` か `deliberation`）。確定したときだけ `actions` に `bill_withdraw` を足す。登録から7日は求めない（提出者はすでに満たしている）

13. **統合案**（`src/lib/server/merge.ts`）：
    - `createMerge`（`?/merge`、`op=create`、`with`=相手の番号）：提出者だけ。上限は下書きと同じ（`draftRefusal`）。`createUnconfirmedDraft` → つながりと押した人の同意を入れる → `rev = 1` にする（#75 と同じ順。作りかけの行は読まれない）。同じ2本の組の統合案がすでにあれば、作らずそこへ移る
    - `consentMerge`（`op=consent`）：その元の法案の提出者か `accepted`。相手の法案の提出者なら、統合案の `bill_cosponsors` に `accepted` で入れる（人数の確かめは同じ文。5人なら 409）
    - `cancelMerge`（`op=cancel`）：統合案の提出者。下書きのあいだだけ。同意とつながりを消す
    - `mergeBlock(db, bill, now)`：`proposeBlock` に足す。つながりがあれば、全員の同意、相手の提出者が `accepted`、元の法案が2本とも取り下げられる状態を確かめる。違えば `merge`（「元の法案の提出者全員の同意が要ります」）か `mergeClosed`（「元の法案が採決に入ったか終わったので、統合案として発議できません」）
    - `proposeBill`：つながりがあるときは `db.batch` で、統合案の発議（今の条件の文を builder で）と、元の法案の撤回（`status IN ('draft', 'proposed')` で、統合案が `proposed` になっている条件つき）を一緒に行う

14. **画面**（法案のページの概要のタブ）：
    - 撤回：提出者と共同提出者に「撤回に同意する」（確かめのチェック。N 人中 M 人が同意と、同意した人の名前）、「同意を取り消す」。ほかの人には出さない
    - 統合案を作る：提出者に番号の欄と「統合案を作る」。取り下げられる状態のときだけ
    - 統合案の同意：元の法案の提出者と共同提出者に、統合案へのリンクと「統合案に同意する」（説明：発議されるとこの法案は撤回になる）
    - 統合案の下書き：提出者に同意の状況と「統合案をやめる」
    - 撤回された法案：段階の下に「撤回されました」か「統合案に統合されました：M」
