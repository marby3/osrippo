# 議員にできないことと、今月の参加者の数え方（設計書）

Issue #158。今月の参加者の数え方（発議要件・定足数・修正案の先議・解任動議の母数）と、票と投票資格のまわりに触れるので Careful。仕様は [docs/spec.md](../spec.md) の「役割ごとにできること」：議員は課題に「検討中」を付けるほかは閲覧で、質疑と答弁には任意で加われる。評価と投票はできない。

受入基準は Issue #158、前提の決定は Issue #147 の決めること4（2026-11-10 ユーザーと決定）。認証そのものは #157（`docs/spec/157.md`）。マイグレーションはない。

## 決めたこと

### 1. 議員かどうか

- **議員**とは、有効な認証（`docs/spec/157.md` の 2）があり、種類が `legislator` の人。有識者と、認証が切れたり取り消されたりした人は一般の参加者と同じ
- 判定はルールの関数 `isLegislator(kind)` と、サーバーの `legislatorAt(db, userId, now)`（有効な認証の種類を読む）。`now` は要求の時刻

### 2. 書き込みを止める（基準1・2）

- 書き込みの共通の入口 `writeGuard`（`src/lib/server/client.ts`）に、**何のための書き込みか** を必須の引数 `use` で渡す。値は次の3つ
  - `'participate'`：ゲームに参加する書き込み。議員は断る
  - `'speak'`：法案の質疑・答弁・補足と、「読んだ」の記録。議員もできる
  - `'report'`：通報。議員もできる
- 必須にするので、渡し忘れた呼び出し元は型チェックで落ちる（19か所すべてで決める）
- 断るときは `fail(403, { message: ja.guard.legislator })`（「議員のアカウントではできません。閲覧と質疑ができます。」）。確かめる順は 国 → 締め出し → 議員
- 呼び出し元ごとの `use`

| 書き込み | 場所 | use |
| --- | --- | --- |
| 課題の投稿 | `kadai/kaku` | participate |
| 課題の「わかる」 | `kadai/[id]` の `support` | participate |
| 課題の通報 | `kadai/[id]` の `report` | report |
| 解決策の投稿 | `kadai/[id]/kaiketsu/kaku` | participate |
| 解決策の「わかる」「考えが変わった」 | `solution-actions` の `reactAction` | participate |
| 解決策の通報 | `solution-actions` の `reportSolutionAction` | report |
| 法案の下書き・保存 | `bill-actions` の `submitBill` | participate |
| 賛同・発議・出し直し・共同提出・撤回の同意・統合 | `bill-actions` の `billGuard` | participate |
| 修正案の提出・取り込み・賛同・採決 | `amendment-actions` | participate |
| 修正案の通報 | `amendment-actions` の `reportAmendmentAction` | report |
| 質疑・答弁・補足 | `post-actions` の `writer` | speak |
| 考え | `post-actions` の `stanceAction` | participate |
| 評価 | `post-actions` の `evaluationAction` | participate |
| 投稿の通報 | `post-actions` の `reportPostAction` | report |
| 「読んだ」の記録 | `post-actions` の `readAction` | speak |
| 投票 | `saiketsu/[id]` | participate |
| 立候補・委員長の投票・解任の署名 | `iinkai` の `writer` | participate |

- 課題のページの `prepare`（「わかる」と通報で共通）は、呼び出し元から `use` を受け取る
- 立候補の取り下げと署名の取り消し（`iinkai` の `undoer`）は `writeGuard` を通らない。議員になる前の立候補や署名を取り消せるよう、止めない
- 撤回の同意と取り込みは、法案の提出者と共同提出者だけの操作。議員は新しく提出者や共同提出者になれないので、議員になる前の法案だけが当たる。参加の書き込みとして止める（法案の行方は、ほかの提出者と共同提出者が決める）

### 3. 画面に出さない（基準1）

- 全体の `+layout.server.ts` が `legislator: boolean` を返す（ログインしていなければ false）。読むのはログインしている人だけで、1回の要求に1回
- `legislator` が真のとき、次の場所でボタンやフォームの代わりに `ja.guard.legislator` を出す
  - 課題の一覧・ページの「課題を書く」、課題を書く画面（`/kadai/kaku`）、課題の「わかる」
  - 解決策を書く画面と、解決策の「わかる」「考えが変わった」
  - 法案を書く画面（`/houan/kaku`）、法案のページの賛同・発議・出し直し・共同提出・統合
  - 修正案のタブの「修正案を出す」・賛同・採決
  - 質疑のタブの考えと評価のボタン（質疑を書くボタンは出す）
  - 採決の一覧と投票の画面
  - 委員会のページの立候補・投票・署名
- 通報のボタンは出す

### 4. 割り当てを作らない

- 投票できないので、採決の割り当て（`assignmentRows`）は議員には作らず、空の一覧を返す。採決の一覧は「割り当て法案 0 / 0」（締めのテストの筋書き5）になり、`ja.guard.legislator` を添える
- 議員になる前に作った割り当ては消さない（基準4）

### 5. 今月の参加者に数えない（基準3・4）

- `sessionParticipants`（`src/lib/server/bills.ts`）が数を決めるとき、`actions.user_id` のうち、**その時点（`now`）で有効な議員の認証がある人を除く**（`NOT IN (SELECT user_id FROM user_verifications WHERE kind = 'legislator' AND revoked_at IS NULL AND expires_at > now)`）
- 数は会期ごとに最初に求めたときに `session_participants` に固定する（今と同じ）。固定したあとで認証を付けたり外したりしても、その会期の数は変えない
- 「行動した時点で議員だったか」ではなく「数える時点で議員か」で判定する（Issue #158 で決定）。行動の記録に認証の状態を足さずに済む
- 投票資格（`eligible`）と数えた票の判定（`countedCondition`）は変えない。議員になる前に入れた票は、今までどおり数える（基準4）。議員になったあとは投票できないので、新しい票はない
- 課題の橋渡しスコア（#126）のグループは票から作るので、議員は新しく入らない。変えない

## テスト

- **ルールのテスト**（`src/lib/domain/verification.test.ts` に足す）：`isLegislator` は議員だけ真
- **DB のテスト**（`src/lib/db/legislators.test.ts`）
  - 基準3：議員の行動を数えない。数えたあとで認証を付けても数は変わらない。有識者は数える
  - 基準4：議員になる前に入れた票を数える
  - 割り当て：議員には作らない
- **画面のテスト**（`e2e/giin-seigen.spec.ts`。基準ごとに1本）
  - 基準1：議員の課題のページに「わかる」がなく文言が出る。課題を書く画面・法案を書く画面・採決の一覧に文言が出る。課題の投稿・「わかる」・解決策の反応・賛同・考え・評価・投票・立候補の POST が 403
  - 基準2：議員が質疑を書け、通報できる
  - 基準5：有識者は「わかる」を付けられる。議員の認証を取り消すと「わかる」を付けられる

## 範囲の外

- 「拾った」ステータス（#150）と答弁イベント（#153）。どちらも議員の書き込みで、それぞれの Issue で `use` を足す
- 選挙期間中に止めること（#151）
