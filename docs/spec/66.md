# 質疑・答弁・補足と、自分の考え（設計書）

Issue #66。マイグレーション（表の追加）を足すので Careful。仕様の正は [docs/spec.md](../spec.md) の「質疑と評価」。画面は `SpBillQA`・`PcBillQA`。法案の進みは [docs/spec/50.md](50.md)、書き込みの確かめの順は #49 と同じ。

仕様書にない次のことは、ユーザーと決めた（Issue #63 決めたこと12。仕様書のドキュメントへの反映はユーザー側）。

- 質疑と補足は付託先の会期の3週目に書ける。答弁は採決の締切まで書ける。立場は発議から会期末まで持てる
- 書くには登録から7日と Turnstile が要る

次のことは、この Issue の受入基準で確かめる（Issue #66 STOP 1）。

- 立場は最初は「未定」で、最初に選ぶのは変更に数えない。そのあと2回変えられる
- 1つの質疑に複数の答弁を書ける（仕様「手分けできる」）。答弁待ちは、答弁が1つもない質疑
- 質疑・答弁・補足に名前を出さない。答弁には「提出者」「賛同者」だけを出す（案のとおり）。`load` の返す値にも `user_id` を入れず、自分のものかはサーバーで求めた `mine` だけを返す
- 質疑のタブは発議から出す。下書きには質疑がないので出さない
- 自分の質疑には答弁できない
- 字数は質疑400字、答弁800字、補足400字
- 通報は別の Issue にする

## 目的

法案のページの質疑のタブで、質疑・答弁・補足を読み書きし、自分の考えを持てるようにする。評価のボタンは #67、似た質疑をまとめるのは #77、併合審査で関連法案の質疑を読むのは #69。

## 範囲

- 入れる：表、書く関数とフォーム、質疑のタブ（一覧、答弁待ちの絞り込み、ページ送り）、自分の考え、レート制限
- 入れない：評価のボタンと読んだ記録（#67）、通報と非表示（新しい Issue）、委員長の整理（#77）、通知（#78）、共同提出者の答弁（#76）

## 決めたこと

1. **書ける時期**（`postWindowOpen(kind, progress)`・`stanceOpen(progress)`。純粋な関数。`src/lib/domain/posts.ts`）：`progress` は `billProgress`（docs/spec/50.md）の値

   | 書くもの | `proposed` | `deliberation` | `vote` | ほか |
   | --- | --- | --- | --- | --- |
   | 質疑・補足 | × | ○ | × | × |
   | 答弁 | × | ○ | ○ | × |
   | 立場 | ○ | ○ | ○ | × |

   読むのは、質疑のタブがあれば誰でもできる（下書き以外。下書きと発議の間に別の状態はない。docs/spec/50.md 決めたこと3）。`vote` の終わりは付託先の会期の終わりと同じ時刻なので、採決の締切と会期末はずれない

2. **答弁できる人**（`answererRole(bill, userId, supporterIds)`）：提出者は `author`、賛同者は `supporter`、ほかは null。賛同者は `bill_supports` のどの版の行でも数える（修正案の取り込みで版が進んでも答弁できるように。docs/spec/65.md 決めたこと8と同じ）
   - 補足は答弁できない人が書く（仕様「それ以外の人も」）。提出者と賛同者が補足を送ると 403
   - 自分の質疑には答弁できない（`posts.user_id` と比べる。送ると 403）。提出者か賛同者が自分の質疑を見るときは、どちらのボタンも出さない。ほかの人は、自分の質疑に補足を書ける（質問の言い足し）
   - 役割は書いたときの値を持つ
3. **本文の確かめ**（`validatePost(kind, raw)`）：`checkText`（`issues.ts`）で、質疑400字、答弁800字、補足400字。改行可
4. **書き込みの順**（`src/lib/server/post-actions.ts`）：番号と存在（404）→ ログイン → 国 → 締め出し（`writeGuard`）→ 登録から7日 → Turnstile → 入力 → 状態（時期、役割、質疑がこの法案のものか）→ レート制限 → 保存。記録（`question_post`・`answer_post`・`supplement_post`）は保存したあとで足す。`target_id` は法案の番号
   - 答弁と補足の親は、同じ法案の同じ会期の、`kind = 'question'` の行。違えば 404
   - `session_key` は `referralSession(proposedAt, minutes).key`（要調整の法案の持ち方は #72）
   - 番号の扱い：URL の法案の番号の形が違うか、法案がなければ 404。フォームの番号と `op` の形が違えば 400（確かめるのは Turnstile のあと、入力の段）
5. **レート制限**（`checkPost`。`limits.ts`）：1アカウント24時間に質疑10、答弁30、補足10。どれも合わせて5分に10回。1回線24時間に合わせて60回。アカウントの上限（24時間と5分のどちらも）を超えたら違反に数え、回線の上限は数えない（今までと同じ）
   - 答弁の上限を多くするのは、提出者がまとめて答えるため
6. **立場を変える**（`setStance(db, actor, bill, session, stance, now)`）：最初に選ぶのは変更に数えず、そのあと2回まで。同じ立場への操作は何もせず、数えない。`session` は `referralSession(proposedAt, minutes)`
   - 行がないのは未定と同じなので、何も選んでいない人が未定を押しても何も起きない（回数を失わない）
   - 賛成寄りと反対寄りは、次の1文で行う。回数の確かめも同じ文の中なので、2つのタブから同時に押しても上限を超えない

     ```sql
     INSERT INTO stances (session_key, bill_id, user_id, stance, changes, updated_at) VALUES (?, ?, ?, ?, 0, ?)
     ON CONFLICT (session_key, bill_id, user_id) DO UPDATE SET stance = excluded.stance, changes = changes + 1, updated_at = excluded.updated_at
     WHERE stances.stance <> excluded.stance AND stances.changes < 2
     RETURNING changes
     ```

   - 未定は、次の1文で行う（行がなければ何も起きない）

     ```sql
     UPDATE stances SET stance = 'undecided', changes = changes + 1, updated_at = ?
     WHERE session_key = ? AND bill_id = ? AND user_id = ? AND stance <> 'undecided' AND changes < 2
     RETURNING changes
     ```

   - 行が返らなければ、同じ立場か上限。読み直して理由を出す
   - `stance_log` はトリガーで足す。`actions`（`stance_set`）は行が返ったときだけ足す（今までの記録と同じで、足すのに失敗しても立場は変わったまま）
   - 未定に戻すのも1回の変更に数える
   - 登録から7日と Turnstile は要らない（「わかる」と同じ。書くものではなく、非公開で、回数の上限がある）。確かめの順は、番号と存在 → ログイン → 国 → 締め出し → 入力 → 時期 → 保存
7. **立場は本人にしか渡さない**：`load` は見ている人の行だけを読む。ほかの人の立場を読む関数を作らない。統計（フェーズ5）は10人未満の区分を出さない決まりと一緒に作る。ページの応答をキャッシュする設定は今のコードにない（ログインした人のページをキャッシュするときは見直す）
8. **質疑のタブ**（`/houan/<番号>/shitsugi`。SpBillQA・PcBillQA）
   - タブの名前は「質疑 N」。N は質疑の数。下書きには出さない（URL も 404）
   - 並びは新しい順。20件ごとに分け、「質疑をもっと見る」で次の20件へ（`?page=`）
   - `?page=` の形が違うか、2ページ目以降に質疑がなければ 404（課題の一覧と同じ）。ページの途中で質疑が増えると次のページに同じ質疑が出ることがあるが、一覧と同じく許す
   - 絞り込み：「すべて」「答弁待ち N」（`?mati=1`）。「質疑をもっと見る」は絞り込みを保つ
   - 1枚のカードに、質疑、答弁（「答弁（提出者）」「答弁（賛同者）」）、補足を出す。答弁がなければ「答弁待ち」を出す
   - `load` の返す値に `user_id` を入れない。自分の質疑かは `mine` で返す
   - **答弁の開閉**：スマホは、カードに1つの「答弁を読む（提出者）」（答弁が2件以上なら「答弁を読む（N件）」）のボタンで開く。`aria-expanded` を付ける。PC は最初から開いていて、ボタンは CSS で隠す（同じものを2つ描かない）。ボタンは `button` のロールで作る
   - 答弁と補足のボタン：答弁できる人には「答弁する」、ほかの人には「補足する」。書ける時期のときだけ出す。ログインしていない人には「補足する」を出し、押すとログインへ。押すとカードの中に欄（「答弁の内容」「補足の内容」）と Turnstile が開く。送るボタンは「送る」
   - 「質疑を書く」：3週目のときだけ出す。`/houan/<番号>/shitsugi/kaku` へ移り、「質疑の内容」と「送る」。ログインしていなければログインへ。URL を直接開いたとき、下書きの法案は 404、3週目の外と登録から7日未満は欄を出さず理由を出す
   - 登録から7日たっていない人には、ボタンの代わりにいつから書けるかを出す（#49 と同じ）
   - カードの読み込みは、質疑のページの分の答弁と補足を `parent_id IN (…)` でまとめて引く。D1 の値の数の上限（100）に対して、20件なので問題ない
9. **あなたの今の考え**：見出し、「自分だけに見えます」、賛成寄り・未定・反対寄りのボタン（`aria-pressed`）、「この会期はあと N回変えられます」
   - ログインしていなければ、どれも押されていない形で出し、「あと N回」は出さない。押すとログインへ（選んだ内容はほかの人に出ない）
   - ログインしていて行がなければ、未定が押された形
   - 期間の外（廃案など）は出さない
   - N は、まだ選んでいなければ「最初に選ぶ1回のほかに2回」なので2を出す。選んだあとは `2 - changes`
10. **画面の言葉**：すべて `src/lib/copy/ja.ts`

## テストの方針

受入基準ごとに1本。フォームの信頼の境界に1本。

- 単体テスト：`setStance` の回数と同じ立場と履歴のトリガー（基準6の DB の側）、`checkPost` の上限と違反に数えるか（基準8）
- 画面のテスト（2幅。`e2e/shitsugi.spec.ts`）：タブ（基準1）、質疑（基準2）、答弁（基準3）、補足（基準4）、絞り込み（基準5）、自分の考え（基準6）、答弁の開閉（基準7）、信頼の境界

## あとで決めること

- 質疑・答弁・補足の通報と非表示（新しい Issue。公開の前に要る）
- 似た質疑をまとめる（#77）
- 要調整で次の会期に審議するときに、前の会期の質疑を見せるか（#72）
- 退会を入れるときの、質疑と立場の行の扱いと外部キーの `ON DELETE`。立場は個人の考えに近いので、退会で消す方向で決める（いまは退会がなく、`issue_supports` と同じく指定しない）
