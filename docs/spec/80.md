# 質疑・答弁・補足の通報と非表示（設計書）

Issue #80。マイグレーション（列、表、トリガーの追加）と、運営の画面の権限に関わるので Careful。仕様は [docs/spec.md](../spec.md) の「モデレーションの方針」と「委員長の仕事：通報の一次対応」。課題の通報は [docs/spec/28.md](28.md)、解決策は [docs/spec/36.md](36.md)。あとで決めるとしていたこと：docs/spec/66.md（非表示の答弁の数え方、1枚のカードの件数の上限）、docs/spec/67.md（非表示の投稿の評価）、docs/spec/78.md（通知）。

修正案の通報と非表示は #103、似た質疑をまとめるのは #104 に分けた（設計レビューが3回とも Blocker だったため）。この設計書の決定の記号は分ける前のものを保つ。K〜M は #103、R〜V は #104 へ送った。

解決策（docs/spec/36.md）と同じ決まりを投稿に広げる。仕様書に定めがないところは次のとおりで、この Issue の受入基準で確かめる（STOP 1 で確認する）。

## 決定

### 通報

- A. **対象**：質疑、答弁、補足。理由は解決策と同じ「人への攻撃・差別」「宣伝・荒らし」「その他」（任意）。「その他」の説明は200字まで。時期の制限はない（結果のあとでも、前の会期の質疑でも、攻撃の文面は隠せるように）
- B. **自動非表示**：解決策と同じく、登録から24時間たった別々の3人の通報（`countsTowardHide`）で自動で非表示。対象は `visible` だけで、表示に戻したあと（`restored`）は自動では消えない。**その法案に関わった人（提出者、どの版かの賛同者、共同提出者、抜けた共同提出者）の通報は数に入れない**（当事者が組んで、自分たちの法案への質疑を消せないように）。**判定は通報のときでなく、数えるときに行う**（自動の非表示の文の中で、そのときの関わりを見る。先に通報してから賛同しても抜けられないように）。通報そのものは残り、`/kanri` に「数に入らないもの」として出る。投票は見ない（票は非公開で、委員長と理事のほかは関わりに入らない。決定O）。記録の理由は「通報が3件」（`reports`）
- C. **上限**：1アカウント24時間に10件。課題と解決策の通報と合わせて数える（`reportsInDay`）。超えると違反に数える。1人1件で、2回目は何もしない。自分の投稿は通報できない
- D. **受け付けの順**：法案の番号と存在（404）→ ログイン → 国 → 締め出し → 入力（`post`、`reason`、`note`。形が違えば 400）→ 投稿がその法案のものか（ない番号も含めて 404）→ 自分のもの（400）→ 状態（投稿か親の質疑が非表示なら 403 と「非表示の投稿には操作できません」）→ 2回目（200。数えない）→ 上限（429）→ 保存。登録から7日と Turnstile は使わない（課題と解決策と同じ）

### 見え方

- E. **質疑を非表示にすると、カードごと出さない**（答弁と補足も一緒に）。「質疑 N」と「答弁待ち N」に入れない。答弁と補足の行は残り、表示に戻すと戻る。下の答弁と補足には評価も読んだ記録も通報も付けられず、新しく書けない（親の質疑の状態も条件に入れる）。下の答弁は、書いた人の責任ではないので、スコアと立候補の資格に数える。下の答弁と補足を書いた人には、質疑のタブに自分の本文と「質疑が非表示のため出ていません」を出す（質疑の中身と理由は出さない。通知はしない）
- F. **答弁を非表示にすると、答弁に数えない**。ほかに答弁がなければ、その質疑は「答弁待ち」に戻り、読んだ記録も質疑の側で取る。補足は数に関わらない
- G. **1枚のカードの件数に上限は設けない**（今のレート制限のまま。全部読む。使われ方を見て決める）
- H. **本人と運営にだけ見せる**：書いた本人と、運営の画面の権限のある人には、質疑のタブの「すべて」の1ページ目の最後に、見出し「非表示の投稿」の欄を出す。自分の（運営はその法案の）非表示の投稿の種類（質疑、答弁、補足）、本文、「非表示になっています」と理由を新しい順に50件まで。ほかの人には何も出さない。**`?mati=1`、`?kanren=1`、2ページ目以降には出さない**（絞り込みの結果に混ざらないように。関連法案の非表示はその法案のページで見る）。**関わった法案（決定O）では、運営の権限があっても自分のものしか出さない**。「運営として対応する」のリンクも出さない。メモと対応した人の役職は出さない（公開の記録で読める）。理由の文は解決策と同じく、`auto_hidden` は「通報により」、`hidden` は「運営の確認により（理由：…）」。非表示の質疑の下の答弁と補足は、運営の欄には出さない（質疑の本文で判断する。通報があれば `/kanri` に出る）
- I. **非表示のあいだは何もできない**：答弁、補足、評価、読んだ記録、通報の対象にしない。評価の行は残し、スコアに数えない。表示に戻すと数える（docs/spec/67.md）。評価の取り消しもできない（表示に戻すとできる）。「確かめたあとに非表示になった」ときに評価の行が1行増えても、スコアに数えないので文の条件には入れない
- J. **立候補の資格**（docs/spec/77.md の決定B「非表示は数えない」を次のとおり変える。STOP 1 で確認する）：表示中と表示に戻した投稿に加えて、**自動の非表示と、委員長か理事が非表示にした投稿も数える**。数えないのは、運営か運営協力者が非表示にした投稿だけ。3人の通報や、選挙の相手になりうる委員長と理事の操作で立候補を止められないように、数えない判断は立候補できない人（運営と運営協力者）に限る。委員長か理事の非表示を、運営が数えない形に変えるには、いったん表示に戻してから非表示にする（どちらも公開の記録に残る）

### 運営の画面

- N. **`/kanri` に区画を足す**：「通報を受けた質疑・答弁・補足」。自動で非表示が先、最後の通報が新しい順に100件。各行に種類、法案の題名と質疑のタブへのリンク、本文、状態、通報の数（数に入るもの／入らないもの。決定Bと同じ式）、理由ごとの数、「その他」の説明、`restored` なら表示に戻したあとの通報の数。通報した人と書いた人は出さない。`?post=<番号>` でそれを上に出す（通報されていないものも扱える。法案のタブの「運営として対応する」のリンクから）。形が違う、ない番号は 404。**自分のものと関わった法案の行は一覧に出さない**（本文も通報の文面も渡さない。100件に絞る前に SQL で除く。`?post=` で指しても 404）
- O. **扱えない人**：自分の投稿。**関わった法案**（`involvedInBill`。提出者、賛同者、共同提出者、抜けた共同提出者。委員長と理事は投票した法案も）の投稿は、全部の役職で扱えない（質疑は提出者と賛同者に向けたものなので、当事者が消せないように）。受け付けでも 403
- P. **操作**：非表示にする（理由とメモ）、表示に戻す（メモ）。メモは1〜200字で公開。入力の確かめは課題と解決策と同じ（`validateStaffAction` を `post` の欄で使う）。確かめの順は、役職（404）→ 国（403）→ 入力（400）→ 存在（404。今の課題と解決策の操作は 400 だが、投稿は「ない番号は 404」に揃える）→ 自分のもの（403）→ 関わり（403）→ 状態（400）。**状態の移り変わり**：非表示にできるのは `visible`・`auto_hidden`・`restored`（`HIDEABLE`）、表示に戻せるのは `auto_hidden`・`hidden`（`RESTORABLE`）。非表示の質疑の下の答弁と補足も操作できる（解決策と同じく、親の状態はそのまま効く）
- Q. **権限**：委員長と代行の理事は運営と同じ（docs/spec/77.md）。委員長の役職で行った操作は「委員長の最後の操作」に数える。代行の理事の操作は数えない（記録の `actor` は `director` で、`lastChairAction` は `chair` だけを見る）

### 記録と通知

- W. **公開の記録**：`/unei` に「法案の質疑への対応」の区画を足す（日時、法案の題名と質疑のタブへのリンク、何か（質疑、答弁、補足）、何をしたか（`auto_hide`・`hide`・`restore`）、だれが（役職だけ。`auto` は「自動」）、理由、メモ）。本文、書いた人、通報した人、投稿の番号は出さない。新しい順に50件ごと。ページは `?shitsugi=`（形が違うか、2ページ目以降に行がなければ 404。ほかの2つの表のページの位置を保つ）。条文も可決も出さないので、法案の確認の記録と同じく帯は付けない
- X. **通知**：書いた人に、非表示（自動と操作）、表示に戻した、を届ける（`post_hidden`、`post_restored`）。`target_id` は投稿の番号、`ref_id` は `status_changed_at`（繰り返すと届く。行が変わったときだけ入れる）。文の題名は投稿の法案の題名、リンク先は質疑のタブ（`/houan/<番号>/shitsugi`。1ページ目に理由が出る）。種類（質疑、答弁、補足）は文に出さない

## 決めたこと

1. **表**（`drizzle/0023_*.sql`。既存の表には `ADD COLUMN` だけ。生成された SQL に表の作り直しがないことを確かめる）：
   - `posts` に `status_actor`、`status_actor_user_id`、`status_reason`、`status_note`、`status_changed_at` を足す。`status` は今の列を使い（CHECK はない）、値は `visible`・`auto_hidden`・`hidden`・`restored`。`schema.ts` の `status` に enum を付ける（型だけで SQL は変わらない）
   - `post_reports`：`id`、`post_id`（`posts` への外部キー）、`user_id`（`user` への外部キー）、`reason`（`attack`・`spam`・`other`・`none`。CHECK）、`note`（NULL 可）、`counted`（登録から24時間たっているか。関わりは入れない。決定B）、`created_at`。一意（`post_id`, `user_id`）。索引（`user_id`, `created_at`）
   - `bill_moderation_logs`：`id`、`bill_id`（`bills` への外部キー）、`post_id`（`posts` への外部キー。NULL 可）、`action`、`actor`、`actor_user_id`（外部キーなし。公開しない）、`reason`、`note`、`created_at`。索引（`actor_user_id`, `created_at`）。`moderation_logs` は `issue_id` が NOT NULL で、変えると表の作り直しになるので別の表にする。`post_id` を NULL 可にするのは、#103 で修正案の行を入れて `amendment_id` を足すため。`action`、`actor`、`reason` に CHECK は付けない（#104 で `merge` を足すときに作り直さないため。値は型で絞る。`moderation_logs` と同じ）。行を書くのはトリガーだけなので、`post_id` の有無の CHECK も付けない
   - トリガー `posts_status_log`（手で書く。`solutions_status_log` と同じ）：`status` が変わったら同じ文の中で記録を書く。更新の文は `status_*` を全部書く（前の理由やメモが記録に残らないように）。表を作り直すとトリガーが消えるので、`schema.ts` に注意書きを足す

2. **ルール**（`src/lib/domain/reports.ts`）：`POST_SHOWN = ['visible', 'restored']`、`POST_CANDIDACY = [...POST_SHOWN, 'auto_hidden']`、`POST_CANDIDACY_ACTORS = ['chair', 'director']`（`hidden` でもこの役職の操作なら資格に数える）。理由の判定は `validateSolutionReport` を使う

3. **関わりの式を1つにする**（`src/lib/server/results.ts`）：`involvedSql` を外に出し、利用者を値でも列でも渡せる形に変える（`involvedSql(user, withVotes)`。`${bills}` の行を見るのは今のまま）。使うのは、法案の確認の2か所、`/kanri` の除外（100件に絞る前の WHERE）、`?post=` と操作の確かめ（`involvedInBill`）、質疑のタブの運営の欄、自動の非表示と `/kanri` の「数に入るもの」（通報の `user_id` の列を渡し、`withVotes` は渡さない）

4. **読むところを直す**（`src` の `posts` への参照を全部検索して洗い出した。読むのは `posts.ts`、`evaluations.ts`、`chairs.ts`、`notification-page.ts` で、わたしの記録や共有用の画像には投稿を出していない。「質疑 N」は `questionTotal` を通る）：
   - `posts.ts`：`unanswered`、`questions`、答弁と補足の読み込みは `POST_SHOWN`。`questionOf` は `status` も返す（親が非表示なら受け付けで 403）。`createPost` の答弁と補足の INSERT は、親が `POST_SHOWN` のときだけ入る1文にする（`db.insert().select(sql)`。確かめたあとに非表示になっても、隠れた質疑の下に増えないように。入らなければ記録を足さず、受け付けは 403）。補足にも `mine` を返す
   - `evaluations.ts`：`evaluationTarget`、`recordViews` は `POST_SHOWN` で、答弁と補足は親の質疑も `POST_SHOWN`。`recordViews` の「答弁のある質疑」の判定も `POST_SHOWN` の答弁で見る。`sessionPostScores` は `POST_SHOWN`（親の状態は見ない。決定E）
   - `chairs.ts` の `standBlock` は `POST_CANDIDACY`、または `hidden` で `status_actor` が `POST_CANDIDACY_ACTORS`。親の状態は見ない
   - 直さないもの：`pressedOnBill`（自分の押した印だけ）、`resolveTargets` の投稿の題名（書いた本人に届く通知の題名で、法案の題名だけを出す）

5. **操作**（`src/lib/server/post-moderation.ts`。`cloudflare:workers` に頼らない）：`reportPost`、`changePostStatus`、`reportedPosts`、`reportedPostIds`、`hiddenPostsFor`、`postMeta`、`billModerationLogPage`。状態の変更は条件を入れた1文で、変わったときだけ通知する。`reportsInDay` は3つの表を数える

6. **委員長の最後の操作**：`lastChairAction` に `bill_moderation_logs`（`actor = 'chair'`）を足す

7. **通知**（`src/lib/domain/notifications.ts`）：`NOTIFICATION_KINDS` に `post_hidden`、`post_restored` を足す。`targetOf` は `post` を返す（今のままだと `bill` に落ちるので分岐を足す）。`hrefOf` は質疑のタブを返す。`NoticeTarget` に足す種類はない（`post` がある）。`resolveTargets` は `post` の分岐が題名と法案の番号を返すので直さない。一覧の題名とリンクは画面のテストで確かめる

8. **質疑のタブ**：
   - カード（`QuestionCard`）の質疑、答弁、補足に「通報する」を付ける（新しい部品 `PostReport.svelte`。`SolutionCard` と同じ開き方で、JS がなければ欄を最初から開く。ログインしていなければログインへ）。出さないとき：自分のもの、通報済み（「通報済みです」）、**関連法案のカード**（その法案のページで行う）。前の会期のカードには出す
   - 運営の権限のある人には、各投稿に「運営として対応する」のリンク（`/kanri?post=<番号>`）。出さないとき：自分のもの、関わった法案、関連法案のカード。**関わりはカードの `billId` で判定する**（関連法案のカードには出さないので、今の法案だけを見ればよい）。投稿の番号は画面に出さない
   - 受け付けは `?/reportPost`。URL の法案のものでなければ 404
   - 断った理由と「通報を受け付けました」はそのカードに出す。**カードが消えたとき**（3件目で自動で非表示になった、開いたあとに親の質疑が非表示になった）は一覧の上に出す。答弁と補足を書く欄の失敗も同じで、親の質疑が非表示なら入力は残らない
   - 1ページ目の最後の欄（決定H、決定E）は `hiddenPostsFor` で読む。返す値に `user_id` を入れず、`mine` と `parentHidden` だけを返す

9. **運営の画面**：`?/hidePost`、`?/restorePost`。送り先に `post` を入れる（JS がなくても同じ投稿を開いたままにする）。断った理由はその行に出す

10. **文言**：`ja.report`、`ja.post`、`ja.kanri`、`ja.unei`、`ja.notifications` に足す。`ja.unei.criteria` に質疑を足し、法案に関わった人の通報は数えないことを書く。通報の欄の基準の文にも同じことを書く。自動の非表示の理由は `reports`（「通報が3件」）

## 範囲
