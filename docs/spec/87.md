# 採決の結果の立場別の分布と「会期中の考えの動き」（設計書）

Issue #87。統計の匿名化の基準に触れるので Careful。仕様の正は [docs/spec.md](../spec.md) の「採決と投票の公正さ」（締切後に結果と立場別の分布を公開する）と「匿名化の基準」。前提の決定は Issue #147 の決めること20・21、受入基準と決めたことは Issue #87（2026-11-12 ユーザーと決定）。結果のページは [71.md](71.md)、立場は [66.md](66.md)、5%刻みの丸めは [149.md](149.md)。

## ユーザーと決めたこと（Issue #87）

1. **立場別の分布**は、締切の時点の暫定の立場（賛成寄り・未定・反対寄り）ごとの、数えた票の賛成・反対・棄権の割合。参考の票は入れない。立場の行がない人は未定（66.md の決まり）
2. **10人未満の基準**は立場の区分ごとに当てる。数えた票を入れた人が10人未満の区分は丸ごと出さない。出す区分も人数は出さず、5%刻みに丸めた割合だけ
3. **会期中の考えの動き**は、その法案に立場を一度でも選んだ人全員を、付託先の会期の1〜4週目の各週の終わりの時点の立場で数えた割合。まだ選んでいない週は未定に数える。数える人が10人未満なら出さない。5%刻み。動かない図
4. **置き場所**：分布は結果のページの票の下。考えの動きは結果のページの「会期中の考えの動きを見る」から行く別のページ。どちらも結果が出てからだけ、ログインなしで見られる

## この設計書で決めること（STOP 1 の基準から読み取ったもの）

- A. **集計は一度だけ作って残す**。仕様の「投票履歴を削除しても、公開済みの集計値は変わらない」（#89 で削除を作る）に合わせ、最初に結果のページか動きのページが読まれたときに作り、表 `stance_stats` に残す。どちらのページも、先に結果のページと同じく `resultOnRead` で結果を確定してから作る（動きのページを先に開いても結果が出る）。**票や立場の履歴を消す処理（#89・退会）は、消す前にその法案の `stanceStatsOf` を呼んで集計を作っておく**（まだだれも読んでいない法案でも、消す前の票で作るため）。2回目からは表の値を使う。同時に読まれても `INSERT … ON CONFLICT DO NOTHING` で最初の1行だけが残り、どちらの計算も同じ入力から同じ値になる
- B. **作るのは結果が出て、確認中でも無効でもないときだけ**。確認中のあいだは作らず、運営が確定したあとの最初の読み込みで作る。無効になった結果では作らない（表に行を入れない）。締切の前と集計中も作らない
- C. **残すのは丸める前の人数**（区分ごとの票の数と、週ごとの立場の人数）。人数はページのデータに出さない。10人未満の判定と5%刻みは、画面に渡す直前にルールの関数で行う。あとで基準を変えても、残した人数から出し直せる
- D. **「締切の時点の立場」**は、`stance_log` のその人の最後の行（`created_at` が同じなら `id` の大きいほう）のうち、`created_at` が付託先の会期の終わり（`endsAt`）より前のもの。行がなければ未定。立場は採決の締切までしか変えられないので、いまの `stances` の行と同じ値になるが、週の計算と同じ道具を使うため履歴から求める
- E. **週の終わり**は、付託先の会期の2週目・3週目・4週目の始まりと、会期の終わり。カレンダーの月なら8日0時・15日0時（`deliberationAt`）・22日0時（`voteAt`）・翌月1日0時（`endsAt`）。分の会期（開発用）なら会期を4つに等しく分けた区切り（1週目の終わりは `startsAt` と `deliberationAt` のまん中）。週の終わりの時刻ちょうどの変更は次の週に入れる（`created_at < 週の終わり`）
- F. **「一度でも選んだ人」**は、その法案・その会期の `stance_log` に行がある人。未定を最初に押しても行はできない（66.md の6）ので、賛成寄りか反対寄りを一度でも選んだ人になる。発議が前の会期の3週目以降だと、付託先の会期が始まる前に選んだ行もある。その行は1週目の終わりの時点に入る
- G. **丸め**は区分ごとに `Math.round(n / total × 20) × 5`（`roundRatio`、149.md と同じ）。区分の中の3つの割合の和が100にならないことがある（例：33.3% が3つで 35・35・35）。そのまま出し、合わせ直さない（合わせ直すと、丸めた結果から人数を推定する手がかりが増えるため）
- H. **区分を出さない理由は書き分けない**。10人未満の区分は行ごと消し、「人数が少ない区分は出していません」の注記を表の下に1つだけ出す（どの区分が少なかったかを示さない）。どの区分も出せないときは表を出さず「人数が少ないため、立場別の分布は出していません」と出す
- I. **動きのページ**の URL は `/saiketsu/[id]/kekka/ugoki`。結果のページと同じく IF世界の帯（`ifBand`）と `noindex` を付ける（結果のページと同じ並びの中のページなので）。法案は結果のページと同じ `postableBill` で読み、番号の形が違う・ない・下書きの法案は 404。結果が出ていないときは、結果のページと同じ言葉（締切の前・集計中・確認中・取り下げ）を出し、動きは出さない。無効になった結果では「この結果は無効になったため、考えの動きは出していません」と出す
- J. **「会期中の考えの動きを見る」のリンク**は、結果が出て確認中でも無効でもないときだけ、結果のページのリンクの並び（「IF世界の条文を見る」の下）に出す。数える人が10人未満のときもリンクは出し、行った先で「人数が少ないため…」と出す（リンクの有無で人数を示さない）
- K. **廃案（定足数に届かず）**も可決・否決と同じに出す（票は数えてあり、仕様は結果を限っていない）。取り下げた法案には結果がないので出さない

## 表

`stance_stats`（マイグレーション `0032_stance_stats.sql`。表を足すだけ）

| 列 | 中身 |
| --- | --- |
| `session_key` | 付託先の会期（結果の行と同じ） |
| `bill_id` | `bills` への外部キー |
| `data` | 丸める前の人数の JSON（下の形）。CHECK `json_valid(data)` |
| `created_at` | 作った時刻 |

主キー（`session_key`, `bill_id`）。`data` の形：

```json
{
  "votes": { "for": { "yes": 7, "no": 2, "abstain": 1 }, "undecided": { … }, "against": { … } },
  "weeks": [ { "for": 3, "undecided": 7, "against": 0 }, … 4つ ]
}
```

## ルールの関数（`src/lib/domain/stance-stats.ts`。DB にも画面にも触れない）

- `STATS_MIN = 10`（匿名化の基準。仕様の「10人未満の区分は表示しない」）
- `weekEnds(session: Session): [number, number, number, number]`（E）
- `stanceAt(logs, userId, at)`：その人の `created_at < at` の最後の行の立場。なければ `'undecided'`（D）
- `tallyStanceStats(votes: { userId; choice }[], logs: { userId; stance; createdAt }[], session)`：丸める前の `data` を作る。`votes` は数えた票だけ（呼ぶ側で絞る）。`weeks` の対象は `logs` に出てくる人（F）
- `distributionView(data.votes)`：区分ごとに合計が `STATS_MIN` 以上なら `{ stance, yes, no, abstain }`（5%刻み）を返し、足りない区分は入れない。返すのは `{ rows, omitted: boolean }`（omitted は1つでも区分を除いたか。H の注記に使う）。区分の並びは賛成寄り・未定・反対寄り
- `motionView(data.weeks)`：数える人（どの週も同じ人数）が `STATS_MIN` 未満なら `null`。以上なら週ごとの `{ week, for, undecided, against }`（5%刻み）

## サーバーの関数（`src/lib/server/stance-stats.ts`）

- `stanceStatsOf(db, bill, result, review, now)`：B の条件を満たさなければ `null`。`stance_stats` に行があればその `data`。なければ数えた票（`countedCondition` で絞った `votes` の `user_id`・`choice`）と、その法案・会期の `stance_log` を読み、`tallyStanceStats` で作って `INSERT … ON CONFLICT DO NOTHING` し、入れたあと読み直した `data` を返す（同時に作った場合も、残った1行の値を返す）
- `stance_log` は `id` の順に読む（D の同じ時刻の行の扱い）
- **ページの読み込み（`+page.server.ts`）が返すのは `distributionView`・`motionView` の結果（または `null`）だけ**で、`StanceStatsData` そのものは返さない。人数がページのデータに出ないのはここで決まる（画面のテストで `__data.json` を確かめる）
- 読む行の数は票の数と立場の変更の数（1人3行まで）。`IN (…)` に値を並べないので、D1 の値の数の上限にかからない
- 会期は結果の行の `session_key` から求める（`referralSession(bill.proposedAt, minutes)`。結果の行と同じ会期）

## 画面

**結果のページ**（`/saiketsu/[id]/kekka`。phase が `done` で無効でないとき）：票の欄（「数えた票 N」）の下に、見出し「立場別の分布」、注記「締切の時点の考え（賛成寄り・未定・反対寄り）ごとの、数えた票の割合です。人数が10人に満たない区分は出しません。」、表（行：「賛成寄りだった人」「未定だった人」「反対寄りだった人」、列：賛成・反対・棄権。値は「70%」）。H の注記と、出せないときの文。リンクの並びに「会期中の考えの動きを見る」（J）

**動きのページ**（`/saiketsu/[id]/kekka/ugoki`）：パンくずは結果のページの下。見出し1は法案の題名、見出し2「会期中の考えの動き」。説明「この法案に考えを選んだ人が、会期の各週の終わりにどの考えだったかの割合です。まだ選んでいない人は未定に数えます。」。図は週ごとの横の帯（1週目〜4週目の4本）で、各部分に「賛成寄り 40%」の文字を付ける（0% の部分は出さない）。図は `aria-hidden` にし、同じ値の表（行：週、列：賛成寄り・未定・反対寄り）を図の下に出す。10人未満なら図も表も出さず「人数が少ないため、考えの動きは出していません」

色は Tokens の変数だけ（賛成寄りは `--color-support`、反対寄りは `--color-oppose` と斜線（結果のページの反対と同じ）、未定は `--color-surface` と枠）。色だけに頼らず、文字と表で同じ値を出す

文言は `ja.result.stance`（分布）と `ja.result.motion`（動き）に置く。画面に「区分」以外の実装用語（stance、bucket、集計表など）を出さない

## テスト

- **ルールのテスト**（`src/lib/domain/stance-stats.test.ts`）：`weekEnds`（カレンダーの月と分の会期）、`stanceAt`（境目ちょうどは次の週）、`tallyStanceStats`（立場の行がない票は未定、未定に戻した人、週の未選択は未定）、`distributionView`（10人ちょうどは出す・9人は出さない、5%刻み、omitted）、`motionView`（9人で null）
- **DB のテスト**（`src/lib/db/stance-stats.test.ts`）：一度作ると、あとで票や立場が変わっても値が変わらない（A）。確認中・無効では作らない（B）。参考の票は入れない
- **画面のテスト**（`e2e/kekka-bunpu.spec.ts`、2幅。基準ごとに1本）
  - 共通の準備：賛成寄りを選んで数えた票を入れた人を10人（2週目に選ぶ）、立場を選ばずに数えた票を入れた人を2人。賛成7・反対2・棄権1（賛成寄り）
  - 基準1：賛成寄りの行に「70%」「20%」「10%」。人数が出ない
  - 基準2：未定の行（2人）は出ず、注記が出る。別の法案（3人）では「人数が少ないため、立場別の分布は出していません」
  - 基準3：動きのページに、1週目 未定 100%、2〜4週目 賛成寄り 100%（表で確かめる）
  - 基準4：3人の法案の動きのページで「人数が少ないため、考えの動きは出していません」
  - 基準5：締切の前は、結果のページに分布もリンクも出ず、動きのページは「結果は締切のあとに出ます」。10人のうち5人が同じ回線から投票した法案で、締切のあとは確認中（動きのページを先に開く）、運営が無効にしたあとは無効の表示になり、どちらも分布・リンク・動きを出さない。動きのページに形の違う番号・ない番号で 404。ログインなしで見られることは基準1〜4（ログインしていない人で見る）で確かめる
  - 基準6：図の各部分の文字と、表の見出し。2幅。色が Tokens の変数だけなことは、今までの `src/lib/styles/tokens.test.ts`（.svelte に色の値を直に書くと落ちる）が担う
  - ページのデータに人数と出さない区分の値が入らないことは、`__data.json` の中身で確かめる（基準2・4）
