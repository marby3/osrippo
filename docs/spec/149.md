# 議員ダッシュボード（設計書）

Issue #149。画面の案は `SpMember`・`PcMember`。課題の「立場を超えた支持」の割合を画面に出すので、統計の匿名化の基準に触れ、Careful。

受入基準は Issue #149、前提の決定は Issue #147 の決めること6〜9（2026-11-10）と、割合の出し方（2026-11-11 ユーザーと決定）。マイグレーションはない。

## 決めたこと

### 1. 開ける人

- `/giin` は、有効な議員の認証がある人（`legislatorAt`、`docs/spec/158.md` の 1）だけ。ほかの人（ログインしていない人を含む）は 404（ページがあることを漏らさない。`/kanri` と同じ扱い）
- ヘッダーの「議員用」のリンクと「認証済み・氏名」は、全体の `+layout.server.ts` が返す `legislator`（#158）と、議員の表示する名前で出す。`legislator` を `{ name } | null` に広げる（真偽で使っている場所は `!== null` に直す）

### 2. 割合を出す（Careful の中心）

- #126 の基準5（割合の値、グループの人数、だれがどちらのグループかは、画面にもページのデータにも出さない）は、**一般の画面の決まりとして残す**。議員ダッシュボードだけを例外にする
- 出すのは課題ごとの **スコア `min(a / A, b / B)` を5%刻みに丸めた値** だけ（`Math.round(score × 20) × 5`。0〜100 の整数）。グループの人数 `A`・`B`、区分の人数 `a`・`b`、だれがどちらかは、議員の画面にもページのデータにも出さない
- 割合を出すのは、`a` と `b` がどちらも10人以上の課題だけ（#126 の決めること E と同じ）。足りない課題は `null` を返し、画面は「—」
- グループ全体が10人未満のときは、どの課題も `null`（区分が10人以上なら全体も10人以上なので、上の条件に含まれる）
- 計算は `bridgeParts`（`src/lib/server/bridge.ts`）の式をそのまま使い、丸める前の値は SQL の中だけで扱う。`bridgeParts` に `ratio`（割合を使える課題だけ `min(…)`、ほかは NULL）を足し、ダッシュボードの一覧だけがそれを選ぶ。課題の一覧（`/kadai`）は今までどおり選ばない
- 丸めはルールの関数 `roundRatio(score: number | null): number | null`（`src/lib/domain/bridge.ts`）。5%刻みにするのは、1人の「わかる」で値が動いて、その人のグループを推定されにくくするため
- **残るリスク（受け入れる）**：丸めても、区分が10人ちょうどの課題で1人が「わかる」を押すと、丸めた値が変わることがある。#126 と同じく、押した人と時刻はどの画面にも出さないので、推定できるのは押した人を外で知っている人に限られる。見られるのは認証した議員だけ

### 3. 一覧

- **課題のタブ**：課題の一覧と同じ `listIssues` に、ダッシュボード用の引数（割合を返す）を足して使う。絞り込みは「すべて」「解決策あり」（`solutions`）「法案になった」（`bills`）。並びは `bridge`（既定）・`support`・`new`。お題・検索・最近増えている順は使わない
  - いちばんの解決策：ページに出る課題の分だけ、別の問い合わせで、表示中の解決策のうち「わかる」が最も多いもの（同じなら id の小さいもの）を引く
- **法案のタブ**：法案の一覧の「審議中」（`listBills(db, 'shingi', …)`）と同じ範囲。いまの段は `progressOf`。元の課題は、引用した解決策の課題（表示中のもの）の最初の1つ
- **IF世界で可決のタブ**：`bill_results.outcome = 'passed'` で、確認中・無効（`vote_reviews.status IN ('open', 'voided')`）でない法案。新しい会期の順。対象の法令は `bill_laws` から（制定の法令は IF世界の法令の名前）
- タブの件数：課題は表示中の課題の数、法案は審議中の数、可決は上の条件の数
- どのタブも20件ずつ、「もっと見る」で次のページ（`?page=`）

### 4. 文言

`ja.giin`（見出し、説明、タブ、列、並び、絞り込み、「—」、「まだありません」、注記、ヘッダーの「議員用」「認証済み・氏名」）。画面に実装用語を出さない。

## テスト

- **ルールのテスト**：`roundRatio`（5%刻み、null はそのまま）
- **DB のテスト**：ダッシュボードの一覧が、区分が10人以上の課題だけに割合を返し、課題の一覧（`/kadai` の呼び方）には割合が入らない
- **画面のテスト**（`e2e/giin.spec.ts`、基準ごとに1本）：基準1〜7。基準5の割合は、人数が足りない課題が「—」になることを確かめる（10人ずつのグループを画面のテストで作るのは重いので、割合の値は DB のテストで確かめる）
