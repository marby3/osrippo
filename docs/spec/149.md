# 議員ダッシュボード（設計書）

Issue #149。画面の案は `SpMember`・`PcMember`。課題の「立場を超えた支持」の割合を画面に出すので、統計の匿名化の基準に触れ、Careful。

受入基準は Issue #149、前提の決定は Issue #147 の決めること6〜9（2026-11-10）と、割合の出し方（2026-11-11 ユーザーと決定）。マイグレーションはない。

## 決めたこと

### 1. 開ける人

- `/giin` は、有効な議員の認証がある人（`legislatorAt`、`docs/spec/158.md` の 1）だけ。ほかの人（ログインしていない人を含む）は 404（ページがあることを漏らさない。`/kanri` と同じ扱い）
- ヘッダー：全体の `+layout.server.ts` が `legislator`（真偽。#158）に加えて `legislatorName`（議員の表示する名前 `user_verifications.display_name`。議員でなければ null）を返す。`legislatorAt` は `legislatorNameAt` の結果が null でないかで決める
  - 「議員用」のリンク（`/giin` へ）は、議員でログインしているあいだ、どのページでもヘッダーのロゴの右に出す（PC・スマホとも。`/giin` では `aria-current="page"`）
  - 「認証済み・氏名」（盾の印は `aria-hidden`）：PC は `/giin` のときだけヘッダーの右（PcMember）。スマホは `/giin` のヘッダーの下の帯に「認証済み議員・氏名」（SpMember）

### 2. 割合を出す（Careful の中心）

- #126 の基準5（割合の値、グループの人数、だれがどちらのグループかは、画面にもページのデータにも出さない）は、**一般の画面の決まりとして残す**。議員ダッシュボードだけを例外にする
- 出すのは課題ごとの **スコア `min(a / A, b / B)` を5%刻みに丸めた値** だけ（`Math.round(score × 20) × 5`。0〜100 の整数）。グループの人数 `A`・`B`、区分の人数 `a`・`b`、だれがどちらかは、議員の画面にもページのデータにも出さない
- 割合を出すのは、`a` と `b` がどちらも10人以上の課題だけ（#126 の決めること E と同じ）。足りない課題は `null` を返し、画面は「—」
- `A < 10` または `B < 10` のときは、どの課題も `null`（区分が10人以上なら全体も10人以上なので、上の条件に含まれる）
- 計算は `bridgeParts`（`src/lib/server/bridge.ts`）の式をそのまま使う。`bridgeParts` に `ratio`（割合を使える課題だけ `min(…)`、ほかは NULL）を足す。`listIssues` に引数 `withRatio` を足し、真のときは **並びがどれでも** グループの CTE を作って `ratio` を選ぶ。並びに `bridgeParts.order` を使うのは並びが `bridge` のときだけで、`bridgeFallback` を返すのも `bridge` のときだけ
- 丸める前の値は、サーバーの一覧の関数の中で `roundRatio` に通し、ページのデータには丸めた値だけを返す。`withRatio` が偽（課題の一覧 `/kadai`）のときは、行に `ratio` の列そのものを入れない
- 丸めはルールの関数 `roundRatio(score: number | null): number | null`（`src/lib/domain/bridge.ts`）。5%刻みにするのは、1人の「わかる」で値が動いて、その人のグループを推定されにくくするため
- **残るリスク（設計レビューの指摘から正確に書き直した。STOP 2 でユーザーに確認する）**
  - 1人の「わかる」で割合は `1 / A` 動く。グループが20人以下（`A ≤ 20`）なら `1 / A ≥ 5%` なので、5%刻みに丸めても **値は必ず変わる**。丸めが効くのはグループが20人を超えてから
  - グループがちょうど10人なら、割合は `a / 10` なので、**区分の人数がそのまま分かる**（10人以上の区分の人数なので、10人の基準そのものは破らない）
  - 押す前と後の値を見比べ、押した人と時刻を外で知っている議員は、その人のグループを推定できる。押した人と時刻はどの画面にも出さない。見られるのは認証した議員だけ
  - より強く守るなら、刻みを粗くする（10〜20%）、課題ごとの基準を上げる、グループが大きいときだけ出す、のどれか

### 3. 一覧

- **URL**：`/giin`（課題のタブ、立場を超えた支持が多い順、すべて、1ページ目）が既定。引数は `tab`（`houan`・`kaketsu`）、`sort`（`support`・`new`）、`kaiketsu=ari`、`houan=ari`、`page`（2〜）。既定の値を書いた URL（`sort=bridge`、`page=1`）、ほかの値、課題のタブ以外での並びと絞り込み、絞り込みの2つ同時は 404。リンクは既定の値を書かない形で作る
- **タブ**：既定は課題。いまのタブに `aria-current="page"`。絞り込みのリンクも同じ

- **課題のタブ**：課題の一覧と同じ `listIssues` に、ダッシュボード用の引数（割合を返す）を足して使う。絞り込みは「すべて」「解決策あり」（`solutions`）「法案になった」（`bills`）。並びは `bridge`（既定）・`support`・`new`。お題・検索・最近増えている順は使わない
  - いちばんの解決策：ページに出る課題の分だけ、別の問い合わせで、表示中の解決策のうち「わかる」が最も多いもの（同じなら id の小さいもの）を引く。なければ「まだありません」
  - 並びが `bridge` で人数が足りないときは、課題の一覧と同じ注記（`ja.issue.bridgeFallback`）を出す
  - 課題名は課題のページへのリンク
- **法案のタブ**：法案の一覧の「審議中」（`listBills(db, 'shingi', page, lapsedBefore(previous), 20)`。`listBills` に件数の引数を足す）と同じ範囲。いまの段は `billProgress`。元の課題は、**いまの版**（`bills.rev`）で引用した解決策の課題（表示中のもの）の最初の1つで、なければ「まだありません」。法案名は法案のページへのリンク
- **IF世界で可決のタブ**：`bill_results.outcome = 'passed'` で、確認中・無効（`vote_reviews.status IN ('open', 'voided')`）でない法案。新しい会期の順（同じ会期は新しい法案から）。法案名は結果のページ（`/saiketsu/<番号>/kekka`）へのリンク。可決した会期は「2041年5月の会期」。対象の法令は **結果の版**（`bill_results.rev`）の `bill_laws` を `seq` の順に並べ、改正・廃止は `law_id`、制定は `if_laws.id`（`if-<法案の番号>`）で IF世界の法令（`/if/hourei/<id>`）へリンクする
- タブの件数：課題は表示中の課題の数、法案は審議中の数、可決は上の条件の数
- どのタブも20件ずつ、「もっと見る」で次のページ（`?page=`）

### 4. 文言

`ja.giin` に足す。見出し「市民の課題と解決策」、説明「閲覧・質疑・答弁ができます。投票と評価はできません。」、注記「選挙期間中は、議員の機能が自動で止まります ・ 反応はすべて記録して公開されます」、ヘッダーの「議員用」、PC の「認証済み・氏名」、スマホの「認証済み議員・氏名」、タブ「課題 N」「法案 N」「IF世界で可決 N」、並び「立場を超えた支持が多い順」「わかるが多い順」「新しい順」（課題の一覧の並びの名前とは別に、案のとおり）、絞り込み「すべて」「解決策あり」「法案になった」、割合「75%」と「—」、「まだありません」、「もっと見る」、会期「2041年5月の会期」。人数が足りないときの注記は課題の一覧の文言を使う。画面に実装用語を出さない。案の画面の 48%・61%・22% は例で、出す値は5%刻み

## テスト

- **ルールのテスト**：`roundRatio`（5%刻み、null はそのまま）
- **DB のテスト**：ダッシュボードの一覧が、区分が10人以上の課題だけに割合を返し（`min(10/13, 10/10)` → 75。並びと同じ `bridgeParts` の式）、課題の一覧（`/kadai` の呼び方）には割合の列が入らない。可決のタブは、確認中・無効を除き、新しい会期の順
- **画面のテスト**（`e2e/giin.spec.ts`、基準ごとに1本）：基準1〜7。基準5の割合は、人数が足りない課題が「—」になることを確かめる（10人ずつのグループを画面のテストで作るのは重いので、割合の値は DB のテストで確かめる）
